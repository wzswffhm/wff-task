# W1–W14 弱点全量表与定向构造

## W1–W14 弱点全量表与定向构造

> 每行结构：**典型行为 → 具体 case（观测证据）→ 推荐构造方式 → 对应 rubric 设计**。
> `weakness_tag` 取值按算法正式词表填写；下表名称为规范原文表述。

---

### W1 · 长文档下的硬约束遵循较差

| 项 | 内容 |
|---|---|
| **典型行为** | 模型不是完全没看到要求，而是随着内容生成变长，部分 hard constraint 从 working state 中丢失；尤其是**需要真实 artifact operation** 才能满足的约束（section break、页码域、字数上限、公式保留），而不是在正文中"写到了"就算完成 |
| **具体 case** | PA-T1-001 无人驾驶航空器管理办法起草：明确要求正文 4000–8000 字，Qwen 最终约 14825 字（接近上限两倍）；同时页码域、单双页等要求并未真正写入 Word XML |
| **推荐构造方式** | 构造 **long-form + 5–15 个 artifact-level hard constraints** 的任务。重点混合三类约束：**内容约束、数量约束、真实文件结构约束** |
| **rubric 设计** | 正向：字数在区间内（binary）；页码域/分节符真实存在于文件结构（binary，需检查 XML 而非正文文字）；负向：仅在正文"提到"但文件结构未实现（negate） |

### W2 · 关键冲突下自行选边 / 修改输入

| 项 | 内容 |
|---|---|
| **典型行为** | Workspace / Context 中存在互相矛盾的关键信息，模型甚至已经发现冲突，但会自行选择其中一个版本继续，极端情况下直接"修正"输入 |
| **具体 case** | 报告中血钾 8.2 mmol/L vs "持续低钾"；材料用量 100ml vs 120ml，都稳定复现了该问题。医疗冲突 Case：病例文字明确描述"持续低钾"，但化验结果显示 K⁺=6.2 mmol/L。高钾和低钾对应完全不同的诊断和治疗策略，模型不能自行决定哪一条是真的 |
| **推荐构造方式** | 构造**含冲突 Workspace** 的任务。同一事实分别出现在 Excel / PDF / 邮件 / Markdown / 数据库结果中，两个值对应完全不同的最终答案；真正值只能通过**询问用户**或额外可信工具确认，或是有其他证据（这里可以是静态 user 多轮数据） |
| **rubric 设计** | 正向：产出中明确指出冲突及两个来源（binary，+10）；负向：自行选边（negate，−7）；致命：直接"修正"输入材料（negate，−10） |

> 详细构造（三类错解、正解表现）见 `04-skill-dependency.md` 类型一。

### W3 · 阻塞状态的识别与恢复能力较差

| 项 | 内容 |
|---|---|
| **典型行为** | 遇到关键资源缺失、权限受限、外部依赖失败、输入损坏或必要信息不足等 **Blocking State** 时无法稳定判断。典型错误两类：**过早放弃 / 不懂变通**（原路径失败后直接停下或把任务推回用户，明明存在 retry、替代工具、备用数据源等可恢复路径）；**强行闭环 / 伪完成**（关键阻塞尚未解除，却使用假数据、placeholder、自行估值、未经授权的替代方案继续执行，并最终宣称任务完成） |
| **具体 case** | case1：image 工具不可用，但模型一直仍在反复调用；case2：某相关文件不存在，模型一直在反复寻找该文件直到超长 |
| **推荐构造方式** | 主要是教会模型 **Blocking State → Recovery**。可涵盖多种类型：① 某数据不可用（目标文件名不可用，但 Workspace 中存在合理替代文件）；② 某服务不可用（需要模型自行先修复服务）；③ 原路径不可行，但环境里有另一种工具可以完成；④ 缺少关键信息（需要 ask_user） |
| **rubric 设计** | 正向：识别阻塞并采用可行恢复路径（binary/likert）；正向：明确记录阻塞与恢复动作（binary）；负向：伪完成（用假数据/占位符却宣称完成，negate −10）；负向：过早放弃（存在可恢复路径却停止，negate −7） |

### W4 · 多要求 / 多交付物下缺少 Requirement Coverage Accounting

| 项 | 内容 |
|---|---|
| **典型行为** | 简单任务基本能完成，但当显式要求项、文件数、sheet / section / field / edit item 增多时，模型容易"完成大方向但漏细项"，缺少一套持续维护的 requirement checklist |
| **具体 case** | hard_194：PPT 要求完成 10 项修改，Qwen 约只完成 4/10；hard_008：要求同时交付完整 Excel 审计表和 Word 摘要但缺少必需工作表 / 章节；hard_180：7 页脚本 PPT 漏掉每日时段和逐镜来源 |
| **推荐构造方式** | 构造**要求有多个产物要求**的复杂任务 |
| **rubric 设计** | 正向：逐项覆盖检查（likert 按覆盖比例分档）；负向：漏项（negate，按漏项数分档）；另可要求交付"要求覆盖对照表"作为可核验抓手 |

### W5 · 关键信息缺失时"该问不问"

| 项 | 内容 |
|---|---|
| **典型行为** | 模型能够意识到部分信息缺失，却没有稳定转化成真正的"提问—等待"。漏问 case 中既有"声明关键假设但继续做"，也有直接静默补全 |
| **具体 case** | 通用-003｜9 天差旅穿搭：用户列出了衣物、帽子、围巾，却没有提供任何鞋款；任务又明确要求每天必须搭配一双鞋，且连衣裙必须配皮鞋。Qwen 没有询问可用鞋款，直接继续生成，最终鞋子部分缺失结果 |
| **推荐构造方式** | 刻意删除一个**决定最终结果的 blocking variable**。例如穿搭缺鞋款、金融测算缺收购比例、分析任务缺时间范围、PPT 缺目标受众等 |
| **rubric 设计** | 正向：明确指出缺失项并请求确认（binary，+10）；负向：声明假设后继续（negate −3）；负向：静默补全（negate −7）；负向：编造缺失变量（negate −10） |

> 该类题通常需**多轮对话或静态 user 数据**承载"提问—等待"。

### W6 · 用户补充信息后只局部更新，没有 Global Re-planning

| 项 | 内容 |
|---|---|
| **典型行为** | 模型"问到了、听懂了、写进答案了"，但依赖这一事实的其他规则、计算、排序、结论仍沿用旧值。Qwen 在完整利用澄清信息的 case 中，仍有 59% 内容未满分、33% 有严重错误 |
| **具体 case** | 并购 Earn-out Case：模型能够主动追问并获得"首期收购 60%、剩余 40% 按业绩分期收购"等关键信息，但最终一方面把剩余 40% 当作购买日或有对价计入合并成本，相当于按 100% 收购 |
| **推荐构造方式** | 一个新增事实**同时影响 3–5 个 downstream fields**。例如主体从 A 改成 B，同时改变税率、适用法规、现金流计算、风险评级和最终建议 |
| **rubric 设计** | 正向：全部 downstream 字段均按新事实更新（likert 按更新比例分档，+10）；负向：仅局部更新（negate −7）；典型的"一致性对账"型判定：新旧字段间不得自相矛盾 |

### W7 · 长表格 / 多 Sheet 下的数据覆盖与抗干扰能力弱

| 项 | 内容 |
|---|---|
| **典型行为** | 阅读长 Excel、多子表或重复实体时容易漏行漏对象、错误聚合、把 inactive / 非目标对象混入统计；模型有时已经注意到"同名多记录"等异常，但仍快速选择一个未经验证的处理口径 |
| **具体 case** | hard_155：没有提取 60 个子表数据；medium_050：源表存在同名学生多条考试记录，Qwen 将记录直接求和排名，得到无法回源的分数与前三名；另有 case 出现 inactive 对象、冲突项覆盖不足 |
| **推荐构造方式** | 构造 **row / sheet scaling + distractor injection**：增加 sheet 数、行数、重复 key、inactive 记录、跨期记录、相似实体、隐藏列、异常值；让 gold **明确依赖正确的 grouping / filtering / dedup 规则** |
| **rubric 设计** | 正向：覆盖全部子表/行（binary +10）；正向：去重/筛选口径正确（binary +7）；负向：漏行漏表（negate，按漏失比例 likert）；负向：把 inactive/非目标混入统计（negate −7） |

### W8 · 启动 Subagent 后把"已派发"当成"已完成"

| 项 | 内容 |
|---|---|
| **典型行为** | Qwen 可以正确拆任务并启动多个研究 Agent，但多次在异步结果返回前直接结束主任务，没有等结果回收动作 |
| **具体 case** | H-104967｜白银供给、回收率与回收技术综合研究：3 次 rollout 均启动 5 个研究 Agent，但全部停在"等待返回" |
| **推荐构造方式** | 构造需要依赖**多个 delayed subagent result** 才能完成 final 的任务。各子 Agent 分别掌握**不可替代**的一部分信息。（该类任务也是目前**非常缺少**的） |
| **rubric 设计** | 正向：Final 覆盖全部子任务结论（likert +10）；负向：派发即完成（negate −10） |

> 详细构造见 `05-workflow.md`。

### W9 · Skill 被形式化调用，但没有真正改变关键判断

| 项 | 内容 |
|---|---|
| **典型行为** | 报告发现"使用了匹配且关键的 Skill"并不等于结果改善。模型可能完整走了一遍 Skill checklist，却没有根据检查结果修正原结论 |
| **具体 case** | Clinical Skill Case：Qwen 先搜索 Skill，再激活 clinical-diagnostic-reasoning 并读取 clinical-reports；Skill 确实使输出结构更完整，也加入了偏差检查，但模型随后仍自行加入固定冰冻分流、固定切缘、固定药物线序等过度具体建议，说明 Skill 被"读了"，却没有真正约束每条建议的证据强度 |
| **推荐构造方式** | 构造一批**必须依赖 Skill 中特有信息或行为规则**才能正确完成的任务，避免 Skill 只是"可有可无"的辅助材料。例如 Skill 明确要求发现数据冲突必须暂停，task 中刚好埋冲突 |
| **rubric 设计** | 正向：产物体现 Skill 特有规则（binary +10）；负向：形式化调用（走了清单但结论未修正，negate likert −7） |

> 详细构造见 `04-skill-dependency.md` 与 `04-skill-dependency.md`。

### W10 · 大 Workspace 下缺少 Coverage Accounting

| 项 | 内容 |
|---|---|
| **典型行为** | 面对大量文件时，模型没有维护"哪些证据已看 / 哪些未看 / 哪些章节依赖哪些文件"的 coverage state，而是在局部证据足以形成一个看似合理框架后提前开始写结果，导致未读取区域对应的事实与风险系统性遗漏 |
| **具体 case** | L5-05｜IPO 法律尽调：要求基于 183 份底稿完成法律尽职调查。Qwen 实际只读取 44 份，随后已经开始形成完整报告，最终触发 25 条披露完整性扣分，股东持股、知识产权、劳动用工等整章节缺失 |
| **推荐构造方式** | 构造**有几百 or 上千个文件的大 Workspace 任务**，把不同必答项的关键证据**分散在不同文件簇**中。可进一步构造"高信息密度少文件"和"信息稀疏多文件"的任务，训练模型做有效 coverage planning，而不是无脑全读 |
| **rubric 设计** | 正向：全部必答章节/条目覆盖（likert，按覆盖比例 +10）；正向：交付覆盖清单（binary +7）；负向：整章节缺失（negate −10） |

> 该类任务对应 C5 复杂度（50+ 文件），是批次中的高难主体。

### W11 · 无据自造数据与口径

| 项 | 内容 |
|---|---|
| **典型行为** | 自行设定界值、外推假设、套用惯例公式、沿用旧版方案或引入工作包外参数，把没有来源的数字写进结论，甚至声称「指南明确写明」 |
| **具体 case** | 自设数值界值却称指南「明确写明」；另一例针对「物理核数→云端 vCPU 如何对应」的唯一检索 exit 1 后未追查，直接用自拟口径逐台匹配 |
| **推荐构造方式** | ① 规范文件里**故意不含**某个常用阈值，正解是如实存疑而非套惯例；② 另设一处规范中确有明文条款，考察是否真去查；③ 提供两套口径的中间数据，考察是否标注口径而非混用 |
| **rubric 设计** | 正向：数值有可溯源出处（binary +10）；正向：不确定时如实标注存疑（binary +7）；负向：套用惯例/自拟口径（negate −7）；致命：声称"指南明确写明"但规范中无此条（negate −10，属幻觉） |

### W12 · 跨源交叉核对缺失

| 项 | 内容 |
|---|---|
| **典型行为** | 只凭单一字段、单一线索或单份材料下判定，不与其他数据源互证；自算值单向否定源文件登记值而不回到规则条文双向核实 |
| **具体 case** | 同一份查询结果中已同时出现 B_ECOM 93.2% 的部门有效口径，仍以整池 71% 定调「有余量」；另一例 171 笔逐笔勾对仅命中 1 笔仍不修正匹配逻辑 |
| **推荐构造方式** | 同一事实分散在 **≥3 份材料且口径不同**（如整池口径 vs 部门口径）；题面要求交叉核对并说明口径取舍理由；设计一处**自算值与登记值冲突**，正解是回查规则条文 |
| **rubric 设计** | 正向：使用 ≥3 源交叉核对（binary +10）；正向：说明口径取舍理由（binary +7）；负向：单源定调（negate −7）；负向：自算值单向否定登记值（negate −7） |

### W13 · 规划与策略调整失当

| 项 | 内容 |
|---|---|
| **典型行为** | 缺少任务拆解；在同一处失败上反复重试、重复调用；一次成稿不做迭代；耗在表面排版而内容不再复查 |
| **具体 case** | 对手册检索返回的全是模板化噪声条款，未更换关键词也未改查银行流水/科目导出，直接转入定稿，使租赁、薪酬、水电等费用行缺少交叉印证 |
| **推荐构造方式** | 长程多子任务（**≥6 个交付要件**），需显式拆解才能不漏；埋一个**必须换策略（而非重试）**才能通过的死路；要求交付含**任务拆解与完成状态表** |
| **rubric 设计** | 正向：交付任务拆解与完成状态表（binary +7）；正向：遇到死路后改变策略并成功（binary +7）；负向：重复无效检索/调用（negate −7）；负向：无拆解导致漏要件（negate likert） |

> 与 `05-workflow.md` 的 W-A 形态高度重合，可协同设计。

### W14 · 脱敏与合规疏漏

| 项 | 内容 |
|---|---|
| **典型行为** | 含真实姓名或敏感内容的版本直接落盘进交付目录；脱敏自检报警未处理即定稿。反向地，也包括**过度脱敏**删掉了用于对照的核验证据 |
| **具体 case** | 脱敏扫描已标出「身份证」字样与精确到日的日期仍存在，仍宣称「已用正则扫描确认无残留直接标识」；另一例未脱敏版本（含 '孙浩'、'RA-207'）直接落到交付路径 |
| **推荐构造方式** | 题面给出明确脱敏规则并**列明「必须保留」的对照项**；要求**首版必须写在 /tmp，脱敏后才可进交付目录** |
| **rubric 设计** | 正向：交付目录中无直接标识（binary +10）；正向：保留了"必须保留"的对照项（binary +7）；负向：未脱敏直接落盘（negate −10）；负向：过度脱敏删掉核验证据（negate −7） |
