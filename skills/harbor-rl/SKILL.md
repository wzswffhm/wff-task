# 法律领域常规办公场景出题（Law1–Law6）

按《RL0-1-数据生产规范 Guideline for 外部供应商（法律）》生产法律领域题。
**交付实现见 `delivery/`**（五件套、task.toml、rubrics.toml、prompt.md、固定模板、验收口径）。

## 用途与触发条件

触发词：法律出题 / 法律评测题 / 法律办公场景题 / Law1–Law6 / 法律意见书 / 起草法规 / 合规审查 / 尽调备忘 / 起诉状。
本批**仅接收法律领域**题目，不接收其他领域。

## 三条底线（违反即整题作废）

1. **真实性**：必须来自真实法律办公场景（"真的会有律师/法务/法官这样做"），`source_note` 写清来源与真实性保障。**禁止为测 LLM 弱点编造的对抗题**。
2. **参考文件必须真实且有源**：不得要求模型凭空猜测法规条款、政策口径、职责分工或统计数据。真实材料（合同/判决书/卷宗/工商档案/流水/监管文件）是什么就用什么。
3. **打分项可核验**：每条打分项须有明确判定锚点、可客观核验；不得出现"语言流畅""分析专业"类空洞项。

## 知识体系与分布约束（强制）

| 领域 | 二级标签 | 说明 |
|---|---|---|
| 法律 | **Law1-诉讼律师** | 民刑行诉讼代理、证据组织、起诉/答辩、上诉、庭审准备 |
| 法律 | **Law2-非诉律师** | 合同审查与起草、交易结构、尽调、法律意见书、并购/融资文件 |
| 法律 | **Law3-企业法务与合规** | 合规审查、内控、劳动人事、合同管理、知识产权、监管应对 |
| 法律 | **Law4-法官与法院辅助** | 裁判文书说理、争议焦点归纳、类案检索、审判辅助 |
| 法律 | **Law5-检察官与检察辅助** | 审查报告、证据审查、起诉书、量刑建议、法律监督 |
| 法律 | **Law6-立法与政策研究** | 法规起草、条文设计、政策研究报告、征求意见稿 |

**分布硬约束**：

- 二级标签**需要覆盖**，题目**平均分布**；补充二级标签须**提前说明**。
- **三级标签原为空，出题时必须补足**；四级标签自行填写，描述细分场景。
- **不接受 2 道以上（2 道本身可以）的题目属于同一个三级标签。**

## 端到端流程

```
① 选题（Law1–Law6 配额规划） → ② 补足三/四级标签 → ③ 设计真实办公场景与交付物
→ ④ 准备真实源文件 → ⑤ 写 instruction.md → ⑥ 产出专家参考答案 → ⑦ 设计打分项
→ ⑧ 写 task.toml / rubrics.json / tests/rubrics.toml / prompt.md → ⑨ 交付自检（见 `delivery/`）
```

### ① 配额规划（先规划再动笔）

按批次题量分配 Law1–Law6，并在每个二级标签下预先分配三级场景，**避免集中在少数标签**。
建议按 `A1 20% / A2 60% / A3 20%` 规划难度配比。

### ② 补足三/四级标签

为每道题写清：

| 字段 | 填写要求 |
|---|---|
| `domain_l2` | 取 Law1–Law6 原文 |
| `domain_l3` | **本批必须自补**，粒度 = 具体业务动作（如"股权转让协议违约条款审查"） |
| `domain_l4` | 细分场景（如"对赌条款回购触发条件认定"） |

> 同一三级标签下最多 2 道题。

### ③ 设计真实办公场景与交付物

- 角色要具体（"某券商投行部 ECM 分析师""某制造业企业法务""基层法院法官助理"），读者要明确。
- 交付物要**就该场景真实会交付的东西**，如：法律意见书（.docx）、合同修订稿（.docx 带修订痕迹）、尽调问题清单（.xlsx）、证据目录（.xlsx）、争议焦点归纳表、条文对照表、合规风险清单。
- 硬约束（文件名、字数、禁止项、必须包含/禁止包含的内容）**独立成段**，不得藏在括号里。

场景与交付物库 → `references/01-taxonomy-and-scenario.md`。

### ④ 准备真实源文件

- 真实或高仿真材料：合同、判决/裁定书、案卷摘要、工商档案、银行流水、往来邮件、监管文件、招投标文件。
- **必须脱敏**：不得含真实姓名、身份证号、手机号、真实企业涉密信息（详见 `references/02-input-files.md`）。
- 放入 `environment/input_files/`，容器内为 `/app/input_files/`（只读）。

### ⑤ 写 instruction.md

按 `delivery/` 的要求：自包含；源路径 `/app/input_files/`；交付路径 `/app/output/`；
逐个列出源文件及其字段/口径；交付物表（文件名 / 是否必交 / 说明）；硬约束独立段落。
**不得泄露** rubric 条目、golden 内容或"评分将检查……"式提示。

### ⑥ 产出专家参考答案

- 与交付物文件名、格式、数量**严格一致**，放入 `solution/golden_output/`，并复制一份到 `tests/__golden_output/`。
- 按打分项自检：**主分 > 0.85**；且**不得命中任何 negate 条目**（尤其"未脱敏"类）。
- 参考答案须体现**真实法律实务口径**：现行有效法条（含条、款、项）、准确请求权基础、可核验的判例案号。

### ⑦ 设计打分项（法律专属要点）

必须覆盖的维度（见 `delivery/` §维度体系）：指令遵循 / 结论正确性 / 数值与计算准确性（赔偿额、违约金、利息、税费） / **专业规范** / 分析与论证质量 / 事实忠实性 / 结构与组织；
法律行业性突出，**专业规范维度应给较高 weight**；写作类交付物**结构与组织维度应给较高 weight**。

法律专属检查点 → `references/03-rubric-legal.md`：

| 检查点 | 典型条目 |
|---|---|
| 法条现行有效性 | 使用现行有效法律规则而非已失效规定（如民法典施行后不再援引合同法条文） |
| 条文定位准确 | 援引时**条、款、项**定位准确（如"《民法典》第五百八十五条第二款"） |
| 请求权基础匹配 | 请求权基础与争议焦点匹配，不张冠李戴 |
| 判例可核验 | 引用的判例、案号与裁判要旨可核对，**不存在虚构案号或伪造裁判理由** |
| 事实可溯源 | 关键事实（成立时间、股权比例、金额）能在源文件溯源 |
| 数值准确 | 赔偿金额合计 = 各项分项之和（±0.01）；万元与元换算正确；违约金上限规则适用正确 |
| 结构合规 | 法律意见书按「事项概述—事实与证据—法律分析—结论与建议」组织 |
| 脱敏合规 | 对外文书不得暴露身份证号、手机号等敏感个人信息 |
| 交付安全 | 处理完成后案卷/源文件清单仍完整可打开 |

分布要求：**Critically Important（+10）≥2 条**；**内容质量维度正分 ≥30%**。

### ⑧ 写配置与评分器

- `task.toml`：`domain = "法律"`、`domain_l2/l3/l4`、`capabilities`、`difficulty`、`vl_dependency`、`source_note`、`tools`、`domain_knowledge`；`category` 按题目性质填写。
- **法律题不做 skill 依赖时**：`skill_set = []`、`expected_skill_dependencies = []`。
- `rubrics.json`（原始细则）+ `tests/rubrics.toml` + `tests/prompt.md`：写法见 `delivery/03-rubrics-and-prompt.md`。

### ⑨ 交付自检

跑 `delivery/` 的 G1–G6 六道门与 17 项自检（`G1–G6` 为归纳编号，规范原文无此编号）。
难点验证：三模型（`gpt-5.6-sol` / `claude-opus-4-8` / `qwen3.8-max0902`）均分 **< 0.7** 且至少一个模型有得分；裁判 `qwen3.7-plus`。

### ★ 关键：法律规范打分项 ↔ 交付态 rubrics.toml 的口径映射

法律规范以**设计态 `rubrics.json`** 描述打分项；交付态 `rubrics.toml` 的字段约束不同，**必须按下表转换**（此处是法律题最高频的返修点）：

| 法律规范（设计态） | 交付态 `rubrics.toml` | 说明 |
|---|---|---|
| `weight = -3 / -7 / -10` | `weight = 3.0 / 7.0 / 10.0` **且** `negate = true` | **交付态严禁负 weight**（会使 `S_max` 计算失真） |
| `type = "Binary"` | `type = "binary"` | 取值须小写 |
| `type = "Gradient"` + `levels` = {1, .75, .5, .25, 0} | `type = "likert"` + `points = 5` | judge 输出 1–5 整数，归一化 `(raw−1)/4`，恰好映射为 1/.75/.5/.25/0 |
| `criterion_type`（Objective / Subjective） | 保留在 `rubrics.json`，**不写入** `rubrics.toml` | 设计态字段 |
| `criterion_necessity`（Explicit / Implicit） | 同上 | 设计态字段 |
| `dimension`（一级 + 二级） | 保留在 `rubrics.json`；可在 `description` 中体现维度归属 | 用于**分布自查**（内容质量正分 ≥30%） |
| `weight ∈ {+10,+7,+3,−3,−7,−10}`（六档） | 交付态只保留**三个绝对值档位** 3.0 / 7.0 / 10.0 | 符号改由 `negate` 承担 |

**计分一致性证明**（两式等价，负向均不进分母）：

```
法律规范：Score  = ( Σ_{P} s·w  +  Σ_{N} h·w ) / Σ_{P} w            # w_N < 0，h = 违规程度
交付规范：reward = clip( ( Σ_{P} w·v − Σ_{N} w·(1−v) ) / S_max, 0, 1 )   # S_max = Σ_{P} w
```

> 令 `h = 1 − v`（违规程度 = 1 − 符合程度），两式**完全等价**。区别仅在写法：
> 法律规范的负 weight 与交付规范的 `negate = true` 表达同一件事。
> **交付前必须确认 `rubrics.toml` 中不存在任何负 weight**（`grep -n 'weight = -' tests/graded/rubrics.toml` 应无输出）。

## 验收标准（速查）

| 项 | 标准 |
|---|---|
| 参考答案 | 主分 **> 0.85**，未命中任何 negate 条目 |
| 难度 | 三模型均分 **< 0.7** 且至少一个模型有得分；等级区间 A1 0.6~0.7 / A2 0.5~0.6 / A3 <0.5 |
| 分布 | Law1–Law6 覆盖且平均；**任一三级标签 ≤2 道** |
| 元数据 | 领域/二级/三级/四级标签、能力、难度、任务说明、所需工具**必填**；VL 依赖必填 |
| Rubric | Critically Important ≥2；内容质量正分 ≥30%；weight ∈ {3,7,10}；likert 全锚点 |
| 人工质检 | 题目真实性、参考答案合理性、打分项设计合理性、**无 hack** —— 任一不过直接打回 |

## 反模式（禁止）

1. 出法律以外的领域题（本批仅法律）。
2. 二级标签未覆盖 / 集中扎堆；同一三级标签超过 2 道。
3. 三级标签留空（本批**必须补足**）。
4. 要求模型凭空猜测法条、政策口径、职责分工、统计数据。
5. 源文件未脱敏（含真实姓名/身份证号/手机号/涉密信息）。
6. 打分项空洞（"分析专业""结构清晰"）或无可核验锚点。
7. 断言"现行有效"却不核对时效（援引已废止条文）。
8. 参考答案虚构判例案号或裁判理由。
9. 题面泄露 rubric / golden / 评分检查点。
10. 交付物文件名六处不一致；文件名含日期/时间戳。
11. 未跑 golden 预检或 Oracle ≤0.85 仍提交。
12. 未提供三模型跑分轨迹。
