## 根因

对照上游 nbd(NetworkBlockDevice/nbd)后发现:`nbd-server.c` 里**整套写时复制实现被剥离了**,`nbdsrv.h` 里配套的客户端字段也没了。于是 `expwrite`/`expread` 直接落到普通的 `rawexpwrite`/`rawexpread`——写直接 `pwrite` 进主文件、读直接 `pread` 主文件、连接建立时不建 diff 文件、断开时无从清理。

## 补回的内容(按 man nbd-server(5) 语义 + 上游实现)

**COW 本身**(`nbd-server.c` + `nbdsrv.h`):
- `CLIENT` 增加 `difffilename` / `difffile` / `difffilelen` / `difmap`(4096 字节页的映射表)
- `copyonwrite_prepare()`:连接确立时按 `cowdir`(缺省为主文件同目录)创建 `<名字>-<客户端>-<pid>.diff` 并初始化映射表
- `expwrite()`:写全部落 diff 文件,不碰主文件。`sparse_cow` 时按页号定位;普通模式追加到文件尾。非整页写先把原页读进来补全再整页落盘
- `expread()`:先查映射表——脏页从 diff 文件读、干净页从主文件读,所以刚写的内容立即能读回
- `finalize_client()`:断开时 `unlink` diff 文件,主文件保持原样
- `expflush()`:COW 时同步的是 diff 文件
- `setupexport()`:主文件只能以只读打开时,COW 导出不再被误降级为 readonly(写仍然进 diff 文件)

**顺带发现的同类问题**:
- `waitfile` 选项也是"配置项在、行为没了"(解析、与 copyonwrite 的互斥校验都在,运行时无效)。补回了完整机制:主文件不存在时先只收写(进 diff 文件、拒绝读未写区域),收到 SIGUSR1 后后台线程打开主文件、把 diff 合并进去再切到正常服务
- `writeit_tls` 对 `GNUTLS_E_AGAIN` 的误报日志修复(同批上游修正)

## 验证

- `make check` 全绿:18 个可运行测试全部 PASS(parse 6、code 5、run 18,含 `cow`)。4 个 SKIP 是构建未带 GnuTLS/syslog 的环境性跳过,与本改动无关
- `cow` 测试三个导出(`cowplain`/`cowsparse`/`cowcowdir`)全部通过:写入后立即读回一致 → 断开后 `*.diff` 无残留 → 主文件逐字节未变 → 重连只读到原始内容
- `waitfile` 端到端实测:主文件缺席时写成功、干净读被拒;建好主文件并发 SIGUSR1 后,diff 自动合并(盘上主文件对应页确为写入数据)、恢复正常读写
- COW + 只读主文件(chmod 444):可正常写读,主文件不受影响
