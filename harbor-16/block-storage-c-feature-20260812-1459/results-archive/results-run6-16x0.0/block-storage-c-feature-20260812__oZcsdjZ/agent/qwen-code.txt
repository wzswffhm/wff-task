## 改动内容

**`nbdsrv.h`** — `CLIENT` 结构新增 4 个会话级 CoW 字段:`difffilename`(diff 文件路径)、`difffile`(fd)、`difmap`(每 4KB 一页的页表,`-1` 表示该页未写过)、`difffilelen`(非稀疏模式下 diff 文件的页数)。

**`nbd-server.c`** — 五处:
- `copyonwrite_prepare()`(新增):连接建立后创建 diff 文件 `<cowdir或主文件目录>/<主文件名>-<客户端>-<pid>.diff` 并初始化页表。目录取 `cowdir` 配置项,缺省用主文件所在目录,与 man page 语义一致。
- `commit_client()`:`setupexport()` 成功后(exportsize 已确定)对 `F_COPYONWRITE` 导出调用上面的准备函数。
- `expwrite()`:CoW 导出的写入按 4KB 页重定向到 diff 文件,主文件不再被写;部分页写入时先从主文件读回原页合并再落盘;`sparse_cow = true` 时页号直接映射为设备页号(稀疏文件),否则顺序追加到 diff 文件尾部(man page 描述的两种模式);`sync`/FUA 语义同步到 diff 文件。
- `expread()`:按页查 `difmap`,脏页优先从 diff 文件返回,干净页回落主文件;兼容 structured reply 的分块/缓冲逻辑。
- `expflush()`/`finalize_client()`:flush 作用于 diff 文件;**断开连接(NBD_CMD_DISC 或异常断连)时 `unlink` 本次会话的 diff 文件**,主文件保持原样。

配置解析(`copyonwrite`/`sparse_cow`/`cowdir` 和命令行 `-c`)原本就在,无需改动。

- `make check`:**18/18 通过**(4 个 SKIP 是 inetd/TLS 环境性跳过,与本改动无关)。其中 `cow` 用例覆盖三种导出(`copyonwrite`、`+sparse_cow`、`+cowdir`)的完整语义:写入后会话内读回新数据、断开后 diff 文件被清理、主文件内容逐字节不变、新连接只看到原始数据;`cfgmulti`、`write`、`flush`、`integrity` 等确认普通导出无回归。

## 一个顺手修掉的坑

实现中发现 glibc 的 `dirname()` 会原地截断传入字符串,若直接传 `client->exportname`,该字段会被永久截断(影响后续 postrun 等),且 diff 文件名会带上目录名而非主文件名。已改为在副本上调用,`exportname` 保持不动。
