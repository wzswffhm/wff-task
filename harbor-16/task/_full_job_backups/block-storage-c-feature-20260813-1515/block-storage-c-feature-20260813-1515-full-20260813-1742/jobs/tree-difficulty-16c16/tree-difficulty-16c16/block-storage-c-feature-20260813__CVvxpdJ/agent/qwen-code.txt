完成了。`treefiles` 选项现在按 man 文档描述的方式真正工作了——之前 `treefiles.c` 只有一行 "not implemented" 的桩,服务端也完全没有接入这个标志,所以配不配都一样落到单个文件里。

## 改动内容

**核心实现** — `treefiles.c`(原来是空桩):
- `construct_path`:把导出内偏移映射成 `exportname/TREEXXXX/.../FILEXXXX` 路径,目录嵌套深度由 `filesize` 推导;每个目录最多 1024 项,叶子是 4096 字节的块文件
- `open_treefile`:按需打开/创建块文件(含缺失目录);只读导出读未写块时返回匿名零填充文件,保证空洞读零
- `delete_treefile`:删除块文件(TRIM 用)
- `mkdir_path`:递归建目录

**服务端接入** — `nbd-server.c`:
- `get_filepos`:`F_TREEFILES` 时按 `TREEPAGESIZE` 算块内偏移,`open_treefile` 取 fd
- `rawexpread/rawexpwrite/rawexpsplice`:操作完成后关闭临时 fd
- `expflush`:treefiles 走 `sync()`(只读直接返回)
- `setupexport`:treefiles 时 `export=NULL`(按需开句柄)、大小取 `filesize`;并强制要求必须设置 `filesize`(man 文档的硬要求,之前没校验)
- `parse_cfile`:拒绝 `treefiles + waitfile` 这种自相矛盾的组合

**TRIM** — `nbdsrv.c`:`exptrim` 对 treefiles 删除覆盖到的整块文件,块随后读回为零。
