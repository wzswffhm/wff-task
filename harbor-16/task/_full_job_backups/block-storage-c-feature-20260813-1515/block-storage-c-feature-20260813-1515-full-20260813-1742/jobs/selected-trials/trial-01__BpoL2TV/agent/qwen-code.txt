## 改动

**`treefiles.c`（新实现，约 270 行）**
- 布局：数据按 `TREEPAGESIZE`=4096 字节切块，块 n 存为 `<exportname>/TREExxxx/.../TREExxxx/FILExxxx`，xxxx 是 n 的 1024 进制各位数字（最低位是文件名，高位由外向内作目录名）。每层目录 ≤1024 个条目，超过 4GiB 的导出自动加深嵌套层级
- 实现了头文件声明的 `construct_path` / `mkdir_path` / `open_treefile` / `delete_treefile`，外加 `trim_treefiles`、`tree_path_extra` 和共享互斥锁

**`nbd-server.c`**
- `setupexport`：treefiles 分支——校验 filesize 必填、创建/校验基础目录、`exportsize = filesize`；treefiles 与 multifile 同配时按 man 页由 treefiles 优先
- `treeexpread`/`treeexpwrite`：读写按块文件分发，跨块请求在块边界截断由上层循环续接；块文件不存在或尾部未写过一律读作 0；支持 F_SYNC/FUA 落盘
- `expflush`：treefiles 分支（块文件随用随关，flush 时 fsync 基础目录元数据）
- `parse_cfile`：treefiles 缺 filesize、或同时配 waitfile/splice 时启动即报错（splice/waitfile 依赖单文件导出的数据结构，混用会崩）

**`nbdsrv.c`**：`exptrim` 增加 treefiles 分支——整块被 trim 的直接删文件（对应 man 页 "Files will be deleted if the corresponding block gets marked as unused"），部分覆盖的块只把 trim 区间写零

普通导出、multifile、copyonwrite 的路径一行未动。
