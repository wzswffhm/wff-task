`treefiles` 补上了。之前 `treefiles.c` 只有一句 "not implemented" 的注释,选项被解析、被打印、却从不生效。现在按 man 文档(nbd-server.5)描述的行为实现了:

## 实现

**`treefiles.c/h`**(原为空壳):导出设备按 4096 字节块拆分,每块一个文件,挂在以导出名为根的文件树下;每级目录最多 1024 个条目,目录深度由 `filesize` 推算。
- `construct_path()` — 偏移 → 块号 → 按 1024 进制分解成 `exportname/TREExxxx/.../FILExxxx` 路径
- `open_treefile()` — 按需创建目录和块文件(在客户端锁下,避免线程竞争)
- `delete_treefile()` / `mkdir_path()` — 删除块文件、递归建目录
- `treeexpread()` — 块文件不存在或读越界一律返回全零(设备初始为零);`treeexpwrite()` — 按块边界分段写,尊重 `sync`/FUA;`treeexptrim()` — 整块 trim 直接删文件,块内部分 trim 打洞

**`nbd-server.c`**:`setupexport` 增加 treefiles 分支(要求必须配 `filesize`,自动建树根目录,只读导出缺树时全零伺候);`rawexpread/rawexpwrite/expflush/expwrite_zeroes` 按标志分派到 tree 实现(write_zeroes 直接删块文件,因为"文件不存在"与"全零"等价);配置解析时拒绝 `treefiles` 与 `splice`/`waitfile` 混用;`multifile` 同时给出时按文档由 treefiles 优先。**`nbdsrv.c/h`**:`exptrim` 分派;CLIENT 增加 `treemutex`。普通导出的代码路径未动。
