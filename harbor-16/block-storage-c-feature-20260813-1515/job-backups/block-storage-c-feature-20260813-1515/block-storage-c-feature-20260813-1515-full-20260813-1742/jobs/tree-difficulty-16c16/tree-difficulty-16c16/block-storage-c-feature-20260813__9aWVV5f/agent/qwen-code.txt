treefiles 选项现在真正生效了。数据不再落到单一文件,而是按 4 KiB 块拆进一棵文件树,读写、TRIM、零填充、持久化都已验证。

## 改动内容

`treefiles.c`(原来是空壳)— 实现了四个函数:
- `construct_path()`:把设备偏移映射成树内路径。块号 = `pos/4096`,按 1024 进制展开,每层一个数字;目录名 `TREEXXXX`,叶子块文件 `FILEXXXX`。树的深度由 `filesize` 决定,保证每个目录 ≤1024 个条目。
- `mkdir_path()`:递归建目录。
- `open_treefile()`:构造路径 + 按需建目录 + 打开(带 `O_CREAT` 才建文件),用每客户端互斥锁串行化。
- `delete_treefile()`:删除指定偏移对应的块文件。

`nbd-server.c`:
- `parse_cfile()`:treefiles 必须配 `filesize`;优先级高于 `multifile`;拒绝与 splice/waitfile 混用。
- `setupexport()`:treefiles 分支——大小取配置的 filesize,块文件惰性创建。
- `rawexpread()/rawexpwrite()`:新增 treefiles 分支,读写都按单块文件裁剪;未写块读回零(不建文件);尊重 F_SYNC/FUA。

`nbdsrv.c`/`nbdsrv.h`:CLIENT 加 `treefiles_lock`;`exptrim()` 对 treefiles 导出删除被完整覆盖块的块文件。
