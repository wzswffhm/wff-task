完成了。`treefiles` 之前是个空壳(`treefiles.c` 只有一行注释),配了该选项的导出会悄悄落回单文件路径。现在已按 man 文档把行为补齐,全部测试通过。

## 改了什么

**`treefiles.c`(核心实现,原先只有占位注释)**
- `construct_path()`:把导出偏移映射成树内路径。块号按 TREEDIRSIZE(1024)进制展开,高位作目录名、低位作文件名,目录层数由 `filesize` 推出(`tree_depth()`),保证每个目录 ≤1024 个条目。
- `open_treefile()`:按需打开块文件;写打开时自动 `mkdir -p` 建目录并 `O_CREAT` 建文件,读打开不存在的块则返回 `ENOENT`。
- `delete_treefile()`:删除块文件(TRIM 时归还空间)。
- `treefiles_sync()`:递归 fsync 整棵树,实现 FLUSH。

**`nbd-server.c` / `nbdsrv.c` / `nbdsrv.h`(接线)**
- `setupexport()`:识别 `F_TREEFILES`,不再打开单文件,`export=NULL`、尺寸取 `filesize`(并修正了 multifile 优先级:treefiles 同时给出时生效)。
- `expread/expwrite` → 新增 `treefiles_read/treefiles_write`,按 4K 块在树中读写;未写过的块读回全零。
- `exptrim`(nbdsrv.c)→ 删除被整块 TRIM 的块文件;`expflush` → 走 `treefiles_sync`。
- `commit_client/finalize_client`:初始化/销毁新增的 `treefiles_mutex`。
- `parse_cfile`:校验配置——`treefiles` 必须给 `filesize`;拒绝与 `copyonwrite`/`waitfile`/`splice` 混用(这些依赖单文件数组);与 `multifile` 共存时 treefiles 优先。
