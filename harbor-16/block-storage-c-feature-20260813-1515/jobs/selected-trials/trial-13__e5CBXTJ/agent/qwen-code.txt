## 问题根源

`treefiles = true` 只被解析成 `F_TREEFILES` 标志位,`treefiles.c` 是一行占位注释("not implemented in this tree"),数据读写路径完全没有分支处理它——所以一切照旧落进单一大文件。

## 实现(按 man/nbd-server.5 的语义)

设备按 **4096 字节块**切分,每个块一个文件,放在以 exportname 命名的目录树下;每层目录最多 **1024 个条目**,按 `filesize` 自动计算嵌套深度(`≤4MiB` 时块文件直接放根目录,更大则逐级 `TREExxxx/` 嵌套);从未写入(或被 TRIM)的块没有文件,读回全零。

- **treefiles.c**:实现了头文件声明的 4 个函数——`construct_path`(偏移→`TREExxxx/…/FILExxxx` 路径)、`mkdir_path`、`open_treefile`(按需建目录建文件)、`delete_treefile`(删块文件并自下而上清理空目录,保留树根)
- **nbd-server.c**:`setupexport` 加 treefiles 分支(校验 filesize、建根目录、优先于 multifile);`rawexpread/rawexpwrite` 经 `treeexpread/treexpwrite` 按块分发(跨块请求由原有 `_fully` 循环自然衔接;支持 F_SYNC/FUA);`expflush` 加 treefiles 分支;`parse_cfile` 校验:treefiles 必须配 filesize,禁止与 splice/waitfile 混用;`commit_client` 初始化新增的 `treefile_lock`(CLIENT 结构,见 nbdsrv.h)
- **nbdsrv.c**:`exptrim` 加 treefiles 分支——整块覆盖的直接删文件(man 页"块标记 unused 即删文件"),部分覆盖的块写零,保证 trim 后读回为零

## 顺带修掉的一个隐患

`copyonwrite_prepare` 直接把 `client->exportname` 传给 `dirname()/basename()`——glibc 会**就地截断实参**,exportname 被改成父目录。普通导出用已打开的 fd 读写不受影响,但 treefiles 每次 IO 都要按名字重建路径,COW 组合下必炸;diff 文件名也因此取错过 basename。改为先 `g_strdup` 再传给 dirname/basename。
