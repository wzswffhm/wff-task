# SOTA 通过率验证（难度验收）

## 目标

验证题目难度符合分级预期：SOTA 模型在 Claude code 框架下的通过率不能超过上限——
太难或太易都要调。**均分口径**，不是单模型。

## 标准（20260801 修改，后续执行新标准）

| 难度 | 三家均分上限 |
|------|-------------|
| L2 | ≤ 65% |
| L3–L4 | ≤ 55% |
| L5 | ≤ 50%（Coding 规范按 0.45~0.50 区间，以当批规范为准） |

- 框架：Claude code
- 待测模型（20260801 标准）：**Claude opus 4.8、glm5.2、kimi-k3**（任选 3 家，以当批规范清单为准）
- 裁判模型：gpt-5.5
- 取三家跑分的**均分**（⚠ 是均分，不是任一家）

## 区分度要求（Coding 交叉长尾规范）

- 题目标题应 Appropriately Difficult：在多个 frontier 模型（如 GPT5.6、Claude fable 5、GLM 5.2、kimi-k3）上跑分后，各模型 harbor 均分**极差（最高−最低）≥ 0.30**，能有效区分不同水平模型。
- 前提：verifier 必须存在且正确（没有 verifier 的题目无法判断区分度）。

## 执行流程

1. 确认题目已过 G1–G4（五件套、task.toml、Rubric、双向预检）。
2. 用同一冻结修订，分别以三家待测模型跑完整评测（harbor run 或等价批量入口），记录每家的 reward 分布与通过率。
3. 计算三家均分，对照难度上限：
   - 均分 > 上限 → 题太难（或 Rubric 写歪导致通过率虚低）→ 检查 Rubric 是否过于苛刻/描述有歧义；必要时按流程修订重跑。
   - 均分远低于下限（如 <0.15）且题目明显简单 → 检查是否 Rubric 空洞/判官不可用。
4. 记录留档：每家模型的 reward、通过率、均分、判定结论，附在题包随附说明或提交登记表备注。
5. 不达标一律**禁止打包提交**；修订需递增 [task].version 并重新跑双向预检。

## 与内部 16-trial 难度门的关系（仅参考，不得混用）

`harbor-skill` 用 16 次独立 trial 的 reward 分布（reward=1 出现率）控制难度，属内部 RL 数据口径。
外发交付以**三家 SOTA 模型均分**为验收口径，二者目标不同、样本不同，**不能互相替代**。
若内部分析需要 16-trial 分布，可并行采集，但外发打包与验收只认 SOTA 均分。
