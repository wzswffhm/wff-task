# cleanup_and_restore —— 副作用清理与恢复证据

本题的被测对象是一个纯 Python 目录同步库，**不触碰任何系统级状态**：

| 潜在副作用类别 | 本题是否涉及 | 说明 |
|---|---|---|
| 注册表 | 否 | 代码路径中不出现 `winreg` |
| Windows Service / 计划任务 | 否 | 无服务或计划任务注册 |
| 证书 / ACL / 防火墙 | 否 | 不调用相关 API |
| 驱动 / 设备 | 否 | 不涉及 |
| 文件系统 | 是（受限） | 全部读写发生在 pytest `tmp_path` 提供的临时目录内 |

## 清理验证

本地验证流程（`verify_stage2.py`）在每次运行结束后会整体删除该次运行的工作目录
（`%TEMP%\wsync-verify\s2_*`）。这一点本身即验证了**被删除/覆盖的文件没有留下只读残留**：
若同步实现未能正确清除只读属性，`shutil.rmtree` 会在清理阶段抛 `PermissionError`，
脚本会立刻失败。实测 13 个中间工作目录全部清理成功，无残留。

## 恢复方式

无需恢复。容器/评测环境中，题目初始态由 `environment/workspace/` + 基线 commit 定义，
每次评测从该基线重新开始即可回到干净状态。
