修复了 wsync 在 Windows 环境下的五类核心问题：

1. **只读属性阻塞** - 在删除或覆盖文件/目录前自动清除只读属性（FILE_ATTRIBUTE_READONLY），确保同步不会因只读条目而中断；递归清除目录树时从叶子节点向上清理。

2. **大小写不敏感冲突** - 在 Windows 下规范化路径为小写进行比较，确保 `Report.PDF` 和 `report.pdf` 被识别为同一文件；更新 `build_plan` 和 `_collect_target_state` 使用大小写不敏感的字典。

3. **单个失败中断全部** - 为每个文件操作添加异常处理，将无法处理的条目记录到 `SyncResult.failed` 列表中，其余条目继续正常处理；区分"可自动修复的只读"和"真正无法处理的占用"。

4. **文件/目录类型冲突** - 在创建或更新前检测路径冲突，当源与目标类型不同时先清理目标侧的旧条目；处理父路径被文件占据的情况，递归向上清理阻塞路径。

5. **内容判定和时间戳** - 使用字节级内容比较而非仅凭大小和时间判断是否需要更新；同步后使用 `os.utime` 保留源文件的修改时间，确保后续同步的幂等性。

关键修改：
- `wsync/core.py`：添加 `_normalize_path`、`_clear_readonly`、`_safe_remove`、`_ensure_parent_is_directory`、`_files_equal` 等辅助函数
- `_collect_target_state`：使用大小写不敏感字典
- `build_plan`：规范化路径进行匹配
- `sync_tree`：为每个操作添加异常处理，处理类型冲突，保留修改时间

所有现有测试通过，验证了只读处理、大小写处理、类型冲突、失败隔离、内容判定和幂等性。
