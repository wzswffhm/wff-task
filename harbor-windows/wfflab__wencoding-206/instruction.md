# wtextio —— 按平台默认编码写文本导致非 ASCII 内容损坏

## 背景

`wtextio` 是工具链里生成报表与清单文本的库。同一段代码在 Linux 上写出的文件可以在任何地方打开，到了 Windows 上生成的文本却报编码错误或者显示成乱码。

## 现象

1. 写含中文的清单时直接抛 UnicodeEncodeError，整条导出流程中断。

2. 含重音字母的文本能写成功，但落盘的字节与预期不符，拿到 Linux 上打开是乱码。

3. 按默认参数读回一个 UTF-8 文件时解出乱码，因为读取侧用的是系统 ANSI 代码页。

## 目标

让 `wtextio` 在上述这些真实的 Windows 场景下都能给出正确结果：

1. 默认编码必须固定为 UTF-8，不随平台变化；写出的非 ASCII 文本在磁盘上就是 UTF-8 字节。

2. 读取时使用与写入相同的默认编码，保证同一份文件在两端都能正确解出。

3. 需要字节序标记时使用带 BOM 的 UTF-8 变体。

## 功能边界

- **需要支持**
  - `write_text` / `append_text` / `write_lines` 的落盘编码
  - `read_text` / `read_lines` 的解码选择
  - `utf-8-bom` 编码别名与 `detect_bom`
- **不需要处理**
  - 编码自动探测
  - UTF-16 / UTF-32 的读写
  - 损坏字节的容错替换

## 约束

- 目标环境：Windows Server 2022（x64），Python 3.12
- 只允许使用 Python 标准库，**不得引入新的第三方运行时依赖**
- 不得改变 `write_text` / `read_text` / `encoding_for` 的公开签名与既有语义
- 不得修改或删除仓库自带的测试，不得为了通过而放宽既有行为
- 必须保持断网可运行

## 允许修改范围

`wtextio/` 包内的源码。`tests/` 下只允许新增测试文件，不得改动既有测试。

## 验收标准（用户可见）

1. 写含中文的文本不再抛异常，落盘的字节等于该文本的 UTF-8 编码。

2. 写出的文件用默认参数读回后得到原文。

3. 读取外部生成的 UTF-8 文件时得到正确结果。

4. `encoding="utf-8-bom"` 写出的文件以 UTF-8 BOM 开头。

5. 落盘换行固定为 CRLF。
