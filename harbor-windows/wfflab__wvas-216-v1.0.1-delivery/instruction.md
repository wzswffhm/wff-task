# wvas：进程虚拟地址空间审计实现有缺陷

`wvas` 是采集端用来**审计本机进程虚拟地址空间**的只读包。给它一个进程 ID，
它要报出这个进程当前占用了哪些地址区间、每段区间是什么状态、什么保护、
多少长度，以及哪些区间背后是磁盘上的文件、文件在哪儿。

支持工程师会把这些数字和自己的调试器对照，也会把报告里的映射文件路径直接
贴进工单，让另一头的人打开。所以这个包的输出要么完全正确，要么毫无用处。

本任务的目标平台是真实的 Windows，验收不使用其他操作系统，也不需要实现其他操作系统的版本。

`docs/NOTES.md` 是当初写这个包时随手记的草稿，**已经和现在的实现对不上**，
不要拿它当依据。

## 现象（仓库 issue #216）

1. **高地址全部对不上**。随便挑一个进程，把 `regions()` 报出来的 `base` 和
   调试器/系统 API 在同一时刻给出的地址并排看，凡是高地址的区间都对不上，
   报出来的数字明显偏小。
2. **大区间的长度离谱**。目标进程专门保留了一段 6 GiB 的地址空间，
   `regions()` 报出来的长度是个很小的数。
3. **保留状态完全看不到**。无论目标进程做了多少次
   `VirtualAlloc(..., MEM_RESERVE, ...)`，`regions()` 的结果里都不会出现
   `state == "reserve"` 的区间；`include_reserved` 这个开关形同虚设。
4. **映射文件路径没法用**。文件映射区间的 `path` 长这样：
   `\Device\HarddiskVolume5\Users\...\thing.dll`。把它贴进资源管理器打不开，
   工单里的人也看不懂。
5. **匿名映射被报成空文件名**。用 `CreateFileMapping(INVALID_HANDLE_VALUE, ...)`
   建出来的匿名映射，`path` 是空字符串 `""`，和"没有文件背衬"混为一谈。
6. **进程不存在时抛裸异常**。pid 不存在时调用方收到的是 `OSError`，拿不到
   `WVasError` 的错误分类。
7. **模块列表严重重复**。`modules()` 会把同一个映像重复报上几百次。

## 任务

修复 `wvas` 包，使其满足下面的验收标准。公开 API 的名字和签名不得改变。

## 验收标准

### A. 区间描述

`regions(pid, include_reserved=True)` 返回区间描述列表，按 `base` 升序排列。
每个描述是一个字典，键恰好是：

`base`、`size`、`state`、`type`、`protect`、`path`、`image`。

取值要求：

| 键 | 要求 |
|---|---|
| `base` | 区间起始地址，必须是**完整地址宽度**下的真值（64 位进程上的地址不得被截断到 32 位） |
| `size` | 区间长度，同样不得截断：超过 4 GiB 的区间必须报出真实长度 |
| `state` | `"commit"` 或 `"reserve"` |
| `type` | `"image"`、`"mapped"` 或 `"private"` |
| `protect` | `protection_name()` 给出的短名 |
| `path` | 背衬该区间的文件路径；没有文件背衬、或者该文件无法还原成可打开路径时为 `None` |
| `image` | 该区间是否属于已加载的映像（布尔） |

`include_reserved=True` 时必须**同时**报出已提交区间和已保留区间；`include_reserved=False` 时只报已提交区间。

对同一个进程、同一时刻，报出的 `base` / `size` 必须与系统 API
（如 `VirtualQueryEx`）量到的结果逐个一致，不得有体系结构相关的取整或截断。

### B. 文件背衬与路径

1. `path` 必须是调用方**可以直接打开**的形式：DOS 盘符路径（`C:\...`）或 UNC 路径（`\\server\share\...`）。任何 `\Device\...`、`\??\...`、`\\?\...` 形式的前缀都算不合格。
2. 文件映射区间的 `path` 必须等于该文件真实的磁盘路径。
3. 没有文件背衬的区间（匿名映射、私有内存、保留内存），`path` 必须是 `None`，不得是空字符串或占位文本。
4. `file_backed_regions(pid)` 返回 `regions(pid)` 中 `path` 不为 `None` 的
   子集，顺序与 `regions()` 一致。

### C. 模块清单

`modules(pid)` 返回已加载的映像，按 `base` 升序；每个映像只出现一次，同一个文件路径不得重复出现，`path` 是映像文件真实的磁盘路径。

清单必须是完整的：已加载的映像都要出现；如果某个映像的文件路径无法还原成
调用方可直接打开的形式，该映像仍然必须出现，它的 `path` 允许为 `None`。

### D. 错误分类

所有失败路径都必须抛 `WVasError`，不得把 `OSError` 泄漏给调用方：

| 情形 | `kind` |
|---|---|
| pid 不是有效的进程 ID（负数等） | `badarg` |
| 进程不存在 | `no-such-process` |
| 进程存在但无权打开 | `access-denied` |
| 目标平台不支持该查询 | `unsupported` |
| 查询本身失败 | `query-failed` |

### E. 边界与回归

1. `protection_name()`、`type_name()` 保持纯函数语义：只做常量到短名的映射，
   不查任何进程。
2. `C:\testbed\tests\test_wvas_basic.py` 是当前可见的冒烟用例，必须继续全部
   通过；不要为了通过它而改动它。
3. 允许使用 `ctypes` 调用系统 API；不得引入标准库以外的依赖，不得联网。

## 运行入口

自测：

```
python -m pytest tests -q
```

评测用的行为用例由评测侧注入，不在 `C:\testbed` 内，且会**另起一个目标进程**
独立测量：它不会采信 `wvas` 自己报出的任何数字。地址空间审计必须对任意进程
成立，不能只对当前进程成立。
