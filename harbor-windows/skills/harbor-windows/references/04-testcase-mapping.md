# 04 · 题面 ↔ testcase 双向映射

来源：规范第六章

---

## 一、双向映射定义

```
正向：题面要求 / 公开契约 → testcase → F2P/P2P 分组
反向：testcase → 题面要求 / 公开契约 → 预期行为
```

**两侧都必须能对上**，任一方向断裂即为映射缺陷。

---

## 二、逐条检查的 7 项

| # | 检查问题 | 不合规表现 |
|---|---|---|
| 1 | testcase 是否**严格对应**模型实际收到的题面或当时可见的公共契约？ | 测试依赖题面未提及的内部实现 |
| 2 | 是否加入**未声明要求、与题面相反的要求或事后新增契约**？ | 测试断言题面没说的行为 |
| 3 | 是否触发候选代码的**真实生产路径和目标 Windows 机制**？ | 只测辅助函数，未走主流程 |
| 4 | 是否验证**输入输出、公共接口、产物、异常、状态或副作用**，而非特定代码写法？ | 断言私有函数名/代码布局 |
| 5 | 是否能接受**独立的等价正确实现**？ | 只有一种写法能通过 |
| 6 | **P2P 是否在初始态通过且与修改范围相关**？ | P2P 在 base 就失败，或与改动无关 |
| 7 | **F2P 是否确由目标缺陷导致初始态失败，并在 Golden 后通过**？ | F2P 失败与目标缺陷无关 |

---

## 三、F2P / P2P 定义

| 类别 | 定义 | 初始态 | Golden 后 |
|---|---|---|---|
| **F2P**（FAIL_TO_PASS） | 由目标缺陷导致失败的测试 | **FAIL** | **PASS** |
| **P2P**（PASS_TO_PASS） | 与修改范围相关、本应保持通过的测试 | **PASS** | **PASS** |

**约束**：
- P2P 必须在**初始态通过**且**与修改范围相关**（回归保护）
- F2P 必须**确由目标缺陷**导致初始态失败
- **required testcase 不得缺失、跳过却被计分**

---

## 四、验证功能而非写法

**允许**：
- 合理的等价实现
- 不同的内部符号名或结构

**禁止**将以下变成隐藏要求：
- Golden 新增的私有函数名
- 函数签名 / 参数个数
- 代码布局 / 固定调用顺序
- 代码文本 / 字符串匹配

**例外**：公开 API、协议、文件格式或 ABI 本身有明确契约时，可以严格验证。

---

## 五、功能测试要求（第六章 6.3）

| 要求 | 说明 |
|---|---|
| 核心断言 | 必须验证**真实功能、Windows 行为或系统终态** |
| 辅助证据 | Patch Diff、源码关键词、正则、文件/进程/端口存在、日志文本**只能作辅助** |
| 构建成功 | **不能**作为核心功能的唯一判据 |
| Mock/Stub | 必须与冻结真实依赖的输入、输出和错误语义一致 |
| 异步/子进程/负观察 | 必须有**完成回执或独立健康哨兵**；不能把提前退出或观察器未启动判为通过 |
| 产物来源 | 每次运行前清除旧构建产物和系统残留，确保产物来自本轮候选代码 |
| 副作用清理 | 注册表、服务、计划任务、证书、ACL、防火墙、安装器、驱动变更**必须可清理、可恢复** |

## 六、testcase_mapping.csv 格式

产出位置：`delivery-extras/tasks/<task-id>/testcase_mapping.csv`

```csv
testcase_id,group,requirement_source,expected_behavior,verification_type,equivalence_ok
tests/test_vscode_credential.py::...::test_get_token_info,F2P,instruction.md#目标2,返回有效 token 信息,公共接口是
tests/test_context_manager.py::test_close[AzureCliCredential],P2P,既有兼容性要求,凭证对象可正常关闭,公共接口是
```

| 字段 | 说明 |
|---|---|
| `testcase_id` | 完整测试标识 |
| `group` | `F2P` / `P2P` |
| `requirement_source` | 题面出处（章节/段落）或"既有兼容性要求" |
| `expected_behavior` | 预期行为描述 |
| `verification_type` | 验证类型（公共接口/产物/异常/状态/副作用） |
| `equivalence_ok` | 是否接受等价实现（`是`/`否`，`否` 需说明理由） |

## 七、审查清单

- [ ] 每条 F2P 都能追溯到题面明确要求
- [ ] 每条 P2P 在初始态通过且与修改范围相关
- [ ] 无未声明要求、无相反要求、无事后新增契约
- [ ] 测试走真实生产路径与 Windows 机制
- [ ] 验证公共契约而非特定写法
- [ ] 独立等价实现能通过
- [ ] 无绑定 Golden 私有函数名/签名/调用顺序
- [ ] 异常/副作用有独立断言，不只是退出码
- [ ] 异步与负观察有完成回执
- [ ] `testcase_mapping.csv` 双向可查
