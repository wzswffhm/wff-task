# wexec —— 构建工具按名字找不到非 .exe 的可执行文件

## 背景

`wexec` 是构建流水线里用来按名字查找并执行外部命令的小库。工具链中的很多「命令」在 Windows 上并不是 `.exe`：构建包装脚本是 `.cmd`，旧工具是 `.bat`。

## 现象

1. 流水线报「找不到命令」，但把同一个名字敲进 PowerShell 却能跑起来 —— 因为查找逻辑只认 `.exe`。

2. 调用方明确写上 `tool.exe` 时反而找不到，查找逻辑在名字后面又拼了一次扩展名。

3. 少数包装脚本能被找到，但启动时抛 WinError 193，因为批处理脚本不能由 CreateProcess 直接执行。

## 目标

让 `wexec` 在上述这些真实的 Windows 场景下都能给出正确结果：

1. 命令解析必须遵循 `PATHEXT` 中声明的扩展名与顺序，不得只认 `.exe`。

2. 名字本身已经带扩展名时不得再叠加，`tool.exe` 不应被拼成 `tool.exe.exe`。

3. 批处理脚本（`.cmd` / `.bat`）必须通过命令解释器启动，并且脚本的退出码要如实反映在返回结果里。

## 功能边界

- **需要支持**
  - `resolve` 对 PATH 与 PATHEXT 的解析结果
  - `run` / `run_ok` 对解析结果的执行与退出码、输出采集
- **不需要处理**
  - App Paths 注册表项与 `where` 的全部行为
  - PowerShell 脚本（`.ps1`）的执行策略
  - 命令别名与函数

## 约束

- 目标环境：Windows Server 2022（x64），Python 3.12
- 只允许使用 Python 标准库，**不得引入新的第三方运行时依赖**
- 不得改变 `resolve` / `run` / `run_ok` / `executable_extensions` 的公开签名与既有语义
- 不得修改或删除仓库自带的测试，不得为了通过而放宽既有行为
- 必须保持断网可运行

## 允许修改范围

`wexec/` 包内的源码。`tests/` 下只允许新增测试文件，不得改动既有测试。

## 验收标准（用户可见）

1. PATH 中存在 `hello.CMD` 时，`resolve("hello")` 返回该脚本的路径。

2. `PATHEXT` 顺序变化时，解析结果随之变化。

3. `resolve("direct.CMD")` 直接命中该文件，不再叠加扩展名。

4. `run(["hello"])` 能成功执行 `.CMD` 与 `.BAT` 脚本，并返回其退出码与标准输出。
