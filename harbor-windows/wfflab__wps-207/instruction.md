# wjob —— PowerShell 步骤失败仍然被判定为成功

## 背景

`wjob` 把 PowerShell 脚本当作流水线里的一个步骤来执行，并根据它的退出码决定要不要继续后面的步骤。Windows PowerShell 的退出码语义与 shell 脚本差别很大。

## 现象

1. 脚本里执行的外部命令明明返回了非零，流水线却继续往下跑，错误版本被发布出去。

2. 脚本里出现 Write-Error 或访问不存在的路径时，返回码依然是 0，失败步骤被记录成成功。

3. 失败时的错误信息完全丢失，日志里只有标准输出，排查时无从下手。

## 目标

让 `wjob` 在上述这些真实的 Windows 场景下都能给出正确结果：

1. 步骤的退出码必须如实反映脚本的执行结果：原生命令的退出码要上传，脚本自身的错误不得被吞掉。

2. 错误流必须被采集并在结果对象里暴露出来，不得丢弃。

3. 正常的成功脚本仍然返回 0，标准输出不受影响。

## 功能边界

- **需要支持**
  - `run_script` 的退出码、标准输出与错误流
  - `run_file` 对 `.ps1` 文件的执行
  - `PSResult` 的 `ok` / `exit_code` 语义
- **不需要处理**
  - PowerShell 会话复用与远程执行
  - 执行策略（ExecutionPolicy）的修改
  - Windows PowerShell 7 的行为差异

## 约束

- 目标环境：Windows Server 2022（x64），Python 3.12
- 只允许使用 Python 标准库，**不得引入新的第三方运行时依赖**
- 不得改变 `run_script` / `run_file` / `PSResult` 的公开签名与既有语义
- 不得修改或删除仓库自带的测试，不得为了通过而放宽既有行为
- 必须保持断网可运行

## 允许修改范围

`wjob/` 包内的源码。`tests/` 下只允许新增测试文件，不得改动既有测试。

## 验收标准（用户可见）

1. 脚本中执行 `cmd /c exit 3` 时，返回的退出码为 3。

2. 脚本中出现非终止错误（如 Write-Error、访问不存在的路径）时返回非零退出码。

3. 错误流内容出现在结果对象的 `stderr` 或 `stdout` 中。

4. 正常脚本仍然返回 0，输出可读。
