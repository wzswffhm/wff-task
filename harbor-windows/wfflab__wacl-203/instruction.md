# wpublish —— 共享目录发布未让只读权限覆盖整棵子树

## 背景

`wpublish` 把构建产物发布到公司的共享目录上，要求访问者只能读、不能改。发布动作本身是「复制目录树 + 设置权限」，而权限必须覆盖整棵子树，包括发布之后才产生的文件。

## 现象

1. 发布目录根部看起来是只读的，但子目录与子文件仍可被访问者改写；有人覆盖了发布包里的安装脚本，回滚时才发现。

2. 发布之后新生成的文件完全不受限制，因为根目录上的拒绝项没有带继承标记。

3. 审计工具把从父目录继承来的权限当成显式设置，报告里出现了一堆「显式授予」条目，运维无法据此判断谁改过权限。

## 目标

让 `wpublish` 在上述这些真实的 Windows 场景下都能给出正确结果：

1. 发布动作必须让只读限制覆盖整棵子树：既作用于发布时已经存在的条目，也要带上继承标记，让之后新建的条目同样受限。

2. 有效权限判定必须遵守 Windows 的**显式拒绝优先**规则：只要命中拒绝项就不予授予。

3. 显式访问控制项与从父级继承来的项必须区分开。

## 功能边界

- **需要支持**
  - `publish` 的权限下发范围
  - `can_write` / `can_read` / `effective_rights` 的判定结果
  - `list_explicit_aces` 与 `list_aces` 的差别
  - `audit` 对发布结果的复核
- **不需要处理**
  - 所有权与特权提升
  - 跨域或跨林的安全主体解析
  - 共享（SMB）层面的权限与 NTFS 权限叠加

## 约束

- 目标环境：Windows Server 2022（x64），Python 3.12
- 只允许使用 Python 标准库，**不得引入新的第三方运行时依赖**
- 不得改变 `publish` / `audit` / `can_write` / `list_explicit_aces` 的公开签名与既有语义
- 不得修改或删除仓库自带的测试，不得为了通过而放宽既有行为
- 必须保持断网可运行

## 允许修改范围

`wpublish/` 包内的源码。`tests/` 下只允许新增测试文件，不得改动既有测试。

## 验收标准（用户可见）

1. `publish` 之后，目标子树中发布时已存在的目录与文件都带有拒绝项。

2. `publish` 之后在目标子树中新建的文件同样带有拒绝项。

3. 同时存在允许项与拒绝项时，`can_write` 返回 `False`。

4. `list_explicit_aces` 不返回任何带继承标记的项。

5. `audit` 对刚发布完的目录返回空列表。
