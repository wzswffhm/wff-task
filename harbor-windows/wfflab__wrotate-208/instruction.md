# wrotate —— 目标序号已有残留时日志轮转失败

## 背景

`wrotate` 负责把服务的日志按序号滚动：`app.log` 滚成 `app.log.1`，已有的轮转依次后移，并按保留份数删除最老的那些。

## 现象

1. 服务重启后第一次轮转就失败：上一轮异常退出时留下的 `app.log.2` 还在，搬到同一个序号上时直接抛 FileExistsError。

2. 中途失败会把状态搞乱：一部分轮转已经后移、另一部分还没动，序号之间出现空洞，日志顺序对不上。

3. 保留份数按文件名排序，导致保留 10 份时反而把 `app.log.1` 删掉、把 `app.log.11` 留了下来。

## 目标

让 `wrotate` 在上述这些真实的 Windows 场景下都能给出正确结果：

1. 序号搬运必须在目标已存在时也能成功完成，不得因为残留文件中断。

2. 一次轮转要么完整完成，要么回滚到开始前的状态，不留半截结果。

3. 保留份数必须按**序号**从大到小删除，而不是按文件名的字典序。

## 功能边界

- **需要支持**
  - `rotate` 的搬运结果与失败回滚
  - `prune` 的保留份数选择
  - `rotate_and_prune` 的组合行为
- **不需要处理**
  - 按大小触发轮转与压缩归档
  - 打开中的日志句柄管理
  - 跨卷轮转

## 约束

- 目标环境：Windows Server 2022（x64），Python 3.12
- 只允许使用 Python 标准库，**不得引入新的第三方运行时依赖**
- 不得改变 `Rotator.rotate` / `prune` / `rotate_and_prune` / `fsutil.move` 的公开签名与既有语义
- 不得修改或删除仓库自带的测试，不得为了通过而放宽既有行为
- 必须保持断网可运行

## 允许修改范围

`wrotate/` 包内的源码。`tests/` 下只允许新增测试文件，不得改动既有测试。

## 验收标准（用户可见）

1. 目标序号上已有残留文件时，轮转仍然完成，各世代内容正确接力。

2. 轮转失败时目录回到开始前的状态。

3. 保留 10 份时保留的是 `app.log.1` 至 `app.log.10`，删除的是序号最大的那些。

4. `app.log` 不存在时轮转是空操作。
