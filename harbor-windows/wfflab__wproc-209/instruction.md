# wproc 在 Windows 构建代理上失控的子进程

## 背景

`wproc` 是构建与部署代理用来**受控地**运行外部命令的小库：给定参数、限定时间、收回输出。
同一份代码在 Linux 构建节点上跑了一年多没有出过事，迁到 Windows 构建服务器之后运维开始持续收到三类工单。

共同点是：**同一条命令、同一份输出目录，在 Linux 上收得住，在 Windows 上收不住。**

1. **超时之后进程还在跑**

   `run(["python", "build.py"], timeout=600)` 到了时间预算、返回了 `timed_out=True`，
   但 `build.py` 拉起来的编译器、打包器、`cmd /c ...` 里的业务程序仍在后台继续写文件、占着输出目录。
   下一个构建任务随即随机失败，值班同学只能重启机器。
   命令链条越长越明显：`python → cmd /c → 真正干活的程序`。

2. **超时之后输出不见了**

   命令在被终止之前明明已经打印了报错信息，超时返回的结果里却是空的。
   日志里什么都查不到，排障只能靠猜。
   输出量大（几百 KiB 的构建日志）时更明显。

3. **明明结束了的命令被判成超时**

   有些命令自己很快就退出了（退出码 0），但只要它顺手启动的后台子进程还活着，
   `run()` 就会一直耗到时间预算用完，然后报 `timed_out=True`——
   退出码和输出全都对不上实际发生的事。这类命令在 Windows 上尤其常见。

## 目标

让 `wproc.run` 在上面三类真实的 Windows 状态下都给出正确结果：

1. 一旦某次运行因为超出时间预算而被终止，**该命令启动的整棵进程树（含后代的进程）都必须停止**；
   `run()` 返回之后，不得再有属于这次运行的进程继续活动。
   终止只允许影响这次运行自己的进程，**不得波及其它无关进程**。

2. 无论运行是正常结束还是被终止，`RunResult.output` 必须包含**该命令在结束之前已经写到
   stdout 与 stderr 的全部内容**，不得因为「到点了」就整段丢弃；输出达到数百 KiB 时同样不得丢。

3. 直接子进程一旦结束，这次运行就结束了：**不得再为了等待它的后代释放输出管道而继续等到时间预算耗尽**。
   此时 `timed_out` 必须为 `False`，`returncode` 必须是那个子进程真实的退出码，输出按第 2 条给出。

## 功能边界

- **需要支持**
  - `run(command, timeout=None, cwd=None, env=None, check=False)` 在上述状态下返回正确的 `RunResult`
  - `RunResult` 的 `returncode` / `output` / `timed_out` / `ok` / `text()` 语义保持不变
- **不需要处理**
  - 网络共享路径、UNC 路径、超过 `MAX_PATH` 的超长路径
  - Windows 服务、驱动、会话隔离与桌面交互
  - 交互式命令：子进程的 stdin 始终是空设备

## 约束

- 目标环境：Windows Server 2022（x64），Python 3.12
- 只允许使用 Python 标准库，**不得引入新的第三方运行时依赖**；
  可以调用 Windows 自带的命令行工具
- 不得改变 `run` / `RunResult` / `CommandFailed` / `CommandTimedOut` 的公开签名与既有语义
- 不得修改或删除仓库自带的测试，不得为了通过而放宽既有行为
- 必须保持断网可运行

## 允许修改范围

`wproc/` 包内的源码。`tests/` 下只允许新增测试文件，不得改动既有测试。

## 验收标准（用户可见）

1. 命令因超时被终止后，它启动的后代进程也停止：`run()` 返回后再观察一段时间，
   这些进程不再有任何活动。
2. 终止一次运行不会影响同一台机器上其它无关进程。
3. 超时返回的 `RunResult.output` 包含截止之前已经写到 stdout 与 stderr 的内容；
   输出达到数百 KiB 时同样不丢。
4. 直接子进程自己结束后，即使它启动的后台后代仍然活着并持有输出管道，
   `run()` 也必须立即返回：`timed_out=False`、`returncode` 为真实退出码、`output` 为已产生的内容。
5. 直接子进程以非零码结束时，退出码原样返回，且 `timed_out=False`。
6. `check=True` 时，非零退出码抛 `CommandFailed`、超时抛 `CommandTimedOut`，两者都带着完整结果。
7. 以上任何情况下，`run()` 都不得抛出与子进程行为无关的异常。
