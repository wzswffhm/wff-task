# wtask：任务调度结果与规格不符（issue #216）

`wtask` 是我们配置管理系统在 Windows 侧用来**预演计划任务**的纯 Python 引擎：
它把任务 XML 解析成模型，并回答「接下来什么时候会跑」。配置中心按它给出的
运行时刻生成巡检日历，因此**同一份任务 XML 必须永远算出同一组时刻**。

最近配置中心上线后陆续收到事故单，汇总如下。

## 现象

1. **每日任务的相位错了**：一份 `DaysInterval=3`、起点 `2026-01-01` 的每日任务，
   日历上落在 1/3、1/6、1/9 …，而值班表排的是 **1/1、1/4、1/7 …**。
   看起来周期从「当月的日号」而不是从任务起点开始算。
2. **每周任务的隔周设置被吞掉**：`WeeksInterval=2` 的任务**每周**都在跑，
   隔周一次完全没生效。
3. **月度任务跑到了没勾选的月份**：只勾了 1 月和 7 月的任务，
   2 月、3 月也照跑。
4. **月末语义不对**：`ScheduleByMonthDayOfWeek` 里 `<Week>5</Week>` 按规格应表示
   「该月最后一周」，实际却在只有 4 个日历周的月份（例如平年 2 月）里**一次都不触发**。
5. **重复触发的次数多了一次**：`Interval=PT30M`、`Duration=PT1H` 的任务，
   本应只在 `08:00 / 08:30` 各跑一次，实际还多跑了一次 `09:00`。
6. **`<Repetition>` 会越过 `<EndBoundary>`**：设了结束边界的任务，
   重复出来的时刻仍然落在边界之后。
7. **被禁用的触发器照样参与计算**：把某个触发器标成 `<Enabled>false</Enabled>`，
   它的时刻仍然出现在结果里。
8. **时长回写不是规范形式**：`PT72H` 这类时长回写后应与规范形式一致，
   现在回写的文本与规格 §6 不符，导致下游按 hash 做增量同步时误判为「配置被改过」。
9. **错误类型不可用**：坏 XML、未知触发器元素、不支持的 `version`、越界的
   `DaysInterval` 等，抛出的都是 `ValueError` / `struct.error` 之类的临时异常，
   调用方无法按类别处理；偶尔干脆不报错，把非法配置当成正常任务。
10. **`ExecutionTimeLimit=PT0S`（不限时长）被当成 0 秒**：
    调用方拿到的是 `timedelta(0)` 而不是「不限」。

## 权威依据

仓库里的 `docs/TASKSCHEMA.md` 是本项目的**权威规格**，覆盖四种日程的语义、
重复与边界、时长的规范形式、规范化序列化以及错误分类。上面的每一条现象，
规格里都有对应的条款。

## 任务

修正 `wtask/` 下的实现，使其**完全符合** `docs/TASKSCHEMA.md`。

## 验收标准

* 规格 §3（四种日程）——含每日任务的起点锚定、`WeeksInterval`、`Months` 过滤、
  以及 `<Week>5</Week> = 该月最后一周` 的语义；
* 规格 §4 / §5（主出现、`EndBoundary`、`Repetition` 的 `k×Interval < Duration` 与边界约束）；
* 规格 §6（时长的解析与**规范形式**）；
* 规格 §7（规范化序列化、幂等、可原样回写）；
* 规格 §8（`next_runs` / `plan_window` 的边界与去重，任务与触发器两级的启用开关）；
* 规格 §9（错误分类：所有结构 / 取值问题都必须是 `TaskDefError`，
  且 `.kind` 取值与规格表一致）。
