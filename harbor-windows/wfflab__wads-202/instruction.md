# wdl —— 下载文件归档时丢掉 NTFS 备用数据流

## 背景

`wdl` 负责把浏览器与下载器落地的文件归档到备份盘，并在发布到内网之前按策略清掉「来自互联网」标记。这个标记在 NTFS 上是一条名为 `Zone.Identifier` 的备用数据流，而不是文件内容的一部分。

## 现象

1. 归档之后的副本不再带有来源标记，内网发布流程因此认为所有文件都是本地产生的，安全策略形同虚设。

2. 统计归档体积时，带标记的文件被算少了几十字节，与磁盘实际占用对不上。

3. 对从未下载过的本地文件调用解除标记接口时直接抛出 FileNotFoundError，批量处理脚本因此在第一个干净文件上就中断。

## 目标

让 `wdl` 在上述这些真实的 Windows 场景下都能给出正确结果：

1. 归档复制必须连同文件的备用数据流一起搬运，`Zone.Identifier` 的内容要逐字节一致。

2. 备用数据流的大小必须按流本身计算，而不是取主数据的大小。

3. 解除标记接口对没有标记的文件必须幂等：返回是否发生变化，而不是抛异常。

## 功能边界

- **需要支持**
  - `copy_file` / `archive_tree` 对普通文件与带备用流文件的搬运
  - `stream_*` 系列对已知流名的读写、存在性与大小查询
  - `unblock` / `is_blocked` 对来源标记的查询与清除
- **不需要处理**
  - 枚举文件上全部备用流
  - 稀疏文件、压缩属性与配额
  - 跨卷或跨文件系统的搬运

## 约束

- 目标环境：Windows Server 2022（x64），Python 3.12
- 只允许使用 Python 标准库，**不得引入新的第三方运行时依赖**
- 不得改变 `copy_file` / `archive_tree` / `stream_size` / `unblock` 的公开签名与既有语义
- 不得修改或删除仓库自带的测试，不得为了通过而放宽既有行为
- 必须保持断网可运行

## 允许修改范围

`wdl/` 包内的源码。`tests/` 下只允许新增测试文件，不得改动既有测试。

## 验收标准（用户可见）

1. `copy_file` 之后目标文件上的 `Zone.Identifier` 流存在且内容与源一致。

2. `archive_tree` 对嵌套子目录中的文件同样保留备用流。

3. `stream_size` 返回的是流的字节数，而不是主数据的大小。

4. `unblock` 对没有标记的文件返回 `False` 且不抛异常，对带标记的文件返回 `True` 并真正清掉该流。
