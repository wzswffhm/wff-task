## 逐条判据

| # | 要求 | 质检时要看的证据 | 不通过的情形 |
|---|---|---|---|
| 1 | **性能/流式断言不得固定魔法阈值** | 断言是否用"输入放大 N 倍"的**规模对比**；是否完整消费迭代器；尾部错误是否有独立断言 | 只消费第一条；硬编码 `max_request ≤ 8192` 之类块大小；无尾部错误断言 |
| 2 | **API 失败单列无效槽位** | `invalid-slots.json` 等注解层是否存在；归档树是否逐字节未被改写；替代轮是否绑定同一计划槽位；是否记录**执行时** runner SHA | HTTP 429/配额/超时被写成正式 0 分；改写原始日志；替代轮给某模型额外加权 |
| 3 | **Windows 价值真实映射** | 要求到 OS 机制的逐条映射；分类字段（如 `primary_direction`）；价值说明文档 | 仅"跑在 Windows 上"；只改题名或强加平台标签；用新需求追溯扣旧样本 |
| 4 | **权重声明必须有证据或正式废止** | 三个通道是否分开（程序化 / 评审项 / 最终分）；逐候选评分证据与合成公式；废止是否有版本化说明 | 声明 50% 评审却只有程序化结果；用程序化满分冒充完整分；保留不生效权重 |
| 5 | **判分配置可被标准解析器读取** | `judge.toml` / `adapter.toml` 能否被 `tomllib` 完整解析；必要字段与 case ID 引用；生效配置 SHA | `Invalid statement (at line …)`；仅凭历史 score 存在即认定配置可用 |
| 6 | **公开测试与隐藏验收分层 + 负访问证明** | 三类材料（公开/隐藏/参考解）的目录、用途、作答期权限；运行时挂载与负访问探针结果 | 仅凭目录名声称隔离；仅凭读过公开测试定性作弊；隐藏材料在作答期可达 |

## 通用复验标准

1. 每条意见都有**可复算证据**（文件 / 脚本 / 日志 / 哈希），不是口头说明。
2. 控制系统复现：Golden 全 1、no-change 全 0，与整改前一致。
3. 题包内容有任何改动 → 旧 jobs 的 `task_checksum` 失效 → **整批重跑**，不得复用旧轮次。
4. 区分度只用主模型（Opus 与 Qwen）判定；GLM/Kimi 自 2026-10-13 起为可选，其结论不替代主判据。
5. 归档为 **archive-only**：只聚合与注解，不新增执行、评分、run id 或 task checksum。
6. 分类与采购目标必须有明确对应。
