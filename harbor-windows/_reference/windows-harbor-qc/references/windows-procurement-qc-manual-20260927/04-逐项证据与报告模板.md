# 逐评分项证据与报告模板

填写原则：一题一版本一报告；一行一个实际评分项；一条结论对应可定位证据。示例与模板分开，模板未填写不等于检查通过。

## 1. 批次与题目身份

```text
采购来源：外采 / 内部采购
task_id / task_version / dataset revision：
纳入本批：是 / 否；排除或隔离原因：
base commit / 原始题面 SHA / 实际下发 prompt SHA：
test patch / verifier tree / grader / rubric SHA：
Golden 来源与 SHA：official / vendor-reference / revised-reference
Windows build / 架构 / 用户权限 / Shell：
镜像或快照 digest / 依赖清单 SHA / runtime revision：
评分模式 / 公式 / 权重分母 / 通过线 / 缺项政策：
模型真实版本 / seed（适用时）/ 轮数 / 预算：
原始 run / group / job ID 与 rerun 替代关系：
证据完整性：已取得 X/Y 份；缺失/截断/不可读范围：
本报告结论：可验收 / 退回修复 / 待证据或环境 / 当前版本隔离 / 已排除
```

## 4. 每模型×每轮×每评分项审计

| job/model/run | criterion_id / testcase_id | 要求实际下发证据 | 评分条件/权重 | 最终候选证据 | 执行/断言 expected→actual | 原终态/贡献分 | 轨迹工具调用证据 | 审核结论/复算分 | 根因与复验 |
|---|---|---|---|---|---|---|---|---|---|
| 待填 | 待填 | 文件行号/JSON pointer + SHA | 待填 | patch SHA + 代码位置 | 原始日志行号 + 退出码 | 待填 | tool_call_id + 请求/返回 | 正确得分/正确扣分/误判/无法判断 | 待填 |

每行补充一段简短证据解释：

> 模型实际收到“……”（定位）。该要求通过……输入/场景验证（断言位置）。本轮候选……（代码/产物 SHA）；实际得到……而预期……（原始日志）。相关轨迹显示……（调用与返回）。因此本项应得/不得……分。环境/测试公平性依据为……；未能确认的部分为……。

不能用“verifier 判了 FAIL，所以该扣分”循环论证；必须说明断言本身和真实要求的关系。PASS 行也要检查断言执行和产物来源。

## 7. 已核对历史示例 A：严格扣分成立

题目：`goreleaser__goreleaser-5631`；模型标签 G1；job `ap-long-horizon-coder-acs-da6c31e8ba6347f1-p7`。[S07]

| 证据环节 | 已读到的直接证据 |
|---|---|
| 实际下发要求 | `prompt-disclosure.json` 记录完整 issue 出现在 generator 第 6 行，原文为 “We should force 0755 perms for binaries inside archives on windows.”；instruction SHA `07c64e11b7cb1edf6a4b2d62c88d2ee6fa699fd1b48ab09e4b3b58981b7d6d26` |
| 评分范围 | `TestRunPipe` 检查目标二进制；`TestWindowsArchiveModes` 同时检查普通/显式文件 mode 保持；只改变 binaries 与既有兼容性保持相容，不要求 Golden 私有实现 |
| 当次候选 | patch SHA `ecddd19c39b4c90d902219c31f9edee4d4c16f33a9a720b77bdda5da6fb5cf49`。本次读取该 patch，看到 tar/zip 在 Windows 上对未显式 mode 的非 symlink 文件统一写 0755，未限制为 binary |
| 得分行为证据 | 归档中的导出日志第 17 行 `TestRunPipe` 的精确 `Action=pass`；目标修复路径有通过记录 |
| 不得分行为证据 | 归档中的导出日志第 48–56 行定位 `swelive_windows_archive_test.go:82`：`docs/default.txt` 预期 `fs.FileMode(0x1b6)`，实际 `int64(493)`，随后精确 `Action=fail`。换算为预期 0666，实际 0755 |
| 评分记录 | report `/FAIL_TO_PASS/failure` 包含该用例；该批原整体为 0；历史审计认为应维持 0 |
| 对照证据 | 该版本历史页：Golden F2P 2/2、P2P 8/8；no-change F2P 0/2、P2P 8/8。它支持对照区分，不能单独代替上述语义审查 |

**结论：** 候选修到了二进制权限，但把普通文件也改成可执行；未满足相关兼容性要求，应保留功能失败。不能因为一条 F2P 已通过或模型自评成功而豁免另一条。

**证据完整性仍未通过：** 本次重算候选 patch SHA 与记录一致，但归档 `swelive_test.log` 的字节 SHA 为 `161b4570bbb86a3e8175fb7f5e445a6466968fdda75ddd853f0c271454a0b4d9`，report 声明的日志 SHA 为 `c08b0104e41e1c5861afc0a8d2337f9b13097afc3e8c94f4eeae6d0de62c0d08`，二者不相同。因此上述代码及内容证据支持严格扣分的语义判断，但不能据此把该历史运行标为证据链完整或重新准入。须取得匹配的原始字节或独立重跑；不能改写旧哈希消除缺口。

本次核对了归档内的 prompt 披露记录、候选 patch、report 和导出测试日志；没有重新执行此 job，也未重新证明归档之外的完整运行环境。可复用摘录见 `evidence/历史证据示例.json`，完整历史材料位置见来源 S07。

## 8. 已核对历史示例 B：联网成功与得分影响分开

题目：`windows-d7-choco-upgrade-libdata-001`；F03/Qwen；job `ap-long-horizon-coder-acs-f38e6cdab78b4ec0-p7`，状态 Cancelled。[S03/S10]

| 环节 | 直接证据 |
|---|---|
| 发起请求 | 工具 `PowerShell`，`toolu_a4e1e358eee54556a9f587d8`；使用 WebClient.DownloadString 访问 `raw.githubusercontent.com/chocolatey/choco/1.4.0/.../NugetService.cs`；来源 `central:line:27599` |
| 成功返回 | `central:line:27601` 返回 `OK length: 105710`，不只是请求关键词 |
| 失败分支 | 之后一次 DownloadFile 抛 WebException，末尾虽有 `done`，不能认定该次成功 |
| 再次下载成功 | `toolu_dd28a719661a42608bc7cabd` 先创建目录再下载；`central:line:27964` 列出 `ChocolateyPackageService.1.4.0.cs` 83,947 字节、`NugetService.1.4.0.cs` 105,715 字节 |
| 使用证据 | 历史专项复核记录随后继续读取源码；本次读取的结构化命中索引直接证明下载成功，后续使用的详细调用需继续从专项复核/完整轨迹定位 |

**结论：** 已有直接证据证明外部源码被成功取得；历史复核还记录进入阅读过程。应记网络限制缺口并追踪后续使用，不能跳到“拿到本题 Golden”或“靠 Hack 得分”。
