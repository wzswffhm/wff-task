## 1. 逐条闭环

### ZQ005-01｜问题｜流式测试引入未声明的 8192 字节读块阈值
手册对应：QD-SP-02, VV-02, VV-03。

| 专家步骤 | 处置 |
| --- | --- |
| ① 依据公开契约设计随输入规模增长的观测，不私自固定小块 | 删除 `max_request <= 8192` 硬阈值与 `bytes_read < len(blob) // 4` 比例断言。改为**规模对照法**：同一实现分别跑 4000 条记录（256 B/条）与 1/8 规模输入，断言 `max_request(大) <= max_request(小)`——窗口不得随输入规模增长，且不指定任何具体块大小。 |
| ② 完整消费迭代器，检查中途与末尾阶段 | 重写 `test_iter_records_is_streaming`：**完整消费**全部 4000 条并按序断言每一条。核心观测量是「**容器被读满时仍未产出的记录条数**」——有界缓冲下它是常数（≈ 窗口大小 / 单条记录大小），而伪流式（先全读再吐）或"先吐第一条再把剩余全部读走"都会让它随输入规模线性增长，因此用 8 倍规模对照判定：`pending(大) <= max(pending(小) × 2, 8)`。不假设任何块大小，**64 KiB 级定长缓冲同样通过**（本包参考实现即定长 4096 窗口预读，实测通过——这正是旧断言会误杀的形态）。 |
| ③ 构造尾部 CRC 错误，确认完整迭代时抛约定错误；明确阈值依据 | 新增 `test_stream_tail_checksum_is_rejected`：翻转容器最后 4 字节（尾部校验和），断言迭代器**先完整产出全部记录**、再抛 `WFormatError(kind="checksum")`。阈值依据全部来自公开契约：题面 E 节只要求"惰性 + 固定大小 `read(n)` + 取完最后一条仍要校尾校验和"，**未声明任何块大小**，新断言与之逐字对应。旧套件"流式尾部坏 CRC 缺独立断言"的缺口由此补齐。 |

**验收对照**：合理的不同缓冲大小均可通过（已用定长窗口参考实现实测）；伪流式、漏验尾 CRC 的实现被拒绝；判定不依赖任何模型的代码写法。

新增 required：`f2p-stream-tail-checksum-is-rejected`（实测 base 失败 / reference 通过 → **F2P**），required 由 15 → **16**（F2P 9 / P2P 7），rubric `streaming` 项 test_ids 同步收纳，`run_tests.ps1` 的 `$slugByFunction` 同步映射 `test_stream_tail_checksum_is_rejected → stream-tail-checksum-is-rejected`（未映射的新函数不会被收集，故必须同步）。

涉及文件：`verifier/tests/test_wfmt_semantics.py`、`tests/run_tests.ps1`、`tests/required_testcases.json`、`tests/rubric.json`、`tests/judge.toml`、`verifier/rubric.conditions.json`。
