# wsparse：Windows 预分配与磁盘占用统计实现错误

`wsparse` 是我们采集器 / 下载器落盘路径上的**空间管理模块**。它向调用方承诺三件事：

- `preallocate(path, size)`：把文件预分配到 `size` 字节，供后续顺序写入直接覆盖，避免边写边扩盘；
- `disk_usage(path)`：报告文件**在磁盘上真实占用的字节数**，用于配额统计和「采集器为什么把盘写满」的告警；
- `allocated_ranges(path)`：报告文件中**真实分配了磁盘簇**的字节区间，供传输层判断哪些区域还需要下载。

## 目标平台（范围声明）

本任务的目标平台是真实的 Windows + NTFS，验收不使用其他操作系统，也不需要实现其他操作系统的版本。

`wsparse` 的验收建立在真实 NTFS 卷的簇分配语义上：「预分配」不得以写满全零的方式实现，「占用统计」必须反映真实的簇分配，「区间查询」必须反映真实的已分配范围。评测器运行在 Windows Server Core 容器中、工作卷为 NTFS，它自己持有文件句柄并独立观测文件在磁盘上的真实布局，**不采信** `wsparse` 自己的返回值。

跨平台兼容（POSIX `ftruncate`、Linux `fallocate` 之类）不在验收范围内，也不构成替代实现。

## 现象（仓库 issue #215）

1. **预分配真的把盘写满**：`preallocate("sink.bin", 1 << 30)` 在 Windows 上跑很久，而且文件立刻占满 1 GiB；同样一行代码在 Linux 上瞬间返回、几乎不占空间。采集器在盘上预分配几十个分片后直接报磁盘满。
2. **占用统计报的是逻辑长度**：对一个逻辑 64 MiB、实际只占 128 KiB 的稀疏文件，`disk_usage()` 返回 64 MiB，配额告警全天误报。
3. **区间查询形同虚设**：`allocated_ranges()` 对任何文件都返回 `[(0, size)]`，传输层因此认为整份文件都已下载完，断点续传失效。
4. **稀疏标志设置无效或撒谎**：`sparse_flag(path, True)` 对一个已经扩展成密集的文件返回成功，但磁盘占用一点没降下来。
5. **不支持时不报错**：在不支持稀疏的对象上调用相关接口，有时静默返回成功，有时抛出无分类的 `OSError`。

## 任务

修复 `wsparse` 包，使其满足下列验收标准。`docs/NOTES.md` 是早期草稿，与 NTFS 的实际语义已经不一致，请以本说明的验收标准为准。`assets/dense_64k.bin` 是一个普通的非稀疏文件，可以拿来做对照；本任务不预置任何稀疏样本，需要观察稀疏语义时请自己在 NTFS 卷上准备。

## 验收标准

### A. 稀疏预分配（硬门槛）

- `preallocate(path, size)` 必须在 NTFS 上把文件标记为稀疏文件（sparse），并把文件长度扩展到 `size` 字节。
- 完成预分配后，文件长度必须是 `size`，而它在磁盘上的真实占用必须远小于 `size`：预分配 1 GiB 时真实占用不得超过 8 MiB。
- 预分配必须是幂等的：对同一路径重复调用不得改变上述语义。

### B. 预分配后的写入语义

- 在 `preallocate()` 得到的文件上写入真实数据后，数据必须能按偏移原样读回。
- 只有**真正被写入过**的区域才允许占用磁盘；预分配留下的空洞不得因为一次写入而整体变成已分配。
- 空洞区域读出来必须是全零字节。

### C. 占用统计

- `disk_usage(path)` 必须返回该文件在磁盘上真实占用的字节数，而不是它的逻辑长度。
- 返回值按簇对齐（NTFS 默认簇 4096 字节），允许向上取整。
- 对一个逻辑 64 MiB 且只在两处写入少量数据的稀疏文件，返回值必须小于 1 MiB；对一个同样逻辑长度的密集文件，返回值必须约等于它的逻辑长度。

### D. 已分配区间

- `allocated_ranges(path)` 必须返回文件中真实分配了磁盘簇的区间列表。
- 每个区间是一个 `(offset, length)` 二元组，按 `offset` 升序排列、互不重叠，并且完全落在文件长度之内。
- 全空洞文件返回空列表；非稀疏文件返回覆盖整个长度的一个区间。

### E. 顺序语义（稀疏标志不可回溯）

- 对一个已经扩展成密集的文件再补设稀疏标志，不得谎报成功：此时 `disk_usage()` 必须仍然反映真实的密集占用。

### F. 不支持时的错误分类

- 当底层对象或卷不支持稀疏文件时（例如把一个目录路径交给这些接口），相关接口必须抛出 `WSParseError`，且 `err.kind == "unsupported"`。
- 不得出现静默成功，也不得只抛出无分类的 `OSError`。

### G. 不得回归

- 可见冒烟测试 `tests/test_wsparse_basic.py` 必须继续通过。
- 公开 API 的名称与签名保持不变（`preallocate` / `disk_usage` / `allocated_ranges` / `sparse_flag` / `sparse_state` / `WSParseError`）。
