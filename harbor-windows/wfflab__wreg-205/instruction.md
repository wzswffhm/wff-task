# wregconfig —— 读不到 32 位程序写下的注册表配置

## 背景

`wregconfig` 用来读取与迁移应用配置。同一份配置在 32 位与 64 位程序眼里是两个不同的注册表键：`HKLM\SOFTWARE` 下面的内容按视图分开存放，32 位程序写入的实际落在 `Wow6432Node` 之下。

## 现象

1. 迁移工具报告「旧版本没有配置」，但老版本程序明明把安装路径写进了注册表。

2. 以 32 位视图写入的配置，64 位版本的程序一个也读不到，两边各写各的。

3. 卸载时只删掉了当前视图的键，另一个视图里的残留配置永远清不掉；如果该键下面还有子键，删除动作会直接失败。

## 目标

让 `wregconfig` 在上述这些真实的 Windows 场景下都能给出正确结果：

1. 访问注册表时必须按调用方指定的视图附加对应的 WOW64 标志；`"32"` 视图必须落到 32 位视图，而不是静默地退回进程默认视图。

2. 存在性判定与读取必须在同一个视图内进行。

3. 删除配置节时必须连同子键一起清掉，并返回该配置节此前是否存在。

## 功能边界

- **需要支持**
  - `ConfigStore` 在 `"default"` / `"64"` / `"32"` 三种视图下的读、写、存在性与删除
  - 含子键的配置节删除
- **不需要处理**
  - 注册表事务与回滚
  - 注册表虚拟化（UAC 下的按用户重定向）
  - 权限提升与远程注册表

## 约束

- 目标环境：Windows Server 2022（x64），Python 3.12
- 只允许使用 Python 标准库，**不得引入新的第三方运行时依赖**
- 不得改变 `ConfigStore` / `view_flags` 的公开签名与既有语义
- 不得修改或删除仓库自带的测试，不得为了通过而放宽既有行为
- 必须保持断网可运行

## 允许修改范围

`wregconfig/` 包内的源码。`tests/` 下只允许新增测试文件，不得改动既有测试。

## 验收标准（用户可见）

1. 在 32 位视图中写入的值，用 `view="32"` 的 `ConfigStore` 能读到。

2. `view="32"` 写入的值在 64 位视图中不可见，反之亦然。

3. `exists()` 的结果随视图变化。

4. `delete_tree()` 能删除含子键的配置节，并返回该节此前是否存在。
