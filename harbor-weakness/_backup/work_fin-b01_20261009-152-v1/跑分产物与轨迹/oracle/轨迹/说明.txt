# oracle 执行体轨迹说明

## 为什么本目录没有 `claude-code.txt` / `trajectory.json`

`oracle` 是 harbor 内置的参考解执行体：它直接运行题包内的 `solution/solve.sh`，
把 `solution/golden_output/` 复制到 `/app/output/`，**不经过 claude-code agent 框架**，
因此不产生 claude-code 轨迹。这是 harbor 的设计使然，不是跑分缺失。

本目录保留的取证材料：

| 文件 | 说明 |
|---|---|
| `oracle.txt` | harbor oracle agent 的执行输出（该执行体 stdout 为空属正常） |
| `trial.log` | harbor 试次日志，记录 trial 创建、环境构建与阶段推进时间点 |
| `../reward.json` | 判分主分（oracle = 1.000000，`verifier_error = 0`） |
| `../reward-details.json` | 27 条判据逐条判定明细（审计件） |
| `../output/` | oracle 产出的 3 份交付物快照（与 `solution/golden_output/` 同源） |

## 有效性

- 轨迹框架核对要求（`claude-code` + `version 2.1.114` + `steps`）**仅适用于三模型执行体**；
  oracle 按 harbor 内置 agent 口径豁免，与 FIN3-WKN-149/150/151 已验收题包的处理一致。
- oracle 的判分证据有效：`criteria_counted = 27`、`verifier_error = 0`、
  按 rewardkit 公式复算与 `reward.json` 一致、与现行 `tests/rubrics.toml` 27 条零漂移。
