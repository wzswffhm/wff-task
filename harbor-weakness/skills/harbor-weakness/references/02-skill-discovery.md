# Skill Discovery 专项（200 条）

## Skill Discovery 类出题（多技能环境下的发现与选择）

**目标**：提供**多个 Skill**，要求模型自行判断：
① **是否需要 Skill**；② **应该使用哪个 Skill**。

**交付实现见 `../delivery/`**；技能包封装规范见 `../delivery/08-skill-packaging.md`。

### 用途与触发条件

触发词：Skill 发现题 / Skill 选择题 / 干扰技能 / skill discovery / 多技能环境 / 该不该用 skill。

### 判据（一句话判定）

> 环境中存在 **≥2 个技能**（其中至少 1 个与本任务无关或只部分相关），且**任务书中不暗示**哪个必需。
> 正解可能是"使用技能 A"，也可能是"**不使用任何技能**"。

元数据断言：**`expected_skill_dependencies` 严格小于 `skill_set`**（真子集，存在故意的无关技能）。

### 三类子场景

| 子场景 | 环境 | 正解 | 考察点 |
|---|---|---|---|
| **D1 正确选中** | 多个技能，其中**恰有 1 个**必需 | 使用该技能完成 | 从描述判断适用性 |
| **D2 正确不用** | 多个技能，**都不必需**（任务靠通用能力即可） | **不使用任何技能** | 抑制"见到技能就用"的倾向 |
| **D3 辨别相近技能** | 两个技能**描述相近**，只有 1 个含本题所需规则 | 选中含所需规则的那个 | 细读 SKILL.md 而非只看 description |

> **D2 是最容易被忽略但价值最高的一类**：防止模型形成"装了技能就必须用"的偏差。

### 端到端流程

```
① 选定子场景（D1/D2/D3） → ② 设计技能集合（必需 + 干扰） → ③ 构造任务与源文件
→ ④ 写各技能 SKILL.md（干扰项也必须真实可用） → ⑤ 写 instruction.md（只列清单，不暗示）
→ ⑥ 产出 golden → ⑦ 设计 rubric → ⑧ 交付自检（delivery）
```

#### ①–② 选定子场景、设计技能集合

**干扰技能的设计原则**：

| 原则 | 说明 |
|---|---|
| 真实可用 | 干扰技能本身语法正确、SOP 完整、能真的跑——不能是坏掉的摆设 |
| 方向相近但规则不同 | 例如任务需要"内部审批流程"，干扰技能是"外部发布流程"：领域相邻、规则不适用 |
| 不含必需规则 | 干扰技能中**不得**包含能解决本题的特有阈值/映射/处置规则 |
| 数量适度 | 1 个必需 + 1~3 个干扰为宜；过多会退化为噪声测试 |

**必需技能**：包含本题的**特有信息或行为规则**（阈值/映射/优先级/冲突处置/SOP）。

#### ③ 构造任务与源文件

- 任务难度不必靠规则堆叠；本型的难度来自**判别**而非执行。
- D2 场景：任务完全可由通用能力（读文件、写文档、算数）完成，任一技能都会引入**多余步骤或错误口径**。
- D3 场景：两个技能的 SKILL.md 都读完才能区分；只在 description 层面无法判断。

#### ④ 写 SKILL.md

每个技能都要有完整的 frontmatter（`name` / `description` / `compatibility`）与 SOP 正文。
**干扰技能的 `description` 要写得"看起来适用"**（提高判别难度），但正文中不含本题所需规则。
写法细节 → `../delivery/08-skill-packaging.md`。

#### ⑤ 写 instruction.md

- 按 `../delivery/08-skill-packaging.md` §3 列出**全部**可用技能的名称、适用描述、`SKILL.md` 绝对路径、脚本基准目录。
- **绝对不得**暗示：哪个技能必需、哪个是干扰项、本题是否需要技能。
- **不得**出现"请使用 A 技能完成"这类点名单一技能的要求（那是 Skill Dependency 题的写法）。

#### ⑥ 产出 golden

- D1/D3：`solve.sh` 复制按正确技能产出的终态产物。
- D2：`solve.sh` 复制**不使用任何技能**产出的终态产物。
- golden 须满足全部正分项、不命中任何 negate 条目、主分 **> 0.85**。

#### ⑦ 设计 rubric

**只对终态产物判分**——不判"是否读了 SKILL.md""调用了哪个脚本"。

| 判分点 | 说明 |
|---|---|
| 选中正确技能的效果 | 终态产物体现该技能特有规则的应用（数值/分类/字段符合该技能口径） |
| 未误用干扰技能 | 终态产物**不含**干扰技能的规则痕迹（如错误的口径、多余的状态产物） |
| D2：未做多余动作 | 终态产物正确且**不含任何技能特有痕迹** |
| 负向：误用干扰技能 | 产物体现干扰技能口径 → 扣分 |
| 负向：D2 场景中不必要地使用技能 | 引入了错误口径或多余结构 → 扣分 |

详细设计与示例 → `本文`。

#### ⑧ 交付自检

跑 `../delivery/` G1–G6 与 17 项自检，外加技能包 9 项自检（08 号文档 §6）。

### metadata 关键字段

```toml
category = "skill-discovery"
skill_set = ["<必需技能>", "<干扰技能1>", "<干扰技能2>"]
expected_skill_dependencies = ["<必需技能>"]        # 必须【严格小于】skill_set
tool_set = ["filesystem", "shell", "python"]
expected_tool_dependencies = ["filesystem", "shell"]
task_complexity = "C2"
weakness_tag = ["W09-Skill形式化调用"]
```

> **D2 场景**：`expected_skill_dependencies = []`（仍满足"真子集"约束）。

### 反模式（禁止）

1. `expected_skill_dependencies` **等于** `skill_set`（那就不是发现题，而是依赖题）。
2. 任务书暗示必需技能或干扰项身份；出现"请使用 X 技能"式点名。
3. 干扰技能是**坏掉的 / 无法运行的**摆设（不具备真实可用性）。
4. 干扰技能中混入了能解决本题的规则（导致多解）。
5. 只靠 `description` 就能判断（未要求细读 SKILL.md 正文）。
6. 对"读了哪个文件""调用了哪个脚本"做过程评分。
7. 技能目录名 / `skill_set` 条目 / `SKILL.md` 的 `name` 不一致。
8. D2 场景中所有技能其实都必需（正解不成立）。
9. 违反 `../delivery/` 的任一硬约束。

## Skill Discovery 子场景设计与干扰技能构造

### 1. 三个子场景的设计要点

#### D1 · 正确选中

| 项 | 设计 |
|---|---|
| 技能集合 | 1 个必需 + 1~3 个干扰 |
| 必需技能 | 含本题特有规则（阈值/映射/优先级/SOP/冲突处置），规则**不能从常识推出** |
| 干扰技能 | 同领域相邻方向，**不含**本题所需规则 |
| 任务书 | 只列清单；不提示是否需要技能 |
| golden | 按必需技能产出，终态产物体现其特有规则 |
| 判分 | ① 产物体现必需技能口径；② 产物**不含**干扰技能痕迹 |

#### D2 · 正确不用（价值最高）

| 项 | 设计 |
|---|---|
| 技能集合 | ≥2 个技能，**都不必需** |
| 任务 | 完全可由通用能力完成（读文件 → 计算 → 写文档），**无任何特有规则需求** |
| 干扰点 | 每个技能都会引入**多余步骤**或**错误口径**（如强制走一套不适用本场景的审批状态） |
| 正解 | **不使用任何技能**，用通用能力直接完成 |
| `expected_skill_dependencies` | `[]` |
| 判分 | ① 终态产物正确；② **不含任何技能特有痕迹**（无多余状态文件、无套用他人口径的字段） |

> **为什么要做 D2**：防止模型形成"环境里装了技能就必须用"的偏差。
> 该偏差在真实企业中会造成无效流程与错误口径，是**真实业务价值**而非人造考点。

#### D3 · 辨别相近技能

| 项 | 设计 |
|---|---|
| 技能集合 | 两个 `description` 高度相近的技能，只有 1 个含本题所需规则 |
| 区分点 | 必须**读 SKILL.md 正文**才能区分（description 层面无法判断） |
| 典型差异 | 口径不同（行业惯例 vs 内部口径）、流程不同（外部发布 vs 内部审批）、适用范围不同（境内 vs 跨境） |
| 判分 | 终态产物匹配正确技能的口径 |

### 2. 干扰技能构造法

#### 2.1 三种"看起来适用"的干扰

| 干扰类型 | 做法 | 示例 |
|---|---|---|
| **领域相邻** | 同一业务域的不同环节 | 任务要"内部审批"，干扰是"对外发布流程" |
| **口径竞争** | 同一能力的不同口径 | 任务要"内部风险口径（75 天）"，干扰是"行业通行口径（90 天）" |
| **范围错位** | 适用范围不同 | 任务要"境内合规审查"，干扰是"跨境数据合规" |

#### 2.2 干扰技能质量要求

| 要求 | 说明 |
|---|---|
| 真实可用 | frontmatter 齐备、SOP 完整、脚本能真跑——**不能是坏掉的摆设** |
| 描述有吸引力 | `description` 要写得"看起来适用"，提高判别难度 |
| 不含必需规则 | 正文中**绝不包含**能解决本题的特有阈值/映射/优先级/处置规则 |
| 有明确适用边界 | 正文中应写出自己的适用范围（供细读者判断不适用） |

#### 2.3 常见错误

| ❌ | ✅ |
|---|---|
| 干扰技能写得明显无关（一眼排除） | 干扰技能与任务**方向相近**，需要读完 SKILL.md 才能排除 |
| 干扰技能缺 frontmatter / 脚本报错 | 干扰技能**真实可运行** |
| 干扰技能里也含正确答案所需的规则 | 干扰技能**只含相邻但不同的规则** |

### 3. 难度调节旋钮

| 旋钮 | 提高难度 | 降低难度 |
|---|---|---|
| 干扰技能数量 | 增加到 3 个 | 减到 1 个 |
| 技能描述相似度 | 高度相近（D3） | 差异明显 |
| 必需规则隐蔽度 | 藏在 references/ 子文件里（需按 SKILL.md 指引读取） | 直接写在 SKILL.md 正文 |
| 任务复杂度 C 级 | 提高到 C3–C4 | 保持 C1–C2 |
| 是否含 D2 反例 | 环境里同时装"多余但诱人"的技能 | — |

> **不要用"降低信息可读性"制造难度**（如把 SKILL.md 写得很绕），那是噪声不是难度。

### 4. 任务书技能入口写法（强制）

```markdown
## 可用技能

本环境已安装以下技能，`SKILL.md` 的容器内绝对路径如下；脚本相对路径以该技能目录为基准：

| 技能 | 适用描述 | SKILL.md 路径 |
| --- | --- | --- |
| `internal-approval-flow` | 内部文件流转与审批状态推进 | `/skills/internal-approval-flow/SKILL.md` |
| `external-publish-flow` | 对外发布件的定稿与发布 | `/skills/external-publish-flow/SKILL.md` |
| `risk-grading-internal` | 按内部口径对账龄做风险分级 | `/skills/risk-grading-internal/SKILL.md` |
```

**禁止**（本型的红线）：

```markdown
<!-- ❌ 点名单一技能 -->
请使用 internal-approval-flow 技能完成本任务。

<!-- ❌ 暗示必要性 -->
本任务必须通过技能来完成。

<!-- ❌ 暗示干扰项 -->
external-publish-flow 与本任务无关，无需使用。
```

### 5. 与 Skill Dependency 型的边界

| 维度 | Skill Discovery | Skill Dependency |
|---|---|---|
| 环境 | 多个技能（含干扰） | 通常 1 个核心技能（可带干扰） |
| 任务书 | **完全不确定**技能是否需要 | **显式强调必须走该 skill** |
| 难度来源 | **判别**（选哪个 / 要不要用） | **执行**（按特有规则做对） |
| `expected_skill_dependencies` | 严格小于 `skill_set` | 非空子集（含必需技能） |
| 正解 | 可能是"不使用任何技能"（D2） | 必须使用该技能 |

> 同一批次内**两类可共存**，但单题必须归入其中一类，`category` 字段如实填写。

## Skill Discovery rubric 设计与 golden 要求

### 1. golden 要求

| 子场景 | golden 内容 |
|---|---|
| D1 / D3 | 按**正确技能**的规则产出的终态产物；`solve.sh` 直接复制 |
| D2 | **不使用任何技能**、通用能力产出的正确终态产物 |

共同要求：
- 满足全部正分项、**不命中任何 negate 条目**；
- 主分 **> 0.85**；
- 与 `instruction.md` / `[[metadata.deliverables]]` 的文件名、格式、数量一致；
- 同步复制到 `tests/__golden_output/`。

### 2. rubric 判定原则

**只判终态产物**。以下事项**不得**作为判分依据：

| ❌ 不可判 | 原因 |
|---|---|
| 是否读取了 SKILL.md | 过程不可观测（judge 看不到 agent 轨迹） |
| 调用了哪个技能脚本 | 同上 |
| 思考过程是否提到该技能 | 同上，且属主观 |

**唯一可判**：终态产物是否体现正确技能的口径 / 是否不含错误技能的口径。

### 3. 判分抓手矩阵

| 子场景 | 正向判分点 | 负向判分点 |
|---|---|---|
| D1 | 产物体现必需技能的特有规则（阈值/映射/字段/结构） | 产物体现干扰技能口径（−7）；产物无任何技能痕迹（−7） |
| D2 | 产物正确且**不含任何技能特有痕迹**（无多余状态文件、无他人口径字段） | 不必要地引入技能特有结构/口径（−7） |
| D3 | 产物匹配**正确**技能的口径（而非相近技能） | 产物匹配**相近错误**技能的口径（−7） |

### 4. 示例条目

#### D1 · 正向：体现必需技能口径

```toml
[[criterion]]
id = "R04"
name = "R04"
description = "风险分级表全部采用 `risk-grading-internal` 技能定义的内部口径（逾期 ≤75 天为正常、76–120 天为关注、>120 天为预警），未采用行业通行的 90/180 天口径。 Deliverables to inspect: `output/FIN-SKD-004_风险分级表.xlsx`."
type = "binary"
weight = 10.0
```

#### D1 · 负向：误用干扰技能

```toml
[[criterion]]
id = "R11"
name = "R11"
description = "风险分级表采用了行业通行的 90/180 天口径（对应 `risk-grading-industry` 技能），而非本环境内部口径。仅当发现明确证据证明该情形存在时判定成立。 Deliverables to inspect: `output/FIN-SKD-004_风险分级表.xlsx`."
type = "binary"
negate = true
weight = 7.0
```

#### D2 · 正向：未引入多余技能痕迹

```toml
[[criterion]]
id = "R05"
name = "R05"
description = "交付物仅包含 `instruction.md` 要求的产物，未生成审批记录、状态文件、签核单等本任务未要求的中间产物，且未套用任一已安装技能的专有口径。 Deliverables to inspect: `output/FIN-SKD-005_汇总表.xlsx`."
type = "binary"
weight = 7.0
```

#### D2 · 负向：不必要地使用技能

```toml
[[criterion]]
id = "R12"
name = "R12"
description = "在任务书未要求的情况下走了技能定义的额外流程（如生成审批链文件、按某项特有口径重算），导致交付物结构或数值偏离正解。 评分为 1–5 整数，按违规程度判定（negate 条目，Reward Kit 归一化后自动翻转计分）：5=交付物结构性偏离，核心数值因套用技能口径而错误；4=核心数值正确但引入多项非要求产物；3=引入 1–2 项非要求产物；2=仅在说明中提及技能但未影响产物；1=完全未引入任何技能痕迹。 Deliverables to inspect: `output/FIN-SKD-005_汇总表.xlsx`, `output/FIN-SKD-005_说明.docx`."
type = "likert"
points = 5
negate = true
weight = 7.0
```

#### D3 · 正向：匹配正确技能口径

```toml
[[criterion]]
id = "R06"
name = "R06"
description = "对账处理采用 `internal-approval-flow` 定义的四态流转与审批单号规则（审批单号形如 AP-YYYY-####），而非 `external-publish-flow` 的发布序号规则。 Deliverables to inspect: `output/FIN-SKD-006_流转记录.xlsx`."
type = "binary"
weight = 10.0
```

### 5. 建议条目结构（8–13 条）

| 类别 | 条数 | weight |
|---|---|---|
| 指令遵循（文件名/路径/格式） | 2–3 | 3 |
| **技能选择正确性**（核心） | 3–4 | 7 或 10 |
| 结论/数值正确 | 2 | 7 或 10 |
| 结构与组织 | 1 | 3 |
| 负向：误用干扰技能 / 不必要使用技能 | 2 | 7 |

> 必须满足 `Critically Important（+10）≥2` 与"内容质量维度正分 ≥30%"。

### 6. 定向弱点对照

| weakness | 本题型中的体现 | 对应判分 |
|---|---|---|
| **W9** Skill 被形式化调用但没有真正改变关键判断 | 用对了技能却未按其规则修正结论 | 负向 likert"未按技能规则修正" |
| **W13** 规划与策略调整失当 | D2 场景中无意义地引入技能流程，耗费步骤且偏离正解 | 负向"不必要地使用技能" |
| **W11** 无据自造数据与口径 | 不用内部口径而套用行业惯例 | 负向"套用行业口径" |

### 7. 常见陷阱

| # | 陷阱 | 修正 |
|---|---|---|
| 1 | `expected_skill_dependencies == skill_set` | 加入至少 1 个干扰技能，使前述为**严格真子集** |
| 2 | 任务书出现"请使用 X 技能" | 删除；本型不得点名 |
