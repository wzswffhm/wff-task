# C1–C5 复杂度分级表与题量配比

## C1–C5 复杂度分级表与题量配比

### 1. 分级表（原表按指标为行、等级为列）

| 指标 | C1 | C2 | C3 | C4 | C5 |
|---|---|---|---|---|---|
| **文件数** | 2 | 5 | 10 | 25 | 50+ |
| **Requirement 数 / 约束** | 3 | 6 | 10 | 15 | 20 |
| **输出产物数** | 1-2 | 2-3 | 3-4 | 4-6 | 4-8 |
| **Evidence Chain** | 1-hop | 2-hop | 3-hop | 4-hop | 5-hop |
| **执行步数 / 子任务数** | 1–3 / 1 | 4–7 / 2–3 | 8–15 / 4–6 | 16–30 / 7–10 | 30+ / 10+ |
| **工具种类数** | 1 | 2 | 3 | 4 | 5+ |
| **领域专业深度（参考）** | 通用常识 | 基础专业 | 中级业务 | 高级专业 | 专家级 |
| **题量** | **120** | **250** | **350** | **180** | **100** |
| **占比** | **12%** | **25%** | **35%** | **18%** | **10%** |

> **注**：C5 的输出产物数为 4-8；如果是一个大型项目（如做整个并购尽调），产出物可以为 1 份。

### 2. 指标定义（计量方式）

| 维度 | 含义 | 计量方式 |
|---|---|---|
| **文件数** | 模型可读取/处理的输入文件数量 | **不含重复文件、临时文件** |
| **Requirement 数** | 显式或隐式需满足的条件/约束条数 | 含功能、格式、引用、质量约束 |
| **输出产物数** | 最终需交付的文件/片段/结果数量 | 如代码文件、表格、报告段落、邮件等 |
| **Evidence chain 深度** | 完成答案所需的**最长跨文件推理步数** | 1-hop = 单文件直接可得 |
| **执行步数** | 模型需调用的原子操作/工具调用次数 | 工具调用次数 |
| **工具种类数** | 不同类型的能力/工具（文本阅读、搜索、代码执行、计算、写作、绘图、表格处理等） | 工具种类数量；**同一类工具的多次调用只算 1 种** |

### 3. 各等级画像与典型真实生产力场景

| 等级 | 画像 | 典型真实生产力场景 |
|---|---|---|
| **C1** | 单文件、单输出、单步完成，无需专业知识 | 从一份 Excel 中统计销售额并生成一句话结论 |
| **C2** | 多文件简单对照，2 种工具，基础专业门槛 | 对比两份报价单，输出差异表 + 推荐方案 |
| **C3** | 标准项目规模，中等推理链，3 种能力组合 | 根据销售数据、客户反馈、产品资料生成分析报告 + 图表 + 建议清单 |
| **C4** | 复杂项目级任务，长依赖链，需要高级领域知识 | 基于季度财报、行业研报、内部纪要撰写投资 memo + 财务模型 + 风险清单 |
| **C5** | 大型项目/知识库，多产物完整交付，专家级判断 | 完成并购项目的 CIM 分析、估值模型、尽调问题清单 |

### 4. 判定方法（不许凭感觉）

```
1) 数文件：实际可读取的输入文件数（排除重复与临时文件）
2) 数约束：instruction 中的显式要求 + 可合理推导的隐含要求
3) 数产物：[[metadata.deliverables]] 的条目数（+ 报告内的独立片段）
4) 量证据链：从"最终结论"回溯，数最长的一条跨文件推理步数
5) 数步数：完成任务所需的最少工具调用次数
6) 数工具种类：去重后的能力类型数
```

**定级规则**：

- 六项指标**大多落在同一档** → 取该档；
- 指标跨档 → **取众数**；若均分分散，取**偏保守**（较低）的档，并在交付说明中记录判定依据；
- **不得**从 `difficulty`（A1/A2/A3）直接换算（两者口径不同：difficulty 看模型正确率，complexity 看任务结构）。

### 5. 与 difficulty 的关系

| 维度 | 判定依据 | 取值 |
|---|---|---|
| `difficulty` | **三模型平均正确率** | A1 ∈[0.6,0.7) / A2 ∈[0.5,0.6) / A3 <0.5 |
| `task_complexity` | **任务结构硬指标** | C1–C5 |

> 二者**独立填写**。一个 C2 任务完全可能是 A3（结构简单但专业门槛高，模型仍做不对）；
> 一个 C5 任务也可能是 A1（结构复杂但步骤机械，模型能完成）。

### 6. 题量配比与批次规划

| 等级 | 题量 | 占比 | 累计 |
|---|---|---|---|
| C1 | 120 | 12% | 120 |
| C2 | 250 | 25% | 370 |
| C3 | 350 | 35% | 720 |
| C4 | 180 | 18% | 900 |
| C5 | 100 | 10% | 1000 |
| **合计** | **1000** | 100% | — |

> 该配比针对 **weakness 数据 1000 条**。专项数据（skill/workflow，1000 条）的 `task_complexity` 按题目实际结构填写，无强制配比，但**须与所在 skill 的构造强度匹配**（如 Subagent Workflow 通常 ≥C3）。

### 7. difficulty-control 维度（与本表联动）

> 观测：**Qwen 在要求项更多、交付物更多、跨应用更多的 hard query 上，思考和工具调用没有随难度增加，甚至有所下降**，
> 明显弱于其他模型；而 Opus 会相应增加执行与验收投入。

因此以下三项应作为**显式旋钮**（直接对应本表的三行）：

| 旋钮 | 对应指标 | C1 | C5 |
|---|---|---|---|
| 要求项数 | Requirement 数 | 3 | 20 |
| 交付物数 | 输出产物数 | 1–2 | 4–8 |
| 跨应用/工具数 | 工具种类数 | 1 | 5+ |

### 8. 批次覆盖统计脚本

```python
# weakness_coverage.py — 统计批次内 weakness 覆盖与 C 级配比
# 用法: python3 weakness_coverage.py <题包根目录>
import sys, pathlib, tomllib, collections

C_QUOTA = {"C1": 120, "C2": 250, "C3": 350, "C4": 180, "C5": 100}

def main(root):
    root = pathlib.Path(root)
    wk = collections.Counter()
    cx = collections.Counter()
    n = 0
    for toml in sorted(root.rglob("task.toml")):
        try:
            d = tomllib.loads(toml.read_text(encoding="utf-8"))
        except Exception as e:
            print(f"[WARN] 解析失败 {toml}: {e}")
            continue
        m = d.get("metadata", {})
        tags = m.get("weakness_tag") or []
        if not tags:
            print(f"[WARN] 缺 weakness_tag: {toml}")
        for t in tags:
            wk[t] += 1                      # 一条标多个，各计 1 次
        level = m.get("task_complexity")
        if level:
            cx[level] += 1
        n += 1
    print(f"题目数: {n}")
    print("\n-- weakness 覆盖（要求 50 ≤ n ≤ 250）--")
    for k in sorted(wk):
        v = wk[k]
        flag = "OK" if 50 <= v <= 250 else ("LOW" if v < 50 else "OVER")
        print(f"  {k:<28} {v:>4}  {flag}")
    missing = [f"W{i:02d}" for i in range(1, 15) if not any(t.startswith(f"W{i:02d}") for t in wk)]
    if missing:
        print(f"  [MISSING] 未覆盖: {missing}")
    print("\n-- C 级配比 --")
    for k in C_QUOTA:
        print(f"  {k}: 实际 {cx.get(k,0):>4} / 目标 {C_QUOTA[k]:>4}")
    return 0

if __name__ == "__main__":
    sys.exit(main(sys.argv[1]))
```

> 判读：`LOW` = 覆盖不足，需补题；`OVER` = 超过 250 上限，需在后续题中减少该 tag 或多标其他 tag。
