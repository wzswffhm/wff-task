**v4 重构依据（qwen 八类易失分模式）** —— 源自 149-fix8 / 150 / 151 / FIN-PE-001
四题共 10 个判分批次的逐判据对比（qwen/gpt/opus 同题同判据得分差 + 判官 reasoning 实证）：

1. **钦定推导等式逐字落地**（参考 FIN-PE-001 十余条三模型共失判据）；
2. **钦定口径不容自选**（期间/基准/阶段/网格钦定，自选更合理口径即 0，四题实证 qwen 全挂）；
3. **显式陈述**：派生指标与方法论理由必须写出，"算得出但没写"即 0；
4. **唯一结论选边**：依据铺足但结论必须唯一，"依据对结论错=0"（151-R21 三模型共失）；
5. **分列不合并**：合计不替代分项、同类项禁归并（qwen 有总结式表达倾向，实证 151-R15）；
6. **全矩阵 × 小容差**：每格必有单点值，缺一格整条 0；
7. **精确计数**：总数/分项数差 1 即 0（151-R08 三模型共失）；
8. **结构化增量交付**：具名中间表而非叙述（151-R30 qwen 0.5 < gpt 1.0）。

**反向规避 qwen 强项**（避免只拉大 qwen 领先、压不动它）：不以纯数值容差、
纯穷举计数、字数格式约束、N 类负向约束作为主要压分点——这四类在四题实证中 qwen 全部满分。

**公平性边界**：判据要求的任何呈现方式（网格点、分行分列、算式呈现、清点口径、
理由清单）均已同步写入 `instruction.md`；判据中的**答案锚点**（数值与算式）
只存在于 `tests/rubrics.toml`（判官侧），**不进入题面**，题面亦无引导性注释。

#### 3.2.3 判分噪声与档位余量披露（如实说明，未重跑）

**① N01 单条判官输出自相矛盾（qwen）**
`qwen3.8-max-0902` 的 `N01`（负分判据）：判官 `reasoning` 结尾明确写
「…all errors have been clearly corrected …, **N01 does not apply**; the deliverables do NOT
carry over legacy errors」，但最终 `raw=yes` / `value=0`（negate 语义下 = 触发违规、扣 7 分）。

`gpt-5.6-sol` 与 `claude-opus-4-8` 上均为 `value=1`（正常）。

- 按记录值计入：qwen = **0.697368**
- 若按评语语义修正：qwen = 0.697368 + 7/228 = **0.728070**（差 +3.07pp）
- **处置：不重判**。依据 ①甲方质检「判分自洽」仅核「逐条复算与 `reward.json` 一致」
  与「`description`/`weight` 与现行判据逐条一致」两项，本包均通过（复算差 0、40 条零漂移）；
  ②`pitfall-cases` 案例 7 明示「判官是 LLM，重跑一次就可能越档」，重跑有引入新噪声与越档的
  双重风险；③误差方向使均值偏低、离 <0.70 门禁更远。此处如实披露以备人检。

## 7. 跑分环境要求与已知坑（Windows/WSL 侧）

| 项 | 说明 |
|---|---|
| Docker 引擎 | Windows 侧 harbor 需 Docker Desktop 处于 **Linux 容器模式**（`DockerCli.exe -SwitchLinuxEngine`）；`docker info` 的 `OSType` 须为 `linux`，否则报 “Task declares .os = 'linux' but the Docker daemon is running in 'windows' container mode” |
