## 2. 环境变量表（`[verifier.env]`，共 8 项）

> `JUDGE_*` 只注入评分侧 `[verifier.env]`，**禁止写入 `[environment].env`**（避免泄漏给被测 Agent）。本题 `[environment].env` 为 **0 项**，符合最小必要原则。

| Key | 必选 | 默认值 | 类型 / 取值 | 说明与联动 |
|---|---|---|---|---|
| `JUDGE_API_KEY` | **是** | —（运行环境注入） | string | judge 网关 key。`test.sh` 派生为 `ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_API_KEY` / `OPENAI_API_KEY`。缺失或失效 → 判官全失败，`verifier_error = 1` |
| `JUDGE_BASE_URL` | **是** | —（运行环境注入） | string(URL) | judge 网关地址，可带 `/v1` 后缀（`test.sh` 剥除后派生 `ANTHROPIC_BASE_URL` 等） |
| `JUDGE_MODEL` | 否 | `qwen3.7-plus` | string（LiteLLM 模型串） | 裁判模型。经 `REWARDKIT_MODEL` 运行时覆盖 `rubrics.toml` 的 `model`；`JUDGE_API_PROTOCOL=openai` 时同时决定降级 LLM judge 的模型串 |
| `JUDGE_PROVIDER` | 否 | `anthropic` | 枚举 `anthropic` / `openai` | 信息性声明，不改变行为 |
| `JUDGE_API_PROTOCOL` | 否 | `anthropic` | 枚举 `anthropic` / `openai` | `anthropic` = claude-code agent judge（**默认链路**）；`openai` = 降级为 openai 协议 LLM judge（`test.sh` 设 `REWARDKIT_JUDGE=openai/<JUDGE_MODEL>` 覆盖 judge 类型，`prompt.md` 的工具提示随之不生效） |
| `EVAL_API_KEY` | 否 | 空 | string | 旧环境兼容兜底；`JUDGE*` 已注入时被忽略（`test.sh` 里 `JUDGE*` 优先） |
| `EVAL_API_BASE` | 否 | 空 | string(URL) | 同上，旧环境兼容兜底 |
| `LITELLM_DROP_PARAMS` | 否 | `true` | bool 字符串 | 网关兼容开关，照抄 |

## 7. 跑分环境要求与已知坑（Windows/WSL 侧）

| 项 | 说明 |
|---|---|
| Docker 引擎 | Windows 侧 harbor 需 Docker Desktop 处于 **Linux 容器模式**（`DockerCli.exe -SwitchLinuxEngine`）；`docker info` 的 `OSType` 须为 `linux`，否则报 “Task declares .os = 'linux' but the Docker daemon is running in 'windows' container mode” |
| 推荐运行位置 | **WSL Ubuntu（root）**：基础镜像 `python:3.12-slim` 与构建层已在本地缓存，可离线命中；Windows 侧 Docker Desktop 直连 `registry-1.docker.io` 会超时 |
| 长跑保活 | `systemd-run --unit=<name> --collect --setenv=HOME=/home/wff --setenv=LANG=C bash <脚本>`；必须以 **root** 运行（`--uid=wff` 会因 drvfs 属主秒退） |
| WSL 防空闲关机 | 注册两个 Windows 计划任务 keeper（`wsl-keeper-ubuntu`、`wsl-keeper-ubuntu-b`），各持有 `wsl.exe -d Ubuntu -u root -e sleep infinity`，校验应有 **2 条** `sleep infinity` 且 `etime` 持续增长 |
| 判官/候选模型并发 | judge 逐条串行 `claude -p`；同一 `JUDGE_API_KEY` 上叠加候选模型 agent 流量会互相拖死 → 候选模型 agent 应使用**独立 key** |
| 故障分识别 | `verifier_error = 1` 是「评分不可信」，**不是 0 分**，不得计入难度统计；须按 `reward_exit_message.json` 的 `exit_code` 分类后重跑 |
