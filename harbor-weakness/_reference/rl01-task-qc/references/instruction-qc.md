# 题面质检（instruction.md）

题面是 Agent 唯一可见的任务描述。质检要回答三个问题：**说清了没有**、**做得对不对**、**有没有被拿来做 hack**。

## 一·前、甲方人检口径：instruction 只判两个维度

甲方人检对题面只给两个结论（《weakness&skill-人工质检内容》），格式类问题不在人检范围：

| 维度 | 判什么 | 合格形态（人检报告原话） | 不合格形态 |
|---|---|---|---|
| **场景真实** | 角色、交付物、使用方在目标行业里是否真实存在 | 「券商投行部 ECM 分析师为定增项目产出内核财务分析与估值报告…交付物与使用方（内核会审核）明确」 | 角色与交付物对不上、使用方不明、行业里没有这种工作流 |
| **有业务价值** | 完成该任务是否直接产出有用成果（不是空转），且**材料设计具备真实难度** | 「直接影响定增项目能否通过内核会，估值结论是否经得起合规审查…属合规与决策价值，非空转任务」 | 交付物只是格式演练；材料平铺直叙没有对抗性 |

「材料设计具备真实难度」是被甲方明确写进合格理由的，值得单独核：

- 真实案例一（FIN1-skill-DEP-003）：题面把完整 API 契约（6 种 kind、3 种 source、Decimal 语义、
  幂等/冲突/授权/生命周期/快照恢复）以**可观察行为**写出，与 Skill 的业务语义形成互补——
  「Skill 管业务语义，instruction 管程序接口，两者缺一不可，构成有效的 skill-dependency 考查」。
- 真实案例二（FIN-A2-SKL-DEP-001）：辅助 skill 故意给出与权威 skill 矛盾的建议
  （用备忘汇率、中位数、直接用 cache），但自身声明「Cosmetic only」，题面三次强调
  「冲突时以技能规定为准」——构成抗干扰 / 权威溯源考查。

**结论写法**：题面质检结论要落到「场景真实 ✅/✗」与「有业务价值 ✅/✗」两条上，
结构类问题（部分数不符、编辑残留）另列，不要混在这两条里。

## 一、结构门禁（机械可查，`check_task_qc.py` 覆盖前四项）

| # | 检查项 | 合格标准 | 不合格 → 等级 |
|---|---|---|---|
| 1 | 段落齐备 | 任务说明 / 参考文件 / 产出要求 / 硬约束 / 完成标准 各自独立成段 | 缺「任务说明」「产出要求」「硬约束」→ 重要 |
| 2 | 硬约束独立成段 | 禁止项、文件名要求、必须使用的 skill/工具 单独成段写出 | 藏在括号里、混在任务说明中间 → 重要 |
| 3 | 产出要求具体 | 逐条写明文件名、格式、必须包含的模块、数量、精度、单位 | 只写「产出一份报告」不写文件名/格式 → 阻断 |
| 4 | 完成标准不泄露 | 只说验收看什么，不出现判据编号、weight、归一化、档位阈值 | 出现 `R07`、`+10`、`判据`、`weight` → 重要 |
| 5 | 无矛盾约束 | 两条要求不能互相排斥（如「只改正文」与「重排整页」） | 互相矛盾 → 阻断 |
| 6 | 部分数声明自洽 | 题面写「必须包含以下 N 个部分、顺序一致」时，实际列出的部分数与 N 相等，且没有编外段 | 声明数与条目数不符 / 同一「第X部分」标题重复出现 → **重要**（`check_task_qc.py` Q-T10） |
| 7 | 无编辑残留 | 产出要求段无行首缩进的残句、无粘贴重复的标题行 | 有 → 提示（`check_task_qc.py` Q-T11） |

第 6 项为什么是重要而不是提示：**题面一有歧义，生产方就会在判据里写「不影响…判定」来兜底**，
而人检看的正好是判据。真实退回形态：题面声明「四个部分」却列出五个组成部分，判据 R12 写成
「题面要求插在逐项分析之后…的段落是本任务明确要求的组成部分，不影响上述四部分的齐全性与
顺序判定」。正确动作是**回题面把部分数与条目数对齐**，不是加一句判据免责。

## 二、交付物一致性（六处逐字对齐，最容易被退回的一项）

同一个文件名必须在这六处**逐字节一致**：

1. `instruction.md` 的产出要求段
2. `task.toml` 的 `artifacts = [...]`（`/app/output/<文件名>`）
3. `task.toml` 的 `[[metadata.deliverables]].path`
4. `solution/golden_output/` 的实际文件名
5. `tests/__golden_output/` 的实际文件名（应与 4 逐字节一致）
6. `tests/rubrics.toml` 各条 criterion 的 ``Deliverables to inspect: `output/<文件名>` ``

任何一处不一致：Agent 会写错文件名、判官找不到交付物或者 oracle 跑不出分。
扫描命令：`python scripts/check_task_qc.py <task-dir>`（第 4 项检查）。

另注：每条 criterion 只列**该条涉及的**交付物，不要每条都写全；但全部 criterion 的并集必须覆盖所有交付物。

## 三、可解性与真实性（人工判断，脚本查不了）

| 检查项 | 怎么核 | 不合格形态 |
|---|---|---|
| 信息是否够 | 逐条对照题面要求与 `environment/input_files/`：每个要求能不能只靠材料推出来 | 要求写「引用 XX 条款」，材料里根本没有该文件 |
| 是否要求凭空猜测 | 看题面有没有让模型写法规条款、政策口径、职责分工、统计数据，而材料里没有出处 | 「请按规定测算 XX 限额」但材料未给规定原文 → 阻断（判据不可验证） |
| 材料是否真实 | 抽查参考文件的来源、时间、主体是否自洽；有无明显编造痕迹 | 引用不存在的公告编号、把 A 公司数据挂到 B 公司名下 |
| 是否可验证 | 每个完成标准能不能由交付物本身或材料核对 | 「分析要有深度」这类无法核验的表述进了得分点 |
| 输入文件是否被保护 | 题面是否声明不得修改输入文件；`operational safety` 相关判据是否有对应要求 | 题面允许改输入，判据又扣「误改源文件」 |

**没有出处的数字、条款、口径，一律按阻断报**：它同时破坏题面可解性与判据合法性。

## 四、hack 形态（发现即阻断）

- **题面歧义刷低分**：换一种合理解读就能得低分，而「正确解读」在题面里找不到依据。
- **不可验证的要求**：要求的产物无法从交付物中核对，判官只能凭感觉给分。
- **互相矛盾的约束**：A 要求与 B 要求不能同时满足，模型必然踩其中一条扣分项。
- **判据与题面错位**：判据考的点题面没写，或题面写了但判据完全没覆盖（Requirement Coverage 缺口）。
- **难度靠惩罚堆出来**：负分项占正分池比例过高、正分项几乎全是格式项。看 `validate_rubrics.py`
  输出的「内容质量正分占比」与负分项数量。

以上都要写进报告的「hack / 异常」小节，作为人工质检结论，不能只当作普通文档问题。

## 五、专项数据（skill / tool / workflow）附加检查

| 检查项 | 合格标准 | 等级 |
|---|---|---|
| 工具集合声明 | 题面给出当前 Environment 下可用的工具集合 / MCP | 缺 → 阻断 |
| Skill 必用声明 | 题面显式写「必须通过 `<skill-name>` 完成，不得用其他方式」 | 缺 → 阻断 |
| Skill 不可省略 | `environment/skills/<name>/` 里的 SKILL.md 承载特有规则：特殊业务规则、环境特化 SOP、特殊阈值与内部映射、业务优先级、fallback 顺序 | 只是背景文档 → 阻断（整题不成立） |
| skill_set 对应 | `task.toml` 的 `skill_set` 与 `environment/skills/` 目录逐一对应 | 不对应 → 阻断 |
| Discovery 场景 | `expected_skill_dependencies` **严格小于** `skill_set`（存在故意的无关 skill） | 相等 → 阻断 |

「Skill 不可省略」的判定动作：**把 skill 抽掉，任务是否必然做不对**。若抽掉后仍能凭常识做对，
该题不属于专项数据，打回重出。

## 六、weakness 数据附加检查

| 检查项 | 合格标准 | 等级 |
|---|---|---|
| trigger 已埋 | `weakness_tag` 标了哪个 weakness，题面/`environment/` 里就必须有对应的诱发条件 | 标了没埋 → 阻断 |
| 必然失败 | 不按预期方式做时，模型必然进入错误分支或状态必然失败；**不是**「少拿几分」 | 只靠题面歧义 → 阻断 |
| 可复现 | 埋点有明确触发条件与证据，能稳定复现 | 随机或依赖模型性格 → 重要 |
| 编号写法 | 用两位编号（`W01`…`W14`），取自算法侧正式词表 | 照抄规范正文的占位示例 `W07-流程跳步` → 阻断 |
| C 档自洽 | `task_complexity` 与文件数/产物数一致（`check_complexity.py`） | 不一致 → 阻断（改题补材料，不许改标注） |

## 七、高频退回实例（照这些形态查）

- 批次目录名用了题目编号，而不是 `供应商+领域+一级分类+时间`（返修加 `_fix<N>`）。
- 题面把「必须使用某 skill」写成建议语气，判官按「未使用 skill」扣分时无处说理。
- 题面写了三个交付物，`artifacts` 只列了一个，另一处又写成别的目录。
- 题面在完成标准里把评分档位抄了一遍，等于把判据交给 Agent。
- 题面要求「引用原文出处」，材料里却是扫描件或英文原文，导致要求无法核验。
- 题面写「必须包含以下四个部分、顺序一致」，实际列了五个组成部分（多一个
  「第二部分之后增加一段」），顺序判定必然分歧；判据里被迫写「不影响四部分的齐全性与顺序判定」兜底。
- 返修插入新段落后没清理原标题，同一「第三部分：材料冲突与口径说明」在题面里出现两次，
  后面还拖着一句行首缩进的残句（替换时留下的旧句）。
