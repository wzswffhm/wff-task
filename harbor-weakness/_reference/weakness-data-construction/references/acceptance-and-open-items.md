# 质检、验收与待确认项

## 提交物

- 题目文件（题包：instruction.md / task.toml / environment / tests / solution）。
- 模型产物与跑分轨迹：提交题目文件时同步提供，用于验证难度要求。
- 供应商须提供 Harbor 格式；高校可视能力酌情提供 Harbor 或非 Harbor 格式的原始文件。

## 自动/AI 质检门禁

参考答案得分与三模型平均分是硬门槛：

| 检查项 | 要求 |
|---|---|
| 参考答案 | 得分 > 0.85（规范另一处写 `score_final ≥ 0.85`） |
| 三模型平均分 | < 0.7（按难度档位：A1 < 0.7，A2 < 0.6，A3 < 0.5） |
| 死题检查 | 至少有一个模型有得分 |

难度判定链路：claude-code 框架下跑 gpt-5.6-sol、claude-opus-4-8、qwen3.8-max0902，各 1 次，产物由裁判模型 qwen3.7-plus 按打分项打分，满分归一化为 1.0 后取平均。

## 人工质检重点

题目真实性、参考答案合理性、打分项设计合理性、是否 hack 等异常作弊情况。一经发现，直接打回。

其中「是否 hack」要专门查**口径歧义**：若三个执行体在同一处口径判据上**一致失分**，且该组判据权重
接近或超过正分池的四分之一，先排查材料是否自相矛盾（同一事实在两份附件里给出互相排斥的表述），
再判定难度是否真实。跑 `scripts/check_cross_model_concentration.py <task-dir>` 可直接得到该比例。
实例：FIN-PE-001 有 15 条判据三模型全 0、占总正分 39.9%，全部挂在一处稀释口径的歧义上
（附件4 与附件3 表述互斥），属"难度由题面歧义撑着"，而非真实专业难度。

## 单题计分

见 [rubrics-spec.md](rubrics-spec.md#计分)：正分项加权得分 ÷（全部正分项权重之和 + 负分项命中扣减）；三模型平均分 =（score1+score2+score3）/3。

## 与其它规范的关系

本文档要求与"外发版-评测题包交付规范（rewardkit）"组合使用，后者是题包最终交付与判分落地的口径来源。两者冲突时以 rewardkit 交付规范为准，并把差异记入下面的待确认清单。
