# 变更记录

## v2.4（2026-10-02）

来源：FIN-PE-001 / FIN-IB-001 两题质检实战。本版修正一处**会把合规申报误判为不合格**的脚本缺陷，
并把"难度被口径歧义撑着"这一新发现固化成自查项与诊断脚本。

### 修正：C 档产物区间取值被压窄（真实造成误判）

`scripts/check_complexity.py` 里手写的 `ARTIFACT_ALLOWED` 与分级表原文不一致：

| 产物数 | 分级表字面区间（重叠） | 旧脚本取值 | 正确取值（并集） |
|---|---|---|---|
| 4 | C3 / C4 / C5 | 仅 C3、C4 | C3 / C4 / C5 |
| 5–6 | C4 / C5 | **仅 C4** | C4 / C5 |

后果：FIN-PE-001（6 个交付物、申报 C5）被旧脚本判 FAIL，质检报告据此写成"必须改为 C4"，
**属误判**——按分级表字面，6 个产物同时落在 C4（4–6）与 C5（4–8）区间内，申报 C5 不越界。
实测：把映射改成并集后，同一份题包由 FAIL 变 PASS；FIN-IB-001 与 FIN-WEAKNESS-UST-001 在新旧
取值下均 PASS，故该冲突只影响产物数落在 4–6 的题。

**修正内容**

1. 脚本改为从 `ARTIFACT_RANGE`（分级表区间原文）**推导**允许档位，不再手写映射；
2. 新增 `--self-test`：断言取值映射与分级表一致，改动脚本后必跑（防止再次漂移）；
3. 新增 `--table`：打印"产物数 → 支持档位""文件数 → 档位"两张映射表，便于与分级表逐行对照；
4. FAIL 输出增加提示：产物数 4–6 且申报 C5 时，若仍 FAIL 只可能来自文件数维度或脚本漂移，
   先跑 `--self-test` 再复核申报依据；
5. SKILL.md 硬约束补充判定口径：**产物区间重叠、落档取并集**；**申诉优先级＝分级表原文 > 门禁脚本**；
   **申报档高于文件数档是合法的**（多产物例外），不要为了迁就脚本去硬凑 25/50 个输入文件
   （补材料属改题、会作废已跑产物）。

### 新增自查：难度不能被"口径歧义"撑着

FIN-PE-001 的 51 条判据中有 15 条被三个模型**一致**判 0，权重合计 119/298＝**39.9%**，
全部挂在一处稀释口径上——而该口径在材料里自相矛盾（附件4 写"按 C 轮融资前已发行股份计算"、
附件3 只提"未考虑期权池"），两个读法分别推出 9.09% 与 10.80%，判据只认后者。即：
**这道题的难度实际由题面歧义撑着**。同类信号在 FIN-IB-001 也出现（4 条全 0、占 32.5%）。

这类题有两个后果：一是甲方人检可能按"靠题面歧义刷低分"直接打回；二是**锁死口径后模型很可能会做对**，
三模型均值被推高、难度档当场失效（同实例：锁口径后均值预计由 0.5431 升至约 0.94，A2 档不成立）。

因此：

- SKILL.md「两道易漏的自查」升级为**三道**，第 3 条给出排查步骤、四种处置路径与副作用预估方法
  （先按「该组权重 ÷ 正分池」估算分数变化，再决定是否同步补难度）；
- `references/acceptance-and-open-items.md`：人工质检重点补"口径歧义"专查项；
  待确认项表补第 11 条（脚本与分级表冲突，以分级表为准）与第 12 条（集中度阈值默认 25%）。

### 新增脚本

| 脚本 | 作用 |
|---|---|
| `scripts/check_cross_model_concentration.py` | 读 `tests/rubrics.toml` 与各执行体 `reward-details.json`，列出「三个执行体同时未满分」的判据、权重合计与占正分池比例；≥25% 时提示按口径歧义排查。只报警不判对错（`--strict` 可升级为 FAIL） |

### 本轮沉淀的经验

- 门禁脚本报 FAIL 不等于题包有错：先跑 `--self-test`，再回分级表逐列核对，冲突时以**规范原文**为准，
  并把脚本缺陷记进交付说明——把工具缺陷写成题包缺陷，会让供应商做无谓返修（本例差点让 6 个交付物的
  题去硬补 12 个输入附件，而那属于改题、要连带重跑三个模型）。
- 判据数值锚点密集（±0.01）时，必须先确认该口径在材料里**只有一种**推导路径；口径含糊 + 锚点严格
  ＝ 必然误伤，且会以"高难度"的假象掩盖。

## v2.3（2026-10-01）

来源：FIN-127/128/129 三轮迭代 + 甲方口径确认。本版把**跑分迭代顺序**与**判据来源自查**固化为标准流程。

### 新增：跑分迭代流程（SKILL.md「跑分迭代流程」节，固定顺序不得跳步）

1. 跑 oracle，主分须 **> 0.85** 且 `verifier_error = 0`；
2. oracle 达标才跑 **qwen3.8-max-0902**，须 **< 0.7**；
3. qwen 达标才跑 **claude-opus-4-8**；
4. **opus 评分高于 qwen 时**，继续跑 **gpt-5.6-sol**；
5. 三模型齐后算均值定档（均值 <0.7，A1 0.6–0.7 / A2 0.5–0.6 / A3 <0.5，至少一个模型非零）；
6. **任一步分值不达标，一律回到 rubrics 层修改**——优先改 rubrics，其次参考答案，最后才动题面。
   动 rubrics / 答案只需重跑判官；**动题面必须重跑模型**（agent 产物与题面一一对应）。

### 新增：判据来源自查（每次改完 rubrics 必做）

**不允许存在题面没要求、也无材料依据的判据（伪需求）。** 每次改完 rubrics 都要：
跑 `check_rubric_style.py --strict` + 新增的 `scripts/list_rubric_sources.py`，
逐条确认每条 Implicit 判据的要求来自 ①题面显式要求 ②参考文件明确要求 ③可合理推导。
数值锚点来自 `input_files/` 不算「题面没有」；要求比题面字面更细时，可在题面补一句概括性要求
（不动判据、可不重跑），或按 Implicit 保留并在交付文档说明。

### 新增脚本

| 脚本 | 作用 |
|---|---|
| `scripts/list_rubric_sources.py` | 列出题包全部 Implicit 判据，附「题面锚点是否命中」，供逐条核对判据来源是否成立 |

## v2.2（2026-09-30）

来源：RL0-1 金融题（FIN-127 / FIN-128 / FIN-129）实战。本版修正两处**会导致元数据整体错位**的缺陷。

### 修正（SKILL.md + references）

1. **14 种 weakness 正式词表已补齐**：此前 `references/taxonomy-and-quota.md` 与
   `acceptance-and-open-items.md` 都写"词表未随文档提供、标 TBD"，导致实际生产时照抄了规范正文里的
   **占位示例** `weakness_tag = ["W07-流程跳步", "W12-约束遵循"]`——而词表里 W7 是"长表格/多 Sheet 下
   的数据覆盖与抗干扰能力弱"、W12 是"跨源交叉核对缺失"，名称完全对不上。
   现已从《基于 weakness 和 skill 的数据构造方案（金融）.pdf》第 4–8 页抄录完整 W01–W14（编号+名称+
   典型行为）进 taxonomy-and-quota.md，并在 SKILL.md 硬约束里放了一份编号-名称清单，
   即使不读 references 也不会再标错。**注意通用版方案里确实没有词表，出题前要先确认拿到的是
   对应领域的版本。**
2. **C1–C5 档位必须逐项核对**：此前 `validate_task_package.py` 只查字段格式，不查
   `task_complexity` 与文件数/产物数是否自洽，导致出现"凭感觉标 C4，实际只有 14 个文件"的情况
   （C4 要求 25 个文件）。现新增硬约束：C 档必须按分级表数出来，不一致要改题（补材料或补交付物），
   **不许改标注**。

### 新增脚本

| 脚本 | 作用 |
|---|---|
| `scripts/check_complexity.py` | 自动数 `environment/input_files/` 与 `artifacts` 里的 `/app/output/` 条目，按分级表推算应落档位并与 `task_complexity` 比对，不一致 FAIL；同时提示 Requirement / evidence-hop / 工具种类数需人工核对 |

### 沉淀的经验（供后续批次复用）

- 对 qwen 加压**无效**的两条路：加"提取型/推导型"要求项（实测 qwen 0.9067→0.9465 反而升高）、
  只增加交付物数量与格式约束。
- 有效的两条路：① **题面从"清单式"改回"任务式"**（要求项从题面移进判据，模型自己判断该做什么，
  漏项直接 0 分而不是拿 0.75）；② 增加**标准答案必须落在审慎质疑一侧**的判断题
  （128 靠这两条把三模型均值从 0.86 压到 0.5165）。
- 迭代时必须分层归档并标注历史轮次（判据改版后跑完的旧 agent 产物不可比、应作废）。

## v2.1（2026-09-29）

来源：RL0-1 法律题（LAW-002 / LAW-004）返修实战。本版把那一轮踩到的坑固化成硬约束、校验脚本与移植说明。

### 新增硬约束（SKILL.md）

1. **判据锚点必须可溯源**：判据里的口径/标准/门槛/数值必须能在 `environment/input_files/` 找到出处；
   材料里的可疑口径（内部邮件、口头说法）只能写成 `negate` 扣分条，不能当正分项的得分前提。
   触发实例：把规则原文并不存在的「合并计算口径」写成算力门槛判据的得分前提，被人检判为
   "判据建立在规则原文不存在的法律标准之上"，参考答案同源缺陷也被连带指出。
2. **判据措辞三要求**：陈述式（不提问式起头）、档位量化（不用「若干/个别/普遍/多数」）、
   定位语贴合交付物形态（法律题写条款编号，不写「可逐格复算（单元格、公式）」）；
   可核验的条目 `criterion_type` 写 `Objective`。
3. **派生新批次必须继承上一轮返修成果**：新增核对流程（revision-and-qc 一之三）。
4. **打包必须验 zip 内的真实权限位**：Windows 重新压缩会把 `external_attr` 写成 0，
   本机看不出问题、对方解包即判 F08。
5. **难度档以实测为准**：零成本回算只作中间估计（实例：回算估 A1，实测 A2）。

### 新增脚本

| 脚本 | 作用 |
|---|---|
| `scripts/check_package_permissions.py` | 从 zip 里读回校验权限位/LF/残留/层级/两份 golden 一致性/交付文档/跑分目录 |
| `scripts/check_rubric_style.py` | 提问式判据、模糊量词、表格类定位语、`Subjective` 误标，以及锚点溯源待核清单 |
