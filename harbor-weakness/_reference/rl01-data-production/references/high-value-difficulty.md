# 高经济价值任务的可验证难度设计

用于专项数据题包需要提高真实区分度时，特别是法律案件复盘、跨文件核账与多交付物决策支持。与 [scoring-and-difficulty.md](scoring-and-difficulty.md) 的实测定档、[rubrics-spec.md](rubrics-spec.md) 的评分语义同时使用。参考过用户提供的《高经济价值任务难度突破指南》、法律服务优秀案例及 15 份案件附件；它们是设计样本，具体数字和法律结论均须在新题自身材料中重新核验。

## 先找值得付费的决策，再安排工作量

明确谁要在何时根据交付物作什么决定，以及错误决定的成本。把原始材料、处理、核验和交付串成同一决策链。附件多、报告长、调用轮数多本身不构成难度；只有当明细、例外和冲突改变最终结论时，额外工作量才有用。若另有执行轮数或时长门槛，靠真实读取、清洗、计算、求解、复核达到，不以重复打开文件、强制进度消息、拼接不相干任务或指定子代理凑数。

## 输入材料要有可裁决的难点

优先保留真实文件各自的粒度和格式，不预先汇总成已清洗答案。可用的难点包括：正式版与草稿、不同编码或同名主体、金额口径差异、截止日后的更正、审批与付款状态差异、需要区分的正常例外。每个冲突都须能从合同、制度、签发记录、时间戳或其他来源确定优先级；不能确定时，正确答案应为「待核」，并写明缺什么凭证、哪些结论只能条件成立。不得靠材料自相矛盾而无裁决规则压分。

把发现难点嵌入必须完成的明细链：逐条处理 → 标记来源与状态 → 用适用规则计算或判断 → 汇总 → 多情景重新计算 → 对交付物交叉核对。若只用最顺手的平均、相加或按比例缩放就能得到正确答案，应先检查任务是否缺少真实约束，而不是增加格式要求。

## 法律服务样本可迁移的结构

对判决材料先盘点文件，再以可追溯键识别「文书、程序案件、实质纠纷、请求项」四种分析单位；同一纠纷有多个案号或并案审理时须保留映射，不按文件名机械计数。一项请求一行，分别记录请求金额、法院认定的基数、支持金额、实际履行金额；没有执行凭证时最后一项应标「未载明」。把当事人主张、答辩、证据、法院查明、说理和主文分层，不能以前两者替代后两者。

计算型请求按来源、基数、期间、公式、结果和主文差异逐项复算；判例归纳必须给出案号及原文位置、适用条件和反例，避免把一案做法上升为普遍规则。交付给不同读者的台账、审查要点、报告、执行清单和案例索引应共享稳定编号，并有跨文件对数表。现行法规须按题目规定的基准日核实有效版本；未提供可靠来源的条文或时限不得编造。对个人信息保持原材料脱敏状态。

优秀案例的参考文字也须独立校验：若称 15 份文书，却列出的分组数量仅合计 14，或「并案判决有两个案号」却直接推断实质纠纷数，就标为待核并回查附件，不写入 golden 或唯一答案。样本中的具体金额、倍数、工龄口径和裁判结论不能迁移到另一批案件。

## 判据怎样查出错误

先估「送分项」的正分比例：文件名、格式、常规结构、泛泛风险提示若已接近目标分数，少量难点无法把实测分压到目标档。把正分重心放在可从输入唯一确认的关键判断、计算结果、异常处理和跨交付物一致性；无法唯一确认时，以必须给出的分支、待核状态和禁忌错误判分。每条判据尽量只查一个结果或一个独立错误，金额写清单位、口径、容差及来源；允许等效专业结论，不能以参考答案的文字相似度判分。

对已观测模型轨迹建立「错误 → 材料依据 → 正确结果 → 判据 → golden 位置」映射。每个实质难点至少有一个直接判据；上游错误连带多个下游失分时，确认每条评价的是不同结果，避免重复扣分。至少两条不同分值的扣分项只能用于可触发、可取证且与正分项不重复的重大错误。Likert/gradient 适合有真实部分正确层级的判断，不能把普通二元事实随意分档来人为压分。

只改 `difficulty`、`expected_pass_rate`、权重或自述分数不能证明题变难。A1/A2/A3 由最终版 golden 与三模型的完整、可追溯实跑决定；若模型得分约 0.94，改为 A1 仍不满足 A1 的 `<0.7` 上界。缺原生模型产物、轨迹、`reward.json` 或 `reward-details.json` 时该轮不得当作有效实测。改题面须重跑 agent；只改判据或参考答案可重判已有产物，但最终交付须保证各执行体面对同一最终版题面与判据。
