# 口径歧义与常见误判：实证案例库

全部案例来自 2026-09/10 的 weakness 金融题质检实战（FIN-WEAKNESS-UST-001、FIN-PE-001、FIN-IB-001）。
每条给：**现象 / 为什么是坑 / 下次怎么发现 / 正确处置**。

---

## 案例 1（本 skill 诞生的直接原因）：门禁脚本取值比规范窄，被误当成题包缺陷

**现象**：一条题有 6 个交付物、12 个输入附件、申报 `task_complexity = "C5"`。
`check_complexity.py` 报 FAIL（"产物数 6 支持 ['C4']，与声明的 C5 不匹配"）。
质检报告据此写成"必须改为 C4"。

**为什么是坑**：分级表的产物数是**重叠区间**（C4=4–6、C5=4–8），6 个产物同时属于两档；
是脚本把映射写窄了（`5–6 → 仅 C4`）。**错在工具，不在题包。**

**下次怎么发现**：

- 跑 `check_complexity.py --self-test`（v2.4 起）；把产物数代入分级表区间手工验证并集；
- 记住结论顺序：**规范原文 > 门禁脚本**。

**正确处置**：报告单列「脚本口径与规范冲突」小节（脚本原始输出 + 人工判据），结论写"提示/待人工核"，
**不得判不通过**；同时把脚本缺陷反馈给平台。实测：改为并集取值后同一题包 PASS，
而另外两题（8 产物、6 产物声明 C4）在两种取值下都 PASS——说明只影响产物数落在 4–6 的题。

## 案例 2：难度被"口径歧义"撑着（最贵的一类问题）

**现象**：某题 A 项目的完全稀释持股比例，材料两处表述互斥——
附件4 写「登记持股 12.00% 系按 **C 轮融资前**已发行股份计算，未考虑期权池稀释」，
附件3 又写「上轮 A 的持股比例**未考虑 2027 年 C 轮融资引入的期权池**」。
按前者（再考虑 C 轮新股 5.00/35.00＝14.29% 的稀释）推出约 9.09%，按后者推出 10.80%；
判据只认 10.80%。三个执行体**一致**按 9.09% 作答 → 15 条判据全 0，
权重合计 119/298＝**39.9% 正分池**。

**为什么是坑**：

- 难度不是来自专业能力，而是来自材料自相矛盾——甲方人检会按"靠题面歧义刷低分"**直接打回**；
- 更麻烦的是**锁死口径后模型很可能就算对了**：该题锁口径后三模型均值预计由 0.5431 升到约 0.94，
  A2 档（0.5–0.6）当场失效，必须同步补难度。

**下次怎么发现**：

- 跑 `check_cross_model_concentration.py <task-dir>`，看"三模型一致未满分"的权重占比（阈值 25%）；
- 对该组判据逐条追问：**这条的换算/口径能不能从 `environment/input_files/` 原文唯一推出？**
- 交叉比对多份附件对**同一事实**的表述（本例：附件3 与附件4 对同一持股比例的说法不一致）。

**正确处置**：三条路径选一，并在报告里写清代价——

1. **锁口径＝改材料**：在材料里写死换算式或给出结构性表格。最干净，但必须重跑 agent，
   且**要同时补难度**（先按「该组权重÷正分池」预估分数变化）；
2. **放宽判据＝改判据**：接受两种读法或把主口径降为单条判据。只重跑判官，同样会推高分数；
3. **保留现状**：仅在甲方书面确认口径后采用，并在交付文档写明推导依据，把风险显性化。

## 案例 3：金标自身不自洽，判据却按 ±0.01 锚死

**现象**：某题判据要求"发行后资产负债率 64.88%（±0.01pp）、净债务 102.13 亿元（±0.01）"，
占正分池约 24%，三个执行体全失分。但金标自身的列示过程是：
总资产 `335.00＋14.8715＝349.8715`（**未扣偿还 8.00 亿元的现金流出**），
总负债 `220.00＋15.00−8.00＝227.00`（**已扣**）——两端口径不一致。
且 14 份材料**没有任何一处**定义这个"发行后静态"的模拟口径。

按一致口径（募集资金净额入账后执行 8.00 亿元偿债）应为总资产 341.8715、资产负债率 **66.40%**、
净债务 **110.13**；按"偿债尚未执行"则为 67.16%。

**为什么是坑**：判据锚点既不能在材料里找到出处，金标自己也算不出该数——符合
"判据建立在材料里不存在的口径上"的打回理由。

**下次怎么发现**：

- 对金标里**成对出现的调整**（发行/偿还、增/减、转入/转出）做**加减自洽性复核**：
  一端扣了、另一端没扣，就是不自洽；
- 逐附件检索该口径关键词（本例："静态/发行后/净债务/资产负债率/货币资金"），确认材料有没有定义。

**正确处置**：补一句口径定义 + 按选定口径**同时**修正金标与判据数值 + 重跑判官。
好消息是这类修正通常**不影响难度**（本例模型答的 66.37%/117.00 与修正后的 66.40%/110.13 仍不符），
可以在报告里明确写"预计分数基本不变、档位不受影响"。

## 案例 4：同一份规则文件里两条条文互相矛盾

**现象**：某题压力情景下最终票面利率取询价区间上限 3.80%，而全部有效订单报价 ≤3.78%。
附件10 第2 条说"按区间上限定价，**差额由承销团余额包销**"（推出可募集 10.45 亿元、有效认购倍数 0.70），
第3、4 条说"**低于最终票面利率的不予配售**""有效认购倍数＝**不低于**票面利率的订单÷基础规模"
（推出 0.00 亿元、0.00 倍）。两种读法还会**翻转**"是否触发发行失败"（0.00 < 9.00 ⇒ 触发）。
两个执行体按字面作答而被扣分。

**为什么是坑**：同一规则文件内部冲突时，"哪个读法对"没有唯一解，模型按任一条作答都可能被判错。

**下次怎么发现**：把规则文件里**相互引用的条文**放在一起读（定价规则 + 配售规则 + 倍数定义），
沿"边界情形"（此处是"定价触及区间上限且无人达到该利率"）走一遍，看是否每条都能同时满足。

**正确处置**：建议在规则文件补一句边界情形的处理（"区间上限定价时全部有效合格订单全额获配；
有效认购倍数按有效合格订单金额合计计算"）。属改材料/改判据，需重跑；权重小时可先按**提示**报。

## 案例 5：证据文件越过白名单，且把内网信息打进包里

**现象**：为证明"某执行体确实在 claude-code 框架下运行"，生产方在
`跑分产物与轨迹/<题目>/gpt-5.6-sol/` 根目录放了 3 个文件（执行框架说明、网关实测脚本与结果），
其中出现内网网关域名 `https://api.aws.nibroute.xyz/v1`，脚本还引用本机路径 `_run/harbor.gpt.env`。

**为什么是坑**：执行体根目录白名单通常只允许 `output/`、`reward*.json`、`轨迹/`；
内网域名与本机路径属不必要的基础设施信息暴露。

**下次怎么发现**：结构检查时对"非白名单文件"逐个打开看用途；对全部文本文件跑内网域名/本机路径扫描。

**正确处置**：**先看它有没有取证价值**——有价值就不要判"残留"，写"移入 `轨迹/证据/` 并脱敏"
的建议，按**提示**报；同时确认**没有真实密钥**（本例脚本从本地 env 读取，包内无 key）。

## 案例 6：元数据编号不合规范（高频、零重跑可修）

**现象**：`weakness_tag = ["W4-…", "W7-…"]`，规范要求 `^W\d{2}`（两位编号）；
另有个别名称与词表原文不符（如"无据自造数据与口径**自行设定**"）。

**为什么是坑**：门禁直接 FAIL；且名称被改写过会导致批次级 weakness 覆盖统计错位。

**下次怎么发现**：`validate_task_package.py` 的 ERROR；并逐条与
`weakness-data-construction/references/taxonomy-and-quota.md` 的词表原名对读。

**正确处置**：改 `task.toml`（纯元数据，**零重跑**），跑门禁复验。注意同一批次编号写法要统一。

## 案例 7："判分未重跑"但按现行权重重聚合——可接受，但要如实披露

**现象**：某轮改了权重但没重跑判官，用同一批逐条判定按新权重重算总分。

**为什么可接受**：判据 description 与 weight 与现行 `tests/rubrics.toml` 逐条一致，
且按 rewardkit 公式复算与 `reward.json` 完全吻合，交付文档也如实写明"未伪称新跑次"。

**下次怎么发现**：见 [evidence-checks.md](evidence-checks.md) 1.5 的四行判据；
关键是**复算能不能对上**、**description 与现行判据是否一致**。

**正确处置**：可接受并在报告中单列该口径；若 description 与现行判据不一致，则必须重跑判官。

## 案例 8：区分度为 0（两个执行体逐条取值完全相同）

**现象**：`claude-opus-4-8` 与 `qwen3.8-max-0902` 得分完全相同、逐条取值也相同。

**为什么是坑**：难度证据的区分度被人检质疑；且若第 6 条（AI 生成区分度）不符甲方预期会被点名。

**正确处置**：先看根因——本例是两家在同一处口径上同样走偏（见案例 2），属真实信号；
如确需拉开，建议**新增一条能区分的判据**（如长文交付完整度/明细颗粒度），
而不是硬调权重（weight 只能取 ±3/±7/±10，数学上可能根本拉不开）。按**提示**报。

## 案例 9：难度均值贴近门槛，余量薄

**现象**：三模型均值 0.6718（门槛 < 0.7），余量仅 2.8pp；另一题 0.693，余量 0.7pp。

**为什么是坑**：判官是 LLM，重跑一次就可能越档；越档后该题不再是 A1/A2，需要补难度。

**正确处置**：报告里算出余量并提示"重跑判官存在越档风险"；
若刚改过判据/金标，优先建议**四个执行体一起重跑**（不要只跑一个，否则难度证据不可比）。

## 案例 10：交付文档缺项与历史轮次记录冲突

**现象 A**：`交付文档.md` 缺"批次内容表"（条数/参考分/三模型分/均值/难度档）。
**现象 B**：同一份文档里第 7 节（上一轮留档）写"gpt 用 codex 执行体、0.6938"，
第 8 节写"已在 claude-code 框架下复跑、0.6687"，包内实际轨迹是后者。

**正确处置**：A 属规范缺项（提示或必须整改，视甲方口径），把表补进 `交付文档.md`；
B 建议在第 7 节标注"已被第 8 节取代"，避免复核人误读——按**提示**报。
