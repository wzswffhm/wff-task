# 判分复算、独立重算与结构安全

## 一、判分证据核验（必做）

### 1.1 计分口径（rewardkit）

```text
Score = ( Σ_{正分项} w_i·v_i − Σ_{negate 项} w_j·(1−v_j) ) / Σ_{正分项} w_i
```

`reward-details.json` 里 `negate` 条目的 `value = 1.0` 表示**未触发违规**（不是"得了 1 分"）。
只按正分项求和会得到 >1 的假值——这是最容易算错的一步。

### 1.2 逐条复算与一致性核对

对每个执行体（`oracle`、`gpt-5.6-sol`、`claude-opus-4-8`、`qwen3.8-max-0902`）：

1. 读 `reward.json` 的 `reward`；
2. 读 `reward-details.json` 的 `reward.criteria[*]`（字段：`id/name/value/raw/weight/description/reasoning`）；
3. 按 1.1 公式复算，必须与 `reward.json` **完全一致**；
4. 逐条比对 `description` 与 `weight` 是否与现行 `tests/rubrics.toml` **完全相同**——
   不同说明判分用的不是最终版判据，该轮分数不能作为难度证据；
5. 记录每个执行体的"未满分条目清单"，供口径歧义排查使用。

### 1.3 难度门槛与档位

| 检查 | 标准 |
|---|---|
| 参考答案（oracle） | ≥ 0.85（目标 > 0.85） |
| 三模型均值 | < 0.7，且至少一个模型非零（非死题） |
| 档位（由实测落，不看申报值） | A1 `0.6≤x<0.7` / A2 `0.5≤x<0.6` / A3 `x<0.5` |
| 单模型 > 0.7 | **不是问题**，只有**均值**受 0.7 约束 |
| 均值余量 | 记录余量（如 0.6718 距 0.7 仅 2.8pp），余量薄时在报告中提示"重跑判官可能越档" |

### 1.4 轨迹框架核对

每个模型执行体的 `轨迹/trajectory.json` 应满足：`agent.name = claude-code`、
`version = 2.1.114`、含 `steps`。若发现 `codex` 等其它框架，属规范硬要求未满足（必须整改）。
同时确认 `轨迹/claude-code.txt` 与 `trajectory.json` 均存在、可解析。

### 1.5 "判分未重跑"能否接受

| 情形 | 判定 |
|---|---|
| 判据/权重/金标未变，直接用原判分 | 可接受 |
| 仅调整权重，但用**同一批逐条判定**重新聚合，且聚合结果与 `reward.json` 可复算一致，并在交付文档如实披露"未重跑、未伪称新跑次" | 可接受（本 skill 认可，但要在报告中单列该口径） |
| 判据 description 变了、却沿用旧判分（`reward-details` 的 description 与现行 toml 不一致） | **不可接受**，必须重跑判官 |
| 题面/材料变了却沿用旧 agent 产物 | **不可接受**，必须重跑 agent |

## 二、独立重算关键链路（本 skill 的核心要求）

**原则**：不引用金标结论，只读 `environment/input_files/`，自己重建计算。
金标只用于**事后对照**，不用作推导依据——否则复算退化成"抄答案"。

### 2.1 先找"卡点链路"

一条题通常有 1–3 条链决定大部分分值。找法：

1. 看交付文档的"出题设计说明/不可省略点"，出题方通常会自述卡点；
2. 跑 `check_cross_model_concentration.py`，看"三模型一致未满分"的判据集中在哪条链上；
3. 问一句：**哪个单一判定错了会连带污染一批下游判据？** 那就是卡点。

### 2.2 复算产出形式

报告里给一张对照表，至少四列：

| 复核点 | 材料出处（附件号 + 表格/条款） | 我的独立复算 | 金标 | 结论 |
|---|---|---|---|---|

结论只能写「一致 / 不一致 / 口径存疑」。**不一致必须给出我的推导过程**，否则无法证伪。

### 2.3 常见链路类型（金融/办公 weakness 题）

- 数据核验：文件 SHA-256 与来源清单交叉核对、记录数/字段数/日期范围/自然缺失；
- 频率与单位换算：日→周标签、百分比↔小数↔基点、亿元↔万元；
- 指标聚合：分位数/中位数（与算术平均的区别）、横截面百分位（平均秩/有效样本数）；
- 估值与分配：完全稀释换算、企业价值→股权价值桥接、折扣（流动性/限售/清算孰低）、
  分配瀑布（优先回报计息口径、GP 追赶目标式 `(出资+优先回报)×g/(1−g)`）；
- 定价与配售：合格订单认定、累计定价临界点、边际档按比例配售与尾差、认购倍数口径差；
- 约束优化：LP/MILP 复算（网格单位、换手约束实现方式极易写错，**先自证约束写对了**再比对结果）；
- 压力情景：冲击向量逐期限对齐、现金口径与利润口径的区别；
- 跨文件一致性：同一数字在多份交付物间是否同源可比。

### 2.4 环境准备（缺库时）

本地复算常缺 `pandas/scipy`。安装前先清代理变量，否则会走不存在的代理：

```bash
unset HTTP_PROXY HTTPS_PROXY ALL_PROXY http_proxy https_proxy all_proxy   # Windows: 置空同名环境变量
python -m pip install pandas scipy
```

**自证脚本正确性**：写出与预期不符的结果时，先怀疑自己的实现（尤其 MILP 的约束写法、
符号方向、百分比/小数单位），再怀疑金标。本 skill 的实践中，两处"金标不一致"经排查
分别是「换手约束写成了逐元素箱约束」和「CVaR 符号取反」——都是复算侧的错误。

## 三、结构与安全检查

| 检查 | 做法 | 不通过的后果 |
|---|---|---|
| zip 内权限位/LF | `check_package_permissions.py <zip>` | Windows 重新压缩会把 `external_attr` 清零，甲方解包后脚本不可执行 |
| 残留文件 | 同脚本；另查 `__pycache__/*.pyc`、`.DS_Store`、`.git` | 打包污染 |
| golden 双份一致 | `solution/golden_output/` 与 `tests/__golden_output/` 逐字节一致 | 判分基准不一致 |
| 交付物命名六处一致 | instruction / artifacts / `[[metadata.deliverables]]` / golden / `__golden_output` / 判据交付物清单 | 命名不符即扣分 |
| 执行体目录白名单 | 只应出现 `output/`、`reward.json`、`reward-details.json`、`轨迹/`（题目级另有 README） | 甲方会按"残留"打回 |
| 密钥扫描 | 正则 `sk-[A-Za-z0-9_-]{16,}`、`Bearer\s+\S{20,}`、`api[_-]?key`、`ANTHROPIC_AUTH_TOKEN\s*=\s*\S` | 凭据外泄 |
| 内网信息落包 | 查内网域名/网关地址/本机绝对路径（如 `C:\Users\...`、`_run/harbor.*.env`） | 基础设施信息外泄，建议脱敏或移入证据子目录 |
| 脱敏边界 | 受限资料（如 `SEC-01..04`、`AP-2027-0920`）不得出现在对外披露交付物中 | 合规风险，按必须整改 |

**白名单冲突的处理**：若某个非白名单文件确有取证价值（如证明执行框架的实测记录），
不要直接判"残留"——在报告中写清它的用途、给出"移入 `轨迹/证据/` 或脱敏"的建议，
并按**提示**报，除非甲方清单已明确禁止。
