# 修复 Windows 上的批量文件发布器

我们的离线部署工具 WinPublish 会把经过 SHA-256 校验的构建产物发布到 Windows 上已存在的文件。当前实现直接覆盖目标文件：应用持有读取句柄时会失败，某些情况下会改坏旧版本；批次后半段失败时，还会留下新旧版本混杂的目录。

请修复工程，使下面的公开行为成立。目标是真实的 Windows NTFS 语义，不需要实现其他操作系统版本。

## 使用方式与修改范围

- 工作目录中的 `src/` 是允许修改、增加或重组的 C# 源代码。
- 保留 CLI：`WinPublish.exe apply <plan.json>`。不要求任何特定私有函数、类型或实现布局。
- `build.ps1` 使用 Windows 内置的 .NET Framework 4.x C# 编译器，语言级别 C# 5，递归编译 `src/*.cs`，生成 `bin/WinPublish.exe`。可使用 .NET Framework 4.8 标准库以及 Windows API，不联网下载依赖。
- 请勿修改构建入口、公开契约、测试或系统配置。无需管理员权限。工程的 `src/`、`bin/` 可写，其余工程文件只读；临时诊断与自测文件可放在 `C:\agenttmp`。
- 构建：`powershell.exe -NoProfile -File .\build.ps1`。

计划文件为 UTF-8 JSON（允许 BOM）：

```json
{
  "files": [
    {"source": "staging/a.dat", "destination": "live/a.dat", "sha256": "64位十六进制SHA-256"}
  ]
}
```

路径相对计划文件所在目录解析，也允许绝对路径。计划包含 1–32 个条目，按数组顺序发布。源和目标都已存在且是普通文件，位于本机同一个 NTFS 卷；本题不涉及跨卷发布、UNC、超过 240 字符的路径、重解析点、只读/加密/压缩文件或系统崩溃恢复。源文件可以位于不同目录。

## 行为要求

### R1：基本发布与完整性

成功时，每个目标的默认数据流逐字节等于对应源的默认数据流。支持空文件、二进制文件、Unicode/空格路径、UTF-8 BOM 计划文件以及任意工作目录。源文件的默认内容、命名流、创建时间和 DACL 保持不变。`sha256` 大小写不敏感，必须对应本轮实际发布的数据；禁止发布校验失败的数据。

### R2：Windows 读取句柄与原子可见性

若旧目标已被读取进程打开，且它授予 `FILE_SHARE_READ | FILE_SHARE_WRITE | FILE_SHARE_DELETE`，发布应成功；该旧句柄仍必须完整读到旧内容，重新打开目标必须读到完整新内容。不能先删除目标再创建，也不能原地截断/写入目标。同步好的持续读取进程只能看到完整旧内容或完整新内容，不能看到目标消失、空窗或半写数据。该要求同样适用于持续读取期间对同一目标反复发布，不能依赖读者恰好避开短暂窗口。若目标还有本计划以外的硬链接，其他链接仍须保留旧内容、原命名流、创建时间和 DACL，只更新计划指定的路径。

### R3：保留目标的 NTFS 元数据

成功发布必须保留原目标的创建时间、DACL（包括继承保护状态）、所有已有命名数据流的名称和原始字节。只发布源的默认数据流，不引入源的命名数据流，也不让源的同名流覆盖目标的流。不要用暂存目录的默认权限替代目标的权限。

### R4：失败时恢复整个批次

对合法批次，如果任一目标的 Windows 共享限制阻止替换（例如另一个健康进程持有未授予 `FILE_SHARE_DELETE` 的读句柄），命令必须有限时间内失败，而不是等对方退出或强行关闭其句柄。命令返回前，此批次所有目标均恢复为调用前的默认内容、命名流、创建时间和 DACL；外部读取进程继续正常工作。不允许只回滚当前条目或只保留部分新版本。

不要求多个文件的变化在同一个瞬间可见：成功前和回滚期间可观察到批次中间状态，但命令结束后的状态必须一致。失败后解除外部占用，再执行相同计划应成功。

### R5：先验证计划，防止别名损坏

空计划、路径/条目缺失、源或目标不存在、非法 SHA-256、实际哈希不符，都必须在改变任何目标之前被拒绝。

任何两个目标若解析为同一个文件（包括大小写/`.`/`..` 路径别名或 NTFS 硬链接），必须拒绝。任何源若与本计划任意目标指向同一个实际文件，也必须拒绝。不同路径不代表不同文件；硬链接身份验证必须利用真实文件系统。允许多个条目重复使用一个不属于目标集合的源。

### R6：退出、资源释放与清理

- 成功：退出码 `0`，stdout 输出一行 JSON：`{"status":"ok","published":N}`。
- 用法或计划验证失败：退出码 `2`，stdout 输出一行 JSON：`{"status":"error","kind":"validation"}`。
- 合法计划的 I/O/共享限制导致发布失败：退出码 `3`，stdout 输出一行 JSON：`{"status":"error","kind":"io"}`。
- 可在上述 JSON 中增加诊断字段，也可向 stderr 输出诊断；不得谎报成功。
- 一次调用在给定的小型批次上应在 15 秒内返回，不得无限重试。
- 无论成功还是可恢复失败，关闭自己的文件句柄并移除本次创建的暂存/备份文件，不遗留后台进程，不改变无关文件和系统状态。

验收时只比较目标原有的 DACL 及其继承保护状态；不要求复制目标的 owner/group 字段，也不得把源文件的安全描述符带到目标。调用创建的暂存、备份和诊断目录必须在返回前清理干净。

假定调用者已拥有计划中所有文件和所在目录的读取、写入及删除权限；外部进程只执行上述稳定读取/占用，不会主动修改文件、权限或目录。不同发布调用不会并发修改同一目标。磁盘耗尽、断电、强制杀死发布器及第三方在回滚期间新建占用不在承诺范围内。

请交付可构建、满足这些行为的实现，不要禁用发布功能或降低校验标准。
