# Windows 来源标记清理器：批处理事务版

## 背景

项目需要在 Windows 上批量清理下载文件留下的 NTFS `Zone.Identifier` 来源标记。现有脚本只要看到文件存在就返回成功。本次要把它补成可重复调用的安全批处理接口，并支持在调用方需要时先预览或以全有或全无的方式提交。

## 目标

完善 `workspace/src/ZoneMarkCleaner.ps1` 中的 `Clear-ZoneIdentifier` 函数，使它在 Windows PowerShell 5.1 和 PowerShell 7 上可用。除了普通模式，还要实现 `-WhatIf` 预览、`-Atomic` 批处理和可选的 JSONL 审计。

## 必须满足的行为

1. 参数接受一个或多个输入路径。路径可能包含空格、中文和方括号等普通文件名字符，必须按字面解释，不能展开通配符。每个输入都要单独得到一个结果，不能因为某一项失败而终止普通模式的后续处理。
2. 只处理已有的普通文件。目录、Junction/符号链接等 Reparse Point、不存在的路径、空路径、非法路径和指向另一个备用数据流的路径都返回 `Failed`，不能修改被拒绝的对象。
3. 普通文件存在名称为 `Zone.Identifier` 的备用数据流时，只移除这个流；流名匹配不区分大小写，`Zone.Identifier.bak` 不能被误删。没有目标流时返回 `AlreadyClean`，重复调用必须幂等。
4. 移除来源标记不能删除或重建主文件。主文件必须保持同一个文件对象，内容、长度、SHA256、创建时间、最后写入时间和原有属性都必须保持不变；除目标流以外的所有备用数据流必须保持原样。只读、隐藏等属性组合也必须在成功后恢复。
5. 普通模式下，输入顺序和结果数量必须一致。每项至少有 `Path`、`Status`、`Error` 三个字段，`Path` 原样回显；成功状态的 `Error` 为空，失败状态有可读错误信息。状态只能是 `Removed`、`AlreadyClean`、`Failed` 或 `WouldRemove`。
6. 支持 `-WhatIf`（PowerShell 的 ShouldProcess 语义），并允许与 `-Atomic` 组合。预览不能删除或改变任何文件，也不能创建或追加审计文件；有目标流的普通文件返回 `WouldRemove`，无目标流返回 `AlreadyClean`，非法输入仍返回 `Failed`。`-Atomic` 与 `-WhatIf` 同时给出时以预览为准，不做整批提交。
7. 支持 `-Atomic`（整批事务）。先整批预检，再动文件：只要有任一输入无效，整批一个文件都不能改，全部结果都是 `Failed` 并带可读错误（措辞不限）；此时不创建、不追加审计文件（这是第 9 条的例外）；本来就已经干净、但属于无效批次的输入也不能报成功。只有全部输入都有效时才按输入顺序提交删除，重复路径按提交后的真实状态报告。
8. 提交过程中任何一步失败，都必须把本批已经删掉的目标流尽力恢复回来，并把已触碰文件的属性和时间还原，不能留下半批结果。恢复动作必须逐个文件确认结果：本批每个输入都要确认，包括提交本身失败、但其目标流已经被删掉的那个文件；已经完整还原的文件与未能还原的文件要能被区分出来（例如在结果的 `Error` 里写明哪些文件没有还原），未能还原的文件绝不能被报告成成功。只要还有文件没能恢复，整批就必须是 `Failed`。`-AuditPath` 必须在删除之前就确认可用：它指向目录、备用数据流、通配符，或它的父目录不可写时，一律在删除前失败。`-Atomic` 模式下审计写入失败也必须触发整批回滚（包括已经提交的文件），并把该失败如实反映到结果或审计行中，不得静默。
9. 支持可选的 `-AuditPath`。普通模式非 WhatIf 调用，以及 Atomic 成功提交完成后，针对每个输入，向该路径追加一行 UTF-8 JSON（追加不得截断或覆盖已有内容，失败项也要成行）；每行至少记录原始 `Path`、最终 `Status`、`Error` 和名为 `TimestampUtc` 的 UTC 时间字段，行顺序与结果顺序一致。审计写入失败不能被静默吞掉；Atomic 模式下审计预检或提交失败不得留下部分文件清理。
10. 父目录链也是输入的一部分：输入路径的**任一父目录**（含中间层级）是 Reparse Point（Junction 或符号链接）时，该输入必须返回 `Failed`，且不得修改对象；不允许只检查叶节点。`-AuditPath` 的父目录链同理，其父链含 Reparse Point 时必须在任何删除之前失败。
11. `-AuditPath` 不得与任一输入文件是**同一文件对象**。判定必须基于文件身份，而不是路径字符串：同一文件的硬链接、不同大小写、相对/绝对或带 `.\` 前缀的不同写法都算冲突，必须在删除任何目标流之前失败；不得只比较两个路径文本是否相等。
12. 同一物理文件以不同写法（绝对路径、相对路径、`.\` 前缀、硬链接）在同一批次出现时，必须按**文件身份**处理而不是按路径字符串处理：每个输入仍按字面回显其 `Path`，提交按文件身份进行，`-Atomic` 中后续重复项必须报告提交后的真实状态（`AlreadyClean`），不得重复删除、不得重复写入审计行数以外的额外处理，也不得误报 `Failed`。
13. 审计目标必须能在删除之前就确认可写：`-AuditPath` 指向的文件还不存在、而它的父目录又拒绝写入（例如带拒绝写入的 ACL、当前用户无法在该目录创建文件）时，必须在删除任何目标流之前失败（普通模式与 `-Atomic` 同样适用）。已经存在且可写的审计文件按其自身可写性判定，不受父目录影响。
14. 当同一批次里同时出现"同一文件对象的多个写法（例如硬链接）"和"父目录是 Reparse Point 的路径"时，后者让整批无效：`-Atomic` 必须整批取消、不修改任何对象；普通模式也必须逐项拒绝且不改动被拒绝的对象。
15. 必须接受扩展长度前缀写法（`\\?\` 与 `\\?\UNC\`），输入路径和 `-AuditPath` 都适用：`Path` 字段原样回显用户给出的写法；带前缀的合法审计路径必须与等价的普通写法一样被接受并写入审计行。这种写法在第 10、11、12 条的父目录 Reparse 判定、文件身份判定与审计冲突判定中，必须与等价的普通写法得到**一致结论**。不得因为带前缀就拒绝合法输入，也不得把前缀当成普通文件名的一部分去拼接。**总长度超过 260 个字符的路径不在本要求范围内**（Windows PowerShell 5.1 所在 .NET Framework 不支持长路径，属平台限制）。
16. 清理不得改变目标流以外的任何文件元数据。在只读、隐藏、压缩或稀疏等属性组合下，清理后主文件的字节、长度、SHA256、创建时间、最后写入时间与属性集合（含压缩/稀疏位）必须保持不变；其他备用数据流（含 `Zone.Identifier.bak`、`Zone.Identifier.orig`、`MyZone.Identifier`）必须逐字节不变；文件的 ACL 与属主必须不变。不得用"重建文件再把内容写回"的方式达到清理效果。

## 边界和约束

- 必须使用 Literal Path 语义，不得把用户路径当作通配符。
- 不能删除或重建主文件来达到清理效果，不能清理除 `Zone.Identifier` 之外的备用数据流。
- 需要兼容 Windows PowerShell 5.1 和 PowerShell 7，不需要网络，不需要管理员权限。
- 只允许修改 `workspace/src/ZoneMarkCleaner.ps1`。不要修改测试、环境、题面或结果协议。
- 普通模式允许逐项成功或失败；Atomic 模式是整批事务，不能通过先改一部分再报告失败来满足要求。

## 运行入口

在 Windows PowerShell 5.1 或 PowerShell 7 中，从任务根目录执行。普通入口示例：

    $paths = @('path with spaces.txt', 'another.txt')
    & .\workspace\run.ps1 -Path $paths

需要验证新增开关时，可以点源脚本后直接调用函数，例如：

    . .\workspace\src\ZoneMarkCleaner.ps1
    Clear-ZoneIdentifier -Path $paths -WhatIf
    Clear-ZoneIdentifier -Path $paths -Atomic -AuditPath .\audit.jsonl

完成修改后，使用入口和函数调用验证普通、预览、Atomic 成功、Atomic 预检失败、审计和重复路径场景，并说明验证结果。最终测试由外部评测程序在独立环境执行。

## 用户可见验收

- 普通模式能安全清理混合输入，坏项不阻断后续好项。
- `-WhatIf` 只给出将要处理的结果，不改变文件或审计文件。
- `-Atomic` 遇到坏路径或坏审计目标时整批不变，全部有效时才提交。
- 带来源标记的文件清理后仍是同一个文件对象，主内容、时间、属性和其他备用数据流不变。
- 审计 JSONL 可逐行解析，顺序、状态和错误与返回结果一致。
