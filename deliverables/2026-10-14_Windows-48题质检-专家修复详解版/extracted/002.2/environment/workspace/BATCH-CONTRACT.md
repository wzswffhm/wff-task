# 可恢复的多案卷发布

单案 seal/report 契约继续有效；新增批次路径必须复用同样的 NTFS 忠实性和摘要协议，而不是降低批次镜像精度。

## 公共接口

- `seal-batch --plan <绝对XML文件路径> --journal <绝对目录路径>`：成功退出 0，输出严格两行 `State=COMMITTED`、`CaseCount=<条目数>`。计划或运行失败退出 3；缺少 CLI 参数仍为 2。
- `recover --journal <目录>`：在新进程中恢复，成功退出 0，输出 `State=ROLLED_BACK` 或 `State=COMMITTED`。无事务记录退出 4；暂时无法恢复退出 3，保留日志和前像以便重试。
- `batch-status --journal <目录>`：只读查询，存在时退出 0，单行 `State=ACTIVE|COMMITTED|ROLLED_BACK`；不存在退出 4。终态记录必须保留以区分已提交、已回滚与从未开始。

计划编码 UTF-8，XML 根为 `<EvidenceBatch version="1">`，包含 1–8 个按顺序排列的 `<Case id="BATCH-A" source="D:\..." dest="D:\..." />`。不支持 DTD。id 只允许 ASCII 字母、数字、横线和下划线，1–64 字符，不区分大小写去重。路径必须为绝对本地路径；路径规范化后不区分大小写。同批次源、目标和 journal 均不允许相同或相互祖先/后代；journal 与目标位于同一 NTFS 卷。计划文件位于这些目录之外。源存在且只读，同一事务无并发操作，无重解析点。已使用的 journal（含终态）不得被新 seal-batch 覆盖。

## 原子性与持久恢复

成功时，每个目标具有其源案卷的完整数据、NTFS 属性、硬链接组和公开摘要；各案卷原生 64 位记录符合单案协议，32 位陈旧记录删除，其他案卷不变。

普通错误返回之前，整个批次恢复到调用前状态，而非只回滚最后一个案卷。原目标存在时，恢复其原来的文件集合、内容、ADS、安全描述符、创建/写入时间、存储形态和 NTFS 文件身份；原目标不存在时不得留下新目标。两种注册表视图分别恢复原来的键存在性、所有值名、值类型和值数据（String、ExpandString、MultiString、DWord、QWord、Binary）；案卷记录无子键，注册表 ACL 不作为日志序列化对象。

源共享锁不是人为强制失败点：如果合法的 Windows 备份读取仍能取得完整源数据，允许整个批次正确成功；如果实际读取失败，则必须整个批次回滚。不得因为普通 FileStream 会失败就拒绝合理的备份读取实现。

进程可能在下列观测点被强制终止（不执行 finally）。此时不能依赖进程内存或异常处理回滚。新进程 recover 必须仅凭 journal 与尚存的目标/前像完成恢复；原 plan 文件和所有源目录可以已经不可用。提交标记之前的事务恢复为 ROLLED_BACK，之后恢复为 COMMITTED 并保留全部新目标和记录。提交后的 recover 只清理事务临时内容，不再写入记录或更改 CompletedUtc。重复 recover 具有幂等性。

恢复时如果某个待删除/替换的目标被另一个 Windows 进程以不共享删除的句柄锁住，必须退出 3，不能吞错误并声明终态、不能丢失尚需的前像；锁释放后再次 recover 必须成功。无断电、卷损坏、恶意篡改日志或多个恢复者并发要求。成功/恢复后的 journal 可以保留终态元数据，但不能保留任何案卷数据副本；目标父目录不能残留临时镜像或前像。

## 可观察的进程终止握手

为便于现场故障复现，冻结如下公共诊断接口，不规定内部日志格式或私有函数：

当 `EVIDENCE_MIRROR_PAUSE` 为指定点、`EVIDENCE_MIRROR_SIGNAL` 为回执文件路径、`EVIDENCE_MIRROR_RELEASE` 为放行文件路径时，达到该点后先确保所描述的状态持久化，写回执内容为该点的 ASCII 文本，再等到放行文件存在才继续。未设置环境变量时不得暂停。回执文件的父目录由调用者提供。等待期间外部工具可以终止整个候选进程；recover 不使用这些暂停变量。

- `prepared`：全批次新镜像和恢复所需前像信息已准备，尚未替换任何目标或发布任何记录。
- `replaced:N`：按计划顺序，第 N 个目标已经被新镜像替换，恢复信息已持久化；不要求注册表更新与所有替换之间有特定内部顺序。
- `published:N`：第 N 个案卷权威记录和陈旧 32 位记录处理已完成，恢复信息已持久化。
- `committed`：整个批次的提交决定已持久化，所有新目标和记录已发布，可以尚未清除旧前像。

N 从 1 起。不得提前写回执、用打印代替真实终态或依赖测试进程替候选恢复状态。任何满足公开状态与恢复语义的实现均可，不要求某种 Win32 调用顺序或 Golden 日志结构。
