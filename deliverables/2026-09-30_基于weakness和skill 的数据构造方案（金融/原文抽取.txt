○  作为对应办公场景的专家，你熟悉该领域的任务要求，熟悉该领域办公目标实现的产物标准。

务，给出一套能衡量任务做得好坏的打分项。
○  我们会根据你给的打分项
▪  ① 对你提交的参考答案打分，看得分是否足够高（正确率>0.85）；
▪  ② 用3个模型执行你给出的任务，并用你给出的打分项打分，看难度是否足够高。
○  此外，人工质检会重点考察题目真实性、参考答案合理性、打分项设计合理性、是否hack等异

三、基于 skills/workflow 的 scaling 的专项数据
1. 背景 & 出发点
目前 Cowork RL 数据中，大部分任务仍运行在相对简单的环境中：
●  以 filesystem / shell / 少量原生工具为主；
●  Tool schema、可用能力和调用方式相对固定；
●  Skill 即使存在，也经常只是辅助信息，并非完成任务所必需；
●  Workflow 多数是线性的「读取 → 处理 → 输出」，较少包含真实业务中的状态变化、异步依赖、异
常恢复、跨工具协同等复杂过程。
下一阶段希望数据建设从单纯扩充 Task Distribution，进一步转向扩充 Environment Distribution。
2. 整体数据目标
本专项主要覆盖以下几类能力：
Skill Dependency
任务必须真正依赖 Skill 中的特有信息、规则或 SOP 才能稳定完成。
skill能够包含一些特有信息或行为规则，避免 Skill 成为一个可有可无的 contextual document
Workflow Execution
构造真实存在：多步骤依赖；多工具协同；branch；async；blocking state；subagent；的长链路任
务。（最好是有涉及 subagent 的，例如在 codex 下运行该任务会触发 subagent）

===== PAGE 9/14 =====
9 / 14
MCP Scaling（低优）
扩大模型在非原生工具、陌生 Tool Schema 和不同 Tool 组合下的泛化能力。可主要通过 MCP
数据需要基于各 Agent Framework 可接入的 Plugin / MCP 能力构造任务，并在每条任务中明确提供
当前 Environment 下模型可使用的工具集合 / MCP。工具可以是框架已有能力，也可以是动态注入的
自定义工具（在题目里显式说明）。
3. Skills 数据需求
Skill Discovery
提供多个 Skill，要求模型自行判断：是否需要 Skill，以及应该使用哪个 Skill。
Skill Dependency
构造：
没有 Skill 中的特殊知识 / 行为规则，模型很难正确完成任务。
推荐构造方式
类型一：特殊业务规则
●  Skill 明确规定：当两个 authoritative source 的关键字段冲突时，禁止自行选择，必须暂停并向用户
确认。
●  Task 中主动埋入这种冲突。模型如果没有真正遵循 Skill：最终一定会进入错误 branch。
类型二：环境特化 SOP
●  例如 Skill 定义某企业内部审批流程：Draft → Compliance Review → Manager Approval → 
Publish
●  Task 要求完成发布。如果模型直接：Draft → Publish。最终 Workflow State 必须失败。
类型三：特殊计算 / 判定规则
●  Skill 中包含：特殊阈值；内部映射规则；自定义字段定义；业务优先级；fallback 顺序。要求这些内
容直接影响 final answer。
Skill Generation / Editing
可以增加一批：创建 Skill；修改已有 Skill；从 SOP 抽取 Skill；Skill migration；Skill package repair 
之类的任务

4. Workflow 数据需求
Dependency-aware Workflow
任务中存在明确 dependency：
A → B
A → C
B + C → D
D → Final
要求模型：
●  正确拆解 dependency；
●  维护哪些任务已完成；
●  避免提前执行依赖未满足的步骤；
●  Final 前确认 dependency 已全部完成。
Subagent Workflow
构造必须依赖多个 Subagent Result 才能完成 Final 的任务。
5. 数据交付 Metadata
建议每条数据额外维护以下字段：
skill_set                  = ["approval-workflow"]   #  环境内安装的功能型 skill（= environment/
                                                     skills/ 下的目录名）
task_complexity            = "C3"                          # C1–C5，取值口径见正文分级表
expected_skill_dependencies= ["approval-workflow"]   #  完成任务真正必须依赖的 skill（子集，
                                                      可为空表示Skill Discovery 干扰项）
weakness_tag               = ["W07-流程跳步", "W12-约束遵循"]   # ≥覆盖1个
字段 类型 取值写法 / 约束
skill_set array 环境内安装的功能型 skill 目录名，须
与 environment/skills/<name>/ 
逐一对应；可含干扰项（Skill 
Discovery 场景）
task_complexity enum C1–C5，按正文分级表的文件数 / 
requirement / evidence-hop 等硬
指标判定
expected_skill_dependencies array skill_set 的子集：不依赖它任务必
失败的 skill。Skill Discovery 任务里
这一项应严格小于 skill_set（存在
故意的无关 skill）
weakness_tag array 覆盖 ≥1 个；

功能型 Skill 的标准目录结构
AQ-002/
├── task.toml                      # 任务声明
├── instruction.md   # 显式说明"  通过contract-redliner skill 完成，禁止其它方式改文档"
├── environment/
│   ├── Dockerfile                 # COPY skills/ /skills/  ← skill 在这里被装进环境
│   ├── skills/
│   │   └── contract-redliner/
│   │       ├── SKILL.md   # Anthropic Skill 格式：frontmatter(name/description/compatibility)
                           +正文SOP
│   │       ├── scripts/           # read_document.py / propose_edits.py / add_comment.py …
│   │       └── references/        # anchors.md  等被SKILL.md 引用的补充规则
│   └── app/                       # 任务输入：contract.docx + grounding 材料
├── tests/
│   ├── test.sh → run_verifier.py  # 判分入口
│   └── rubrics.json               # 判据
└── solution/
    ├── solve.sh
    └── ground_truth.docx          # ground_truth
