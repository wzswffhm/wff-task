# Windows 价值与采购分类说明（wfflab__wfmt-215）

> 的分类澄清与后续路线记录，**不代表修改或重评了原始产物**。原始作答记录、
> 原始分数与原始证据一律保持原样；本说明只新增口径，不改写历史。

对应质检条目：`ZQ005-03｜风险｜Windows 专属价值较低`。
对应手册条款：**QD-SP-12**、**QD-SP-18**。

## 1. 结论

本题**不主张 Windows 反事实价值**。它的能力域是**通用编码能力**：

| 能力维度 | 具体内容 |
| --- | --- |
| 二进制格式逆向 | 从权威样本反推头部、记录区与尾部校验和，包括变长 tag 的字节布局 |
| 校验和实现 | 32 位通用 CRC 变体的确定性与覆盖范围（header + records） |
| 错误分类 | `WFormatError.kind` 的分类学与校验顺序 |
| 流式 IO 纪律 | 惰性迭代、有界 `read(n)`、读满容器时未产出条数有界、尾部校验 |
| 一般工程能力 | 逐字节往返、公开 API 不回归、生成数据自洽 |

判分用的全部断言只触及上表内容。**"在 Windows 上执行"不构成 Windows 采购
价值**：同一个包在 Linux 上换掉解释器即可原样通过，分数不会变化。

## 2. 判据与操作系统机制的关系（逐项核对）

| 断言族 | 依赖的 OS 机制 | 说明 |
| --- | --- | --- |
| 样本 `verify` / 逐字节往返 | 无 | 纯内存字节运算 |
| 变长 tag 与记录布局 | 无 | 与文件系统无关的容器内部布局 |
| CRC-32 标准测试向量 | 无 | 跨平台一致的 CRC 变体 |
| 错误分类 `kind` | 无 | 纯 Python 异常对象 |
| 流式 `read(n)` 纪律 | 只依赖文件对象的 `read(size)` 契约 | 由测试内 `GuardedReader` / `io.BytesIO` 提供，不依赖 Win32 句柄语义 |
| `read_all` 与 `unpack` 一致 | 无 | 纯内存 |

明确**不依赖**：注册表、NTFS 重解析点/ACL/大小写语义、Win32 API、进程与
服务、计划任务、代码页与 `PATHEXT`、PowerShell 特有行为。

## 4. 若需要 Windows 专属评测（未实施，供后续立项）

专家修复步骤第 3 条要求：新增有实际产品需求的 Windows 语义，发布新版后重新
作答。**新需求不得追溯扣旧样本**——即：不能拿旧的一轮作答去判定新需求的失败。

候选改造方向（任选其一，均需新版本号 + 重跑控制组与模型）：

1. **Windows 文件共享与句柄语义**：要求记录流在被另一进程以 `FILE_SHARE_READ`
   打开时仍可增量读取，并在写端遭拒时给出约定错误分类（`ERROR_SHARING_VIOLATION`）。
2. **NTFS 稀疏/压缩文件容器**：要求流式读取在稀疏区间上保持 O(已读) 内存
   （用 `FSCTL_QUERY_ALLOCATED_RANGES` 或等价能力），把流式纪律绑定到真实
   Windows 文件语义。
3. **重解析点 / 备用数据流（ADS）落盘**：要求容器写入 ADS 或跨 junction
   解析到真实文件，判据依赖重解析点语义（与题池中已有的 Windows 语义题互不重复）。

改造后必须复核：控制组 Golden=1 / no-change=0、区分度重跑、分类与采购目标一一对应。
