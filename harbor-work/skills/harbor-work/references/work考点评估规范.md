# work 考点评估规范（本地要点）

来源：用户在 Chrome 中打开的《work考点评估规范》（2026-08-12 查阅）。本文保留用于 A/B 标注的可执行要求；原文中的图片案例不在离线副本中。

## 好考点的标准

- 一个考点对应一个可诊断的失败模式。同一逻辑不要反复拆分；不同考点的检查对象、证据和通过条件应互斥。
- 写明可观察的证据和通过条件。考点本身应让评估者判断产物质量，而不是要求其重新通读指令和输入材料。
- 将存在性、格式、关键词等表层合规与内容正确性、业务逻辑、任务完成度、专业准确性等深层质量分开。表层项是门槛，不得替代质量判断。
- 只在任务明确追求创新、专业深度或用户体验时设置卓越性项，并给出可观察的判断条件。
- 避免“质量好”“逻辑清晰”“专业性强”“翻译正确”等无锚点的宽泛或常识性标准。

## 锚点与权重

- 关键计算、复杂业务逻辑、关键推理结果和核心整合数据必须写入可溯源的答案锚点。简单信息匹配和无法穷尽的细节无需逐项列出答案。
- 选择锚点时优先覆盖决定产物质量的关键结果、核心论据与结论关系，以及支撑整体交付的结构骨架。
- 已核实正确的数值、公式、术语和参考结论应保留；专家的工作是核验和纠错，不能为了笼统化而删除锚点。
- 一般代码和数据分析任务中，深层质量权重不低于约 70%；文档写作、研究综述通常约 75%。只有纯格式转换等任务，表层合规才可提高到 50–60%。无创意或体验目标时，卓越性通常不超过约 10%。

## 修改分类

- 修改：修正专业错误、补充细节证据或答案锚点、消除歧义、明确评分条件，或在同一检查逻辑内补足必要内容。
- 新增：原有 Rubric 缺少独立的核心交付、关键业务逻辑或重大失败模式时，新增一条独立考点。
- 合并/删除：只处理检查对象和判断逻辑实质重复、与任务无关、虚构或无法修复的考点；不能把大量有效考点压缩为少数规则。
- 禁止无实质的换说法、无依据缩小范围、删除正确锚点，或为了增加数量把同一逻辑拆成琐碎项。

## 评分与证据

- 每个分数引用产物中的具体位置和事实；评分理由评价产物，不评价考点评估步骤。
- 评分方式优先使用二元判断（通过/不通过）。只有"覆盖多少、质量好坏、归因是否基本准确"这类复合判断才适合 0-1 梯度评分。
- 常见二元判断场景：是否有某文件、某数字、某 DOI、某章节、某明确规定——这些都不需要五档，直接改通过/不通过更稳。
- 每条 Rubric 的评分标准必须与对应 R 结合，不能泛泛而谈或使用通用标准。
- 检查“做了动作”不等于检查“内容质量合格”。对公式、推理和专业方案，应判断其方法、结果与业务逻辑是否可靠。
