## 题目

任务概述：
为 networkx 增加一组互相一致的公开多目标（帕累托）最短路径 API：核心查询 nx.pareto_paths(G, source, target, weight="weight", cost="cost", *, max_cost=None, max_weight=None)，只返回配对结果的 nx.pareto_frontier(...)，以及可变图上的索引 nx.ParetoIndex(G, source, weight="weight", cost="cost")。它们在同一张图上同时考虑两条可加属性，返回 source 到 target 之间所有互不支配的 (cost, weight) 组合，并为每个组合给出恰好实现该组合的简单路径；索引还支持在图上增删边后继续查询，且结果必须与「对当前图直接调用函数式入口」完全一致。
改动是新增一个公开算法模块及其导出（三个入口）。其一，签名：nx.pareto_paths(G, source, target, weight="weight", cost="cost", *, max_cost=None, max_weight=None)；nx.pareto_frontier(...) 同签名但只返回排序后的 (cost, weight) 列表；nx.ParetoIndex(G, source, weight="weight", cost="cost") 提供 pareto / frontier / update_edge / remove_edge / reset / graph。其二，两条属性名可配置，且既可为属性名字符串也可为可调用对象 f(u, v, data) -> number。其三，pareto_paths 返回 record 列表，每条为 {cost, weight, path}，path 为简单路径，首尾为 source 与 target，沿路径属性之和精确等于声明的组合；pareto_frontier 必须恒为 pareto_paths 的 (cost, weight) 投影。其四，集合语义：被支配组合不得出现，可达的非支配组合不得遗漏；支配为分量均不大于且至少一项严格更小；且前沿集合与边的插入顺序无关。其五，排序与边界：按 cost 升序、cost 相同时按 weight 升序；source 等于 target 返回仅含零属性单条记录；不可达与节点缺失分别抛现有的 NetworkXNoPath 与 NodeNotFound；被上界挡空返回空列表；负属性抛 ValueError；多重图抛 NetworkXNotImplemented。其六，索引语义：构造时对图做快照且不修改调用方图；任意 update_edge / remove_edge 序列后，pareto / frontier 的结果必须等于对当前索引图直接调用函数式入口的结果（含空结果与异常种类）；remove_edge 对不存在的边抛 NetworkXError；reset 恢复构造时快照。其七，兼容与不变量：新 API 完全附加，不改变任何既有算法、导出或异常的行为；函数式入口是纯函数，同一输入重复调用结果完全一致。

在 networkx 中实现并导出三个互相一致的公开入口：

- nx.pareto_paths(G, source, target, weight="weight", cost="cost", *, max_cost=None, max_weight=None)
- nx.pareto_frontier(G, source, target, weight="weight", cost="cost", *, max_cost=None, max_weight=None)
- nx.ParetoIndex(G, source, weight="weight", cost="cost")

语义契约（全部为可观察行为）：
1) 每条边带两条可加属性（默认名 cost 与 weight）。边缺少某条属性、或该属性为 None 时按 0 计。
2) 返回 source 到 target 之间所有【非支配】的 (cost, weight) 组合。支配定义为：(c1, w1) 支配 (c2, w2) 当且仅当 c1 <= c2 且 w1 <= w2 且 (c1 < c2 或 w1 < w2)。返回中不得出现被支配的组合，也不得遗漏任何可达的非支配组合。
3) pareto_paths 返回列表，元素是字典 {cost, weight, path}；path 必须是【简单路径】（同一节点不重复出现），首元素为 source、末元素为 target，并且沿 path 累加两条属性必须【精确等于】该记录声明的 cost 与 weight。
4) 结果按 cost 升序排序；cost 相同时按 weight 升序。
5) source == target 时返回单条 {"cost": 0, "weight": 0, "path": [source]}。
6) source 或 target 不在 G 中时抛 NodeNotFound。target 在 G 中但与 source 不连通时抛 NetworkXNoPath。
7) 若可达但不存在任何同时满足 max_cost 与 max_weight 上界的路径，返回空列表 []（不抛异常）。上界只用于过滤候选路径，不得改变其余语义，也不得因剪枝而遗漏仍在上界内的非支配组合。
8) 路径中出现负的 cost 或 weight 时抛 ValueError。
9) 多重图（MultiGraph / MultiDiGraph）不支持，抛 NetworkXNotImplemented。
10) 必须同时支持有向图与无向图。
11) 纯函数：函数式入口不得修改 G（节点集、边集、边属性都不变）；对同一输入重复调用必须返回完全相同的结果（含顺序）。
12) weight 与 cost 既可以是属性名字符串，也可以是可调用对象 f(u, v, data) -> number。三个入口都必须支持两种写法，且对同一张图两种写法必须给出完全相同的 (cost, weight) 集合与顺序。
13) pareto_frontier 只返回排序后的 (cost, weight) 二元组列表（不返回见证路径），并且必须恒等于 [(r["cost"], r["weight"]) for r in pareto_paths(...)]——在带与不带双上界时都成立。其边界与异常语义与 pareto_paths 完全一致。
14) 前沿集合与图的构造顺序无关：同一批节点与边（属性完全相同）无论以何种顺序插入，pareto_paths 与 pareto_frontier 给出的 (cost, weight) 集合与顺序必须完全相同。
15) ParetoIndex(G, source, ...) 是可变图上的索引。构造时必须对传入图做快照，【不得修改调用方的 G】；并以 source 为起点。其接口：
    - idx.pareto(target, *, max_cost=None, max_weight=None)：结果必须与 nx.pareto_paths(idx.graph, source, target, ...) 完全相同。
    - idx.frontier(target, *, max_cost=None, max_weight=None)：同上，对应 nx.pareto_frontier。
    - idx.update_edge(u, v, **attrs)：新增或覆盖这条边（必要时补建节点）。
    - idx.remove_edge(u, v)：删除该边；若该边不存在则抛 NetworkXError。
    - idx.reset()：把索引图恢复为构造时的快照。
    - idx.graph：当前索引图，必须反映全部已执行的 update_edge / remove_edge。
    任意 update_edge / remove_edge 序列之后，两条查询的结果都必须等于「对 idx.graph 直接调用对应函数式入口」的结果，包括空结果与抛出的异常种类。
16) 三个入口的异常语义完全一致：缺失节点 NodeNotFound；连通但无路径 NetworkXNoPath；负属性 ValueError；多重图 NetworkXNotImplemented。ParetoIndex 在构造时就校验 source 是否存在与是否为多重图；对不存在的 target 查询时同样抛 NodeNotFound。
17) 性能：在 3000 个节点、12000 条边的随机有向图上，构造索引、执行一次 update_edge 与一次 remove_edge、再完成一次 pareto 与一次 frontier 查询，合计须在 30 秒内返回；在 4000 个节点、16000 条边的随机有向图（cost 与 weight 均为 0..20 的整数）上，单次 pareto_paths 调用须在 30 秒内返回。退化为枚举全部简单路径的实现无法满足该要求。

判定依据只有可观察行为：返回组合的集合与顺序、每条 record 的 path 是否为简单路径且属性精确吻合、frontier 与 paths 的投影关系、索引在变更前后与全量重算的一致性、边界输入下的返回值或异常种类、以及纯函数与规模要求。不与任何参考实现比对。

任务难点：
- 支配语义的精确实现：必须区分「被支配」与「完全相等」。若只按严格改进去剪枝，等价组合会被反复展开，在零属性环上导致结果重复乃至不终止；若剪枝过强，又会静默丢掉前沿上的组合。前沿必须既不重不漏。
- 给出精确见证：每条 record 必须配一条简单路径，其两条属性之和精确等于声明的组合。由于搜索过程可能走过带环的路线，必须能还原出剥离环之后仍然属性不变的简单路径；而 witness 又不能因为随意取边而算错属性。
- 上界过滤与边界行为的相互作用：max_cost / max_weight 的剪枝必须保持完备性（上界内仍在前沿的组合不能丢），同时要分别处理 source 等于 target、节点缺失、不可达、可达但被上界挡空这四种不同结局，并给出各自规定的返回值或异常类型。
- 规模与确定性：小图可以正常枚举，但数千节点/上万条边的实例无法承受朴素枚举，必须设计有效的多标号搜索与支配剪枝；同时输出顺序与重复调用结果必须完全确定，不能依赖字典遍历或集合顺序。
- 三入口的一致性：frontier 必须恒为 paths 的 (cost, weight) 投影，不得出现「一个入口按上界过滤、另一个不过滤」这类漂移；索引的查询又必须与函数式入口逐项相同。任何在两个入口之间各自实现一套逻辑的做法，都会在边界与异常上分叉。
- 索引在变更后的正确性：update_edge / remove_edge 之后必须给出与全量重算一致的结果。带缓存或增量维护的实现最容易在这里出错——删掉一条曾参与最优解的边、或覆盖一条端点相同而属性不同的边之后，陈旧结果会被继续返回；同时构造索引不得改动调用方传入的图。
- 可调用属性与顺序无关性：weight / cost 允许是可调用对象，三个入口都要统一解析，且与属性名写法结果一致；此外前沿集合必须与边的插入顺序无关，这要求支配剪枝与结果排序都不依赖邻接表或字典的遍历顺序。

# networkx 多目标帕累托最短路专家经验

本任务要在 networkx 里新增一组公开接口：核心查询 `nx.pareto_paths(G, source, target, weight="weight", cost="cost", *, max_cost=None, max_weight=None)`、只返回配对的 `nx.pareto_frontier(...)`、以及可变图上的索引 `nx.ParetoIndex(G, source, weight="weight", cost="cost")`。同一张图上同时优化两条可加属性，返回起终点之间**所有互不支配**的 (cost, weight) 组合，并为每个组合交付一条**恰好实现该组合**的简单路径；索引还要求在图上增删边后继续查询，且结果与"对当前图直接调用函数式入口"完全一致。难点不在于"写两层循环"，而在于把支配语义、见证还原、边界结局、规模要求、**三入口一致**与**索引变更**六件事同时想清楚。下面按六条真正需要推理的难点展开。

## 共享方法

把问题看成一堆**标签**在图上沿边传播：每个标签记录（当前 cost、当前 weight、所在节点，以及它是从哪个标签扩展出来的）。总原则是：**只要两个标签到达同一节点，而其中一个的两项属性都不大于另一个，属性较大的那个就没有继续扩展的价值**——因为它此后无论怎么走，都不可能变回更好。这条简单的剔除规则是整个解法的基础，也是绝大多数错误的发生地。

沿着这条原则往下的每一步，都要同时问两个问题：这一步剔除是否**漏**了可能更好的路线（完备性）；这一步保留是否**多**了永远不会更优的路线（剪枝有效性）。

---

## 难点一：支配语义必须区分「更差」和「相等」

### 契约模型
需要稳定推导的事实只有一件：到达同一节点的标签之间，只有当两个标签的两项属性**都不大于**对方、且至少一项**严格更小**时，才构成支配关系；若两项**完全相等**，它们对后续扩展完全等价。

### 冲突关系
这里最容易出错的不是"漏判支配"，而是"漏判相等"。如果只用严格更小来判定支配，那么两项完全相同的标签会被当成新的、值得保留的东西反复入队；一旦图里存在两条属性全为 0 的环，这个过程**不会终止**，或者会产出巨量重复标签。反过来，如果剔除时只看单项更优（例如只看 cost 更小），就会把真正位于前沿上的组合误删，导致结果**缺失**。

### 决策方法
剔除的判据就用支配定义本身，并且把"相等"一并归入可剔除：已有标签两项都不大于新标签时，新标签不再入队。淘汰已有标签时同理，两项都不大于才淘汰。不要用"严格更小"作为唯一的剔除条件，也不要用单项比较代替分量比较。

### 反例历史
一个典型故障是：零属性的双向边构成环时，标签无穷增殖，程序不结束或内存爆掉；另一个故障是前沿少了一整段，原因是把"cost 相同、weight 更小"的标签错当成互不支配而同时保留，随后又在另一处按单项剪枝删掉了正确的那一个。

### 验证思路
构造含两条属性全为 0 的环的图，确认调用能迅速结束且返回的前沿规模有限；构造同 cost 不同 weight、以及同 weight 不同 cost 的路线，确认两者中只有不被支配的那个出现在结果里。

## 难点二：见证路径必须简单且属性精确

### 契约模型
每条记录都需要一条**简单路径**（同一节点不重复），首元素为起点、末元素为终点，并且沿路径累加两条属性必须**精确等于**该记录声明的 cost 与 weight。这两条要求是独立的：路径合法不代表属性对得上，属性对得上也不代表路径简单。

### 冲突关系
搜索过程中到达终点的标签链**可能带环**。要交付的是简单路径，因此必须先把节点序列还原出来再剥离环。这里存在一个容易被忽略的取舍：剥环会不会改变属性？答案是可以安全依赖一个性质——对于**真正位于前沿上**的组合，剥掉环之后两项属性之和不会变小；而如果变小了，说明原组合本就被剥环后的路线支配，那它根本不该出现在前沿里。也就是说，只要正确处理前沿，剥环不会破坏属性精确性。

### 决策方法
沿标签的前驱链反向还原节点序列，再自前向后去掉重复节点构成的环，保持首尾不变。还原完成后必须**重新累加**一次属性做核对，不要直接沿用搜索时记录的数值：属性名、多重边或缺失属性的默认值都可能让原始数值与最终路径不一致。

### 反例历史
常见错误有两种：一是直接把带环的标签链当作路径返回，违反简单路径要求；二是剥环之后没有重新核对属性，遇到属性缺省或属性名不同的边时给出的数值与实际路径对不上。

### 验证思路
在含环的图上检查每条见证是否有重复节点；对每条见证独立重算两条属性之和，确认与声明的数值完全相等；对缺少属性字段的边确认其按 0 参与计算。

## 难点三：上界过滤与四种边界结局

### 契约模型
上界（`max_cost` / `max_weight`）是**过滤条件**：一旦某条标签的累计属性超过上界，它和它的后继都不可能再满足上界。边界上存在四种必须区分的结局：起点等于终点、节点根本不在图中、节点在但不可达、可达但被上界全部挡掉。

### 冲突关系
最大的冲突是"剪枝"与"完备"的张力。按上界丢弃超限标签是安全的，但**不能**因为它已经在队列里被剪掉，就把仍在上界内的组合也一并丢掉。另一组冲突是四种结局的**返回形式不同**：起点等于终点要给出一条零属性的记录；节点缺失与不可达分别对应两类不同的既有异常；可达但被上界挡空要给空列表而**不是**异常。把这几件事混成同一个分支，是最常见的失分点。

### 决策方法
先在入口处把"节点是否存在"与"是否存在路径"判定清楚，再谈过滤：起点等于终点直接给出零属性单条记录；节点缺失抛既有节点异常；可达性先判，不可达抛既有"无路径"异常；上界只在扩展与最终收集时生效，被上界挡空时返回空列表。属性为负值时前面的"越扩展越差"前提不成立，必须在遍历中显式拒绝并抛出参数错误。多重图由于平行边会让"一条节点序列"对应多组属性，契约直接声明不支持并抛出既有异常。

### 反例历史
典型错误包括：把"被上界挡空"也当成异常抛出；把节点缺失与不可达混用同一个异常；以及在没有路径时仍去收集上界结果，导致异常类型错乱。

### 验证思路
分别构造起点等于终点、目标节点不存在、目标存在但不可达、可达但上界极小这四种输入，逐一确认返回值或异常类型；再构造负属性与多重图输入，确认抛出规定的异常。

---

## 难点四：规模与确定性

### 契约模型
小图上直接枚举所有简单路径也能得到正确结果，但"数千节点、上万条边"的实例会立刻爆炸。可依赖的事实是：前沿规模通常远小于路径总数，因此**按属性驱动扩展、并对到达同一节点的标签做支配剔除**，可以把搜索规模压到与前沿和标签数同阶。此外输出必须是**确定**的：前沿按 cost 升序、cost 相同按 weight 升序返回，重复调用同一输入必须给出完全一致的结果与路径。

### 冲突关系
冲突在于"正确"与"可行"的取舍：只求正确可以穷举，只求快速可以近似，但契约同时要求精确与时限。另一处冲突是确定性：如果把标签放在集合或字典里直接倒出来，顺序会随插入历史变化，重复调用就可能不一致。

### 决策方法
用能按属性大小取最小标签的优先队列驱动扩展，每扩展一步对目标节点做一次支配剔除，把被支配与重复的标签就地丢弃；收集结果时显式按 (cost, weight) 排序后再输出，不要依赖容器遍历顺序。`max_cost` / `max_weight` 类的上界应在入队前就用于剪枝，避免把注定超限的标签继续扩展。

### 反例历史
一个典型故障是把"队列入队"当作"标签最终保留"，于是被支配的标签出队后仍参与扩展，规模失控；另一个故障是结果顺序随字典遍历变化，同一输入两次调用输出不同。

### 验证思路
在上万条边的图上确认能在时限内返回；对同一输入连续调用多次，确认结果（含顺序与路径）逐次完全一致；构造前沿较大的小图，确认返回顺序严格按 cost 升序、weight 递减。

---

## 难点五：三个入口必须是同一套语义

### 契约模型
投影入口 `pareto_frontier` 只返回排序后的 (cost, weight) 配对列表，并且必须**恒等于** `[(r["cost"], r["weight"]) for r in pareto_paths(...)]`——在带与不带双上界时都成立。索引入口 `ParetoIndex.pareto / .frontier` 也必须与其对应的函数式入口逐项相同。可依赖的事实是：三者描述的是同一个数学对象，只在"是否附带见证路径"上不同。

### 冲突关系
最大的冲突是"看起来省事"与"语义一致"的取舍。若为投影入口另写一遍逻辑（例如为了省掉见证还原而单独做一次搜索），就极可能出现「一个入口过滤了上界、另一个没有」「一个在挡空时返回空列表、另一个抛异常」这类分叉。可调用属性（把 `weight` / `cost` 写成 `f(u, v, data)`）同理：如果只在主入口支持、或在两处各自实现一遍解析，那么"缺失属性按 0"这条规则会只在其中一种写法或其中一个入口下成立。

### 决策方法
把搜索与"是否收集见证"分成两个层次：核心求解返回统一结构，三个入口共用它，投影入口只做 `(cost, weight)` 抽取。属性解析集中到一处：先判断 `weight` / `cost` 是否可调用，是则包装成 `f(u, v, data)` 形式，否则包装成按名字取值且缺失按 0 的形式，之后整个求解过程只跟统一的读取函数打交道。上界、异常判定等全部放在共用层，避免任何入口有独立分支。

### 反例历史
典型故障有三种：投影入口与主入口在某组上界下给出不同的集合；把可调用属性只在主入口解析，导致索引入口对函数写法直接报错或把函数对象当成属性名；以及"挡空"在一个入口返回空列表、在另一个入口抛异常。

### 验证思路
对同一批随机图，逐例比对 `pareto_frontier` 与 `pareto_paths` 的配对投影，并且**带与不带**双上界都要比；用属性名写法与函数写法各跑一遍，确认结果集合与顺序完全一致；把"缺失属性按 0""挡空返回空列表""负值抛错"三类边界在三个入口上各验一遍。

## 难点六：索引在改边之后仍要与重算一致

### 契约模型
`ParetoIndex` 在构造时对传入图做**快照**（不得改动调用方的图），并支持 `update_edge` / `remove_edge` / `reset` / `graph` 与两类查询。可依赖的事实是：只要"查询结果 == 对当前索引图直接调用函数式入口"，索引就是正确的——因此本题不强制做增量更新，**每次查询基于当前图重新求解也是合格解**。

### 冲突关系
冲突集中在"缓存"与"正确"之间：缓存能省时间，但只要失效条件写漏一个，就会返回陈旧结果；而不做任何缓存又会被误认为"不够增量"。三处最容易出错的具体场景是：删掉一条曾参与最优解的边（旧前沿必须被重算掉）；覆盖一条端点相同、属性不同的边（属性必须真的被替换，而不是叠加或忽略）；以及构造索引时直接持有调用方的图对象并就地修改（违反"不修改传入图"）。

### 决策方法
让索引持有一张**自己的**图（构造时复制），所有变更都作用在这张图上；查询统一走与函数式入口相同的求解过程。若确实要做缓存，缓存键必须包含"当前图的状态"与"本次查询的两个上界"，且任何 `update_edge` / `remove_edge` / `reset` 都必须使缓存失效。`remove_edge` 对不存在的边要显式抛出既有的边错误，`reset` 要把图恢复为构造时的快照。

### 反例历史
常见故障包括：删边后仍返回旧前沿；覆盖同一条边的新属性不生效；查询时复用了上一次的某个上界结果；以及构造索引后调用方的图被悄悄加了一条边。

### 验证思路
连续做若干次增删边，每一步都把索引查询结果与"对当前图重新计算"逐项比对（含空结果与异常种类）；每次变更后确认最初传入的那张图仍然完好；对不存在的边调用删除确认抛出边错误；变更后 `reset` 再确认结果回到构造时状态；同一目标用不同上界连续查询两次，确认第二次不会复用第一次的结果。

## 收尾自查

实现完成后至少确认六件事：其一，任意两个到达终点的组合之间不存在支配关系，且可达的非支配组合没有遗漏；其二，每条见证路径无重复节点、首尾正确、两条属性精确吻合；其三，起点等于终点、节点缺失、不可达、上界挡空这四种边界各自返回规定的结果或异常，负属性与多重图抛出规定的异常；其四，在数千节点、上万条边的图上能在时限内返回，且同一输入重复调用结果完全一致；其五，只返回配对的入口与主入口在带/不带双上界时都逐项一致，可调用属性与属性名写法结果相同，且把同一批边以不同顺序插入后前沿不变；其六，索引在若干次增删边之后与"对当前图重新计算"逐项一致，`reset` 能回到构造快照，并且整个过程没有改动最初传入的那张图。只要这六件事守住，新增能力就能被正确观测，且不会影响既有算法。
