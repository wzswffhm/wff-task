## 题目

任务概述：
为一个 SQLite 索引加磁盘值文件的持久化缓存引入多键原子写批次：批次内的写入先进入暂存区而不进入缓存索引，退出批次时一次性提交；失败、异常或进程崩溃则整体丢弃，并保持索引与磁盘文件一致、不留下未被索引引用的文件。
改动集中在四处。其一，公开入口：新增 cache.batch() 上下文管理器，批次内的 set、__setitem__、add、delete、__delitem__、pop 进入暂存区；在批次内再次调用 batch() 抛出 RuntimeError。其二，可见性：暂存内容对打开批次的那个缓存句柄可见（读己写），对同一进程的其他句柄和其他进程的句柄完全不可见；len(cache) 反映该句柄可见的条目数，而迭代接口只反映已提交内容。其三，提交与丢弃：正常退出时在单个事务内把暂存内容写入缓存索引、删除被覆盖的旧值文件并清空暂存区；异常退出时删除暂存写入的值文件并清空暂存区；下一次打开同一个缓存目录时，若发现上一次进程留下的未完成批次，必须丢弃它并回收其文件。其四，接入时机：暂存条目在提交前不参与过期、按标签淘汰、计数与迭代，提交后一次性全部生效；同一键在批次内被多次写入或删除时以最后一次操作为准。批次内不支持的操作（clear、touch、incr、decr、push、pull、evict、expire、cull）必须抛出 RuntimeError 而不是部分生效。现有公开函数签名和行为不得改变，构建与测试环境不允许联网。

在 diskcache 的 Cache 上实现多键原子写批次。提供 cache.batch() 上下文管理器：批次内通过 set、cache[key] = value、add、delete、del cache[key]、pop 执行的写入进入暂存区，不进入缓存索引。暂存内容必须对打开批次的句柄可见（读自己的写入，len(cache) 计入它们），并且对同一进程的其他 Cache 句柄和其他进程的 Cache 句柄完全不可见；len() 之外的迭代接口只反映已提交内容。正常离开 with 块时，所有暂存写入必须同时生效：一次性写入缓存索引、删除被覆盖的旧值文件；此时其他句柄才能读到它们。以异常离开 with 块时，所有暂存写入必须被丢弃，缓存回到进入批次前的状态，且不得留下没有被索引引用的值文件。进程在批次内被杀掉时同样如此：之后任意进程再次打开该缓存目录，未完成批次必须被丢弃、其文件必须被回收，已提交的内容必须原样保留，cache.check() 不得报告未知文件。暂存条目在提交前不得参与过期、按标签淘汰、条目计数与迭代，提交后必须立刻全部参与；批次内对同一个键先写入再删除、或先删除再写入时，以最后一次操作为准。批次内再次调用 batch() 必须抛出 RuntimeError；批次内调用 clear、touch、incr、decr、push、pull、evict、expire、cull 也必须抛出 RuntimeError，不能部分生效。批次期间不得阻塞其他进程对同一缓存目录的独立读写。现有公开函数签名与单一键操作的行为不得回归。判定依据是可观察行为：哪些值能被读到、条目计数、过期与按标签淘汰的结果、check() 的输出和磁盘上是否存在未被引用的文件，不与任何参考补丁比对。

任务难点：
- 确定暂存区的落点与提交跃迁：暂存写入必须对打开批次的句柄可见，同时对其他句柄和进程完全不可见，而提交必须是一次原子跃迁；把写入直接落到缓存索引再靠事务回滚，会在文件已经落盘而索引回滚时留下不一致，把整个缓存目录加全局写锁又会阻塞其他进程的独立写入。
- 处理崩溃切点与值文件生命周期：值文件写入并不在数据库事务之内，进程可能在写完文件之后、提交之前被杀掉，也可能死在提交事务中间；实现必须保证重新打开缓存时索引与磁盘一致、未完成批次被丢弃、被覆盖的暂存文件与旧值文件都被回收，且不给正在使用同一目录的其他进程造成破坏。
- 把握暂存条目接入缓存语义的时机：暂存条目在提交前不能参与过期、按标签淘汰、条目计数和迭代，提交后必须一次性全部参与；同一键在一个批次内被反复写入和删除时，最终结果必须以最后一次操作为准，并且不能因为中间步骤留下多余文件或错误计数。
