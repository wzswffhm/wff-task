# 连续作业循环

与 SKILL「连续作业循环」配套：整题交付完成后自动开下一题。

## 触发条件

当前作业同时满足：

1. delivery-checklist / P0 全过  
2. zip 已写出（如 `task/<task-name>.zip`）  
3. 飞书回写成功（文本字段 + zip 附件 + `状态=已提交`，见 [feishu-delivery.md](feishu-delivery.md)）  
4. 用户未要求「做完先停」

→ 查下一题；有则开，**无则停**（见下）。

## 下一题筛选（硬条件）

飞书多维表中同时满足才可执行：

| 字段 | 必须值 |
|------|--------|
| **标注员** | **林丹** |
| **状态** | **已领取** |

另：须仍是可做的待交付题（例如尚未「已提交」/仍缺合规交付；以表内实际可执行含义为准）。

**没有命中上述条件的作业 → 连续循环立刻停止。**  
短报一句即可，**禁止**反复刷飞书、轮询等待、空转重试「看看有没有新题」。

### 来源优先级

1. 用户本会话给出的 `zq*` 队列（FIFO）——**仅当该行也是 林丹 + 已领取** 才开；否则跳过并说明  
2. 飞书：`标注员=林丹` 且 `状态=已领取` 的下一条待交付  
3. 都没有 → **停止**，不要追问刷表；等用户再说「继续」或点名作业

## 新题启动清单

```text
[ ] 确认上一题 zip 路径已告知，且飞书状态=已提交
[ ] 查询：标注员=林丹 AND 状态=已领取；无结果 → 停止连续循环
[ ] 读取该行：作业ID / 领域 / 子领域 / 任务类型 / 语言
[ ] 新建目录名：<作业ID>-<语义>-<语言>-<题型>-<YYYYMMDD-HHMM>
[ ] harbor tasks init codingrl/<新目录名> --tasks-dir task
[ ] 写 task.toml 对齐飞书；国内镜像 Dockerfile 模板可复用
[ ] 选题（避免与刚失败备份里同一太易工程，除非用户指定）
[ ] 先接 quality.toml + rewardkit，再校准与难度门
[ ] 交付后再走 feishu-delivery 全套回写 → 再按本筛选开下一题或停止
```

## 同作业换仓 / 验证失败重开

仍属同一飞书作业 ID，**不算**「完成去下一题」。必须：

1. 保留旧 `task/<旧目录>/`（勿覆盖）
2. 新建 `task/<基式>-<YYYYMMDD-HHMM>/` 从头做
3. 同 ID 下 **最新时间戳目录 = 默认成功 / 查阅对象**

## 禁止

- 上一题 P0 未过就开下一题「先做着」  
- 选到标注员不是林丹、或状态不是「已领取」的行  
- **无题可做时继续刷飞书 / sleep 重试 / 循环 list**  
- 覆盖上一题目录或删掉上一题 zip/成功 jobs  
- 换仓时清空同名目录重做，或不加分钟时间戳  
- 把换仓（同作业失败备份）当成「完成去下一题」  
- 连续开题时并行多个 16×8 打爆 Docker（默认串行一题；用户明确要求并行再开）

## 串行与资源

- **默认一题做完再开下一题**（含难度门占用的并发 8）  
- OrbStack 网络/磁盘告警时先清理旧 trial 容器与悬空网络，再开下一题  
- API 限流时降低并发或排队，不要静默重试打满额度

## 用户口令

| 用户说 | 行为 |
|--------|------|
| （默认）/ 连续开题 / 一直做 | 交付后按「林丹+已领取」开下一题；无则停 |
| 停 / 先别开新题 / 做完这题停 | 交付后结束循环 |
| 先交再做 / 等质检 | 交付后暂停，等用户发话再查 |
| 继续 / 再看看有没有题 | **再查一次**飞书；仍无则停，不要进入轮询 |
| 并行做两题 | 仅当宿主机与 API 允许时开第二题；各自独立难度门早停 |
