## 改动内容

**`nbdsrv.h`** — `CLIENT` 结构新增 4 个字段:`difffile`(diff 文件 fd)、`diffname`(文件名,断开时删除用)、`diffmap`(脏页号 → diff 文件内偏移的哈希表)、`diff_lock`(保护这三者的互斥锁,因为请求由 4 线程池并发处理)。

**`nbd-server.c`**:

| 函数 | 作用 |
|---|---|
| `open_diff()` | 连接建立时为 COW 导出创建私有 diff 文件;配了 `cowdir` 就放那里,否则放主文件同目录;文件名含 PID 避免并发连接互踩;`sparse_cow` 时 ftruncate 成导出大小(数据按原偏移存),否则块追加到文件末尾 |
| `close_diff()` | 挂进 `finalize_client()`,线程池排空后执行:unlink diff 文件、释放状态。`NBD_CMD_DISC` 和连接异常断开都走这条路 |
| `masterexpread()` | 原 `rawexpread()` 主体,只读主文件 |
| `cowexpread()` | 按 4K 页读取:diff 里有的页优先从 diff 读,其余读主文件 |
| `cowexpwrite()` | 写入重定向到 diff,绝不碰主文件;整页直接写,跨页/不对齐的部分页先从 diff(已脏)或主文件(未脏)读回旧内容做读-改-写,保证页内其他数据不丢;`sync`/FUA 语义作用于 diff fd |
| `rawexpread()`/`expwrite()` | 检测 `F_COPYONWRITE` 分发到上述路径 |

`write_zeroes` 经由 `expwrite` 自动继承 COW;TRIM 对 COW 原本就返回成功且不动主文件;COW 导出原本就不通告 `CAN_MULTI_CONN`。配置解析(`copyonwrite`/`cowdir`/`sparse_cow`/`-c`)都是现成的,未改动。
