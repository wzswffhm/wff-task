## 改动内容

**`nbdsrv.h`** — `CLIENT` 增加每连接的 COW 状态：`difffile`（diff 文件 fd）、`difffilelen`（diff 文件当前长度，新块从这里追加）、`difffilename`（断开时要删除的文件名）、`difmap`（脏块号 → diff 文件内偏移的映射表）。字段名与仓库自带单测 `tests/code/trim.c` 的引用保持一致。

**`nbd-server.c`**：

- **建立连接**（`setup_cow`，由 `setupexport` 调用）：COW 导出时主文件只以只读方式打开；diff 文件建在 `cowdir`（若配置）或主文件同目录，`O_EXCL` 创建防并发连接撞名；`sparse_cow = true` 时把 diff 文件扩到导出大小、块按自然偏移存放，否则新脏块映射到 diff 文件末尾（两种模式语义照 man page）。
- **写路径**（`expcowwrite`，`expwrite`/WRITE_ZEROES 分流）：按 4096 字节块只写 diff 文件，绝不碰主文件；块第一次被部分写入时先把主文件里的原始块拷进 diff，保证块内容完整；`sync`/FUA 时同步 diff 文件。
- **读路径**（`rawexpcowread`）：脏块优先从 diff 文件返回，未写的块读主文件。
- **flush**：`expflush` 同时 fsync diff 文件。
- **断开连接**（`cleanup_cow`，挂到 `finalize_client`）：unlink diff 文件、关 fd、释放映射表，主文件保持原样；协商失败、客户端重选导出等路径也做了清理，不留残余。
- 请求线程池是多线程的，用已有的 `export_lock` 读写锁保护脏块表（读加读锁，分配块/写加写锁）。

TRIM 对 COW 导出已有 no-op 处理、配置解析已禁止 `copyonwrite` 与 `splice`/`waitfile` 混用，这两条路径无需改动。
