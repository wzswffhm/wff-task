## 改动

**`nbdsrv.h`** — CLIENT 增加 4 个会话级 CoW 字段(名字与 `tests/code/trim.c` 已有的引用一致,该单测此前编译不过):`difffile`(diff 文件 fd)、`difffilename`、`difffilelen`、`difmap`(块号→diff 内偏移的 GHashTable)。

**`nbd-server.c`**:

- **建立**:`setupexport()` 里 CoW 导出的主文件改为只读打开(永不写主文件,这也让 man 页描述的 "主文件目录不可写 + cowdir" 场景成立);导出大小确定后调 `setup_cow()` 创建 diff 文件——位置取 `cowdir`,否则主文件同目录,名字 `<basename>-<pid>-<n>.diff`(每连接唯一)。`sparse_cow = true` 时按 man 页语义把 diff 文件 ftruncate 到导出大小做稀疏文件;缺省的稠密模式则把每个新写块连同块号追加到 diff 文件末尾。
- **写**:`rawexpwrite()` 分流到 `cow_write()`: touched 的 4096 块先 copy-up(从主文件/diff 取整块、尾部不足补零),合并写入数据后记入 diff;已脏块直接原位覆写。F_SYNC/FUA 语义照旧作用在 diff 上。
- **读**:`rawexpread()` 分流到 `cow_read()`: 逐块查 `difmap`,脏块优先从 diff 返回,连续干净块合并成一次主文件读取。两条路径用 `client->export_lock` 读写锁保护(线程池 4 线程并发处理请求)。
- **断开**:`finalize_client()`(正常 NBD_CMD_DISC 和异常断连都会走到)新增 `cleanup_cow()`:关 fd、unlink diff 文件、释放映射表,主文件保持原样。
- **其余**:`expflush()` 同时 fsync diff;treefiles 模式下 CoW 也走只读 master;FLUSH/WRITE_ZEROES/TRIM 在 CoW 下行为正常(TRIM 维持原有 no-op)。
