## 问题根因
`F_COPYONWRITE` 标志、`copyonwrite`/`cowdir`/`sparse_cow` 配置项和 `-c` 命令行选项都已存在,但读写路径完全没有使用它们——写直接落到主文件(`rawexpwrite` → `pwrite`),读也直接读主文件,断开连接无任何清理。

## 实现(2 个文件)

**`nbdsrv.h`** — 给 `CLIENT` 增加每连接的 COW 状态(字段名与 `tests/code/trim.c` 期望的一致):
- `difffile` / `difffilename`:diff 文件句柄与路径
- `difffilelen`:非 sparse 模式下新块的追加位置
- `difmap`:`GHashTable`,记录"脏块号 → diff 文件内偏移"
- `difmap_lock`:保护上述状态(线程池默认 4 线程并发处理请求)

**`nbd-server.c`** — 新增 COW 核心函数并挂到现有路径:
- `setup_cow()`:建 diff 文件,命名 `<basename>.<pid>.diff`;有 `cowdir` 放 cowdir,否则放主文件同目录;sparse 模式 `ftruncate` 到导出大小(稀疏文件)
- `cleanup_cow()`:关闭并 `unlink` diff 文件、释放映射
- `cow_write()`:写入只进 diff 文件,绝不碰主文件;按 4096 字节块(`DIFFPAGESIZE`)处理,部分块用"读旧块→覆盖→整块写回",支持 FUA/`sync`
- `cow_read()`:先从主文件读,再用 diff 中已写块覆盖(脏块优先)
- 挂钩点:`rawexpwrite`→`cow_write`、`rawexpread`→`cow_read`、`expflush` 改为同步 diff、`finalize_client` 调 `cleanup_cow`、`setupexport` 主文件改只读打开并在末尾调 `setup_cow`、`get_filepos` 的 treefile 在 COW 下只读打开
