## 改动

**`treefiles.c`(新实现,原先是 stub)**
- 导出被切成 4096 字节块(TREEPAGESIZE),块号以 1024(TREEDIRSIZE)为基数展开成多级路径:中间目录 `TREEXXXX`、叶子块文件 `FILEXXXX`。树深取恰好覆盖 `filesize` 的最小层数(4MB 一层 `FILE0000..1023`;50MB 两层 `TREE0000/FILEXXXX`…)
- `open_treefile`:按需打开/创建块文件,目录用 `mkdir_path` 递归创建,创建路径有互斥保护
- `delete_treefile`:删除块文件(TRIM 时用)

**`nbd-server.c`**
- `setupexport`:treefiles 分支强制要求 `filesize`(树的深度由它决定),size 直接取配置值;与 multifile 同时给时 treefiles 优先(符合 man 文档)并告警
- 新增 `treeexpread`/`treeexpwrite`,在 `expread`/`expwrite` 入口分发:IO 按块边界切分落到对应块文件;读不存在的块返回全零,写时按需建文件;`expflush` 对 treefiles 直接成功(每请求开/写/关,无积压)
- 配置解析阶段拒绝 treefiles 与 copyonwrite / waitfile / splice 混用(这些路径会直接操作 export 数组,混用会崩),错误信息风格沿用现有的 cow+splice 等校验

**`nbdsrv.c` / `nbdsrv.h`**
- `exptrim` 加 treefiles 分支:整块被 trim → 删文件;部分 trim → 只把 trim 区域写零,文件保留
- CLIENT 增加 `treefiles_mutex`,新增错误码 `NBDS_ERR_CFILE_INVALID_TREEFILES`
