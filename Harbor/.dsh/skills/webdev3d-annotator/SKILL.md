# Webdev+3D 前端产物人工标注

## 角色边界

- 以独立标注员身份完成当前任务的完整评估。每个标注任务相互独立，不能参考或复用其他标注任务的结论。
- 本任务是"深度体验+多维度评估"模式：以原始提示词（Query）为基准，深度体验生成的3D前端产物，从多个维度进行全面分析，明确指出产物的不足与缺陷。
- 对每个标注任务承担完整的独立判断责任：应达到能够正确理解用户需求、识别核心要求并完成高质量评估的水平。不得把核心判断留给后续环节。
- 作为标注员，独立完成需求分析、产物体验、维度评估、问题定位和备注填写，形成可复核的完整作业结果；不要把核心判断留给用户或后续环节。
- 全部结果生成后交由用户统一确认。用户确认前，不提交、不推进任务，也不等待逐项人工确认。
- 对每个任务先独立判断需求是否合理。需求明显不合理、严重脱离真实业务逻辑或没有实际价值时，填写有依据的需求质量判断即可；不要继续评估产物。输入资源问题在需求判断阶段处理，不混入产物评估。
- 需求合理时，完成规则要求的全部评估维度：提示词匹配度、功能与交互、产物技术质量、美学与体验及其他维度。
- 只填写当前标注员自己的作业，不查看或采用其他标注员的结论。

## 开始前

- 从标注中心领取已分配数据；当前平台入口为标注任务页面。如页面提供具体任务地址，以页面任务为准，不要假定旧地址或默认任务仍有效。
- 先完整阅读 `references/Webdev+3d前端产物人工标注规则.pdf`、`references/标注流程指南.md`、`references/评估维度详解.md` 和 `references/质量标准手册.md`。标注规则覆盖最新的评估维度、评分标准、综合调整与最终评估流程；快速参考指南只用于快速定位问题，不能取代原文。
- 作业重点依次为：深度体验产物、逐维度评估、问题定位、填写备注；需求分析和总结是次要环节，但仍按流程完成。
- 使用用户的浏览器操作标注平台；浏览器操作前，先阅读并遵守浏览器控制技能。只允许一个代理控制浏览器、鼠标、键盘和剪贴板。
- 按流程对每个环节独立完成阅读、判断和填写：需求分析、产物体验、维度评估、问题定位、备注填写均不得以前一环节的泛化结论替代核验。必须实际打开并体验产物；3D网页、交互功能、动画效果等可视产物同时检查内容与渲染效果。
- 3D产物可能包含动态加载内容。打开后必须持续交互，直至功能不再新增，再判断完整性、交互逻辑、动画效果或功能覆盖；不得依据首次加载的静态内容推定产物完整规格。
- 若数据只提供部分文件，或缺少某类输入、输出，只评估实际提供的部分并写明缺失范围；不得为了填满流程虚构文件、过程或评估证据。若需求明确引用但资源不可访问，按资源缺失处理并按平台规则终止后续阶段。

## 标注流程

1. **需求分析（重点）。** 阅读 `query.md`，核对用户需求、目标场景、交付物、约束、使用价值和可执行性。出现严重需求不合理、场景不明确、约束冲突或没有实际价值时，选择需求模糊或缺乏实际价值并写清依据后终止后续流程；需求合理才继续。
2. **产物加载。** 在新标签页打开生成的HTML网页，确认页面加载正常、3D内容渲染正确、交互功能可用。资源缺失、内容缺失、格式错误或功能不可用而使任务不可执行时，选择对应资源标签、写明文件和缺陷定位后终止后续流程。
3. **深度体验（重点）。** 按照用户需求中的描述，全面体验产物的各项功能：3D场景、交互控制、动画效果、音效、视角切换等。记录每个功能的实际表现，与需求要求进行对比。体验过程中注意检查性能、流畅度、错误提示等技术指标。
4. **维度评估（最重点）。** 按照5个评估维度逐项检查，每个维度都要提供具体的问题定位和证据：
   - **提示词匹配度**：检查元素/特效缺失、风格偏离
   - **功能与交互**：检查镜头逻辑、动画/状态机、交互触发
   - **产物技术质量**：检查模型/物理硬伤、材质/渲染Bug、性能与健壮性
   - **美学与体验**：检查光影/渲染层次、色彩/后处理、布局
   - **其他**：自行补充其他维度的问题
5. **问题定位。** 对发现的问题进行精确定位：具体的功能模块、交互步骤、视觉元素、错误提示等。每个问题都要有明确的证据和影响程度评估。
6. **备注填写（重点）。** 为每个评估维度填写1-2句具体备注，说明：
   - 评测结果：在哪个维度出现了什么问题
   - 依据来源：题目要求、输入材料、html呈现
   - 问题类型：主要元素缺失、风格偏离、动画逻辑不符合常识、事实错误、编造、结构混乱、穿模、不可交付等
   - 影响程度：是否影响核心结论、是否导致无法交付、是否只是轻微瑕疵
7. **补充说明。** 如有其他维度问题，在补充备注中进行说明。
8. **核对、保存并等待用户确认。** 复读已填字段，确认评估结果、证据、问题定位和备注互相一致后保存当前标注作业，并将完整结果交由用户统一确认。没有用户明确授权时，不提交或推进在线任务。

## 评估维度详解

### 1. 提示词匹配度

- **元素/特效缺失**：检查Query要求的主体、环境、音效是否遗漏
  - 例如：用户要求"蓬松云层"，但产物中没有云层或云层效果不明显
  - 例如：用户要求"循环背景音乐"，但产物中没有音频或音频无法播放
- **风格偏离**：检查视觉与题材呈现是否偏离Query设定
  - 例如：用户要求"卡通风格"，但产物呈现写实风格
  - 例如：用户要求"明快的青蓝背景"，但产物使用暗色调
- **完整性检查**：核对用户需求中的所有要求是否都被满足
  - 列出需求中的所有关键要素，逐一检查产物中的对应实现

### 2. 功能与交互

- **镜头逻辑**：
  - 阻尼感：拖拽镜头时是否有平滑的阻尼效果
  - FOV缩放边界限制（Clamp）：缩放是否有最近/最远距离限制
  - 视角切换逻辑：第一人称/第三人称切换是否流畅
- **动画/状态机**：
  - 动画过渡是否平滑（无硬切）
  - 有无滑步现象
  - 状态切换是否符合逻辑（待机、行走、跳舞等）
- **交互触发**：
  - 键盘控制响应是否准确（WASD方向键等）
  - 鼠标控制响应是否准确（拖拽、点击等）
  - 交互逻辑是否完整（所有可交互元素都有响应）

### 3. 产物技术质量

- **模型/物理硬伤**：
  - 穿模（Clipping）：物体相互穿透
  - 破面：模型表面破损
  - 法线反转：模型显示异常
  - Z-fighting：深度冲突导致的闪烁
- **材质/渲染Bug**：
  - PBR通道失效：金属度、粗糙度等参数异常
  - 透明材质排序错乱：透明物体显示顺序错误
  - UV拉伸：纹理映射异常
- **性能与健壮性**：
  - 严重掉帧：FPS低于30
  - 报错卡死：JavaScript错误导致页面崩溃
  - 加载异常：资源加载失败或超时

### 4. 美学与体验

- **光影/渲染层次**：
  - 阴影表现：是否有柔边阴影、阴影是否正确
  - AO缺失：环境遮蔽效果是否开启
  - 光照平淡：光照是否有层次感
- **色彩/后处理**：
  - 色调映射（ToneMapping）：是否有电影级色调效果
  - 泛光（Bloom）：是否有适当的泛光效果
  - 曝光控制：高光区域是否过曝、暗部是否欠曝
- **布局**：
  - 物体大小：各元素比例是否协调
  - 排列布局：场景布局是否合理、美观
  - 视觉焦点：是否有明确的视觉引导

### 5. 其他维度

根据具体任务特点，自行补充其他需要评估的维度，例如：
- 音效质量：背景音乐、音效是否合适
- 响应式设计：在不同设备上的显示效果
- 无障碍性：是否考虑残障用户需求
- 创新性：是否有独特的创意或技术亮点

## 备注填写规范

### 好的备注示例

1. **提示词匹配度**：
   - "缺失Query要求的蓬松云层，产物中完全没有云层元素，导致场景氛围与用户期望不符。"
   - "'厚重写实'风格实际偏向卡通，材质质感和光照处理都与需求描述不一致。"

2. **功能与交互**：
   - "镜头缩放未做距离限制，导致可以缩放到星球内部，破坏了场景完整性。"
   - "状态机切换僵硬，从待机到行走的过渡有明显硬切，影响动画流畅度。"
   - "键盘控制响应延迟约0.5秒，影响交互体验的即时性。"

3. **产物技术质量**：
   - "飞行器与云层发生严重穿模，视觉上明显不专业。"
   - "金属材质的EnvMap反射缺失，导致金属感不真实。"
   - "粒子生成过多导致掉帧卡顿，FPS降至15以下。"

4. **美学与体验**：
   - "未开启AO导致物体缝隙处缺乏深度感，整体显得扁平。"
   - "缺乏电影级ToneMapping，高光区域严重过曝，丢失细节。"
   - "色彩搭配单调，主要使用蓝灰色系，缺乏视觉层次。"

### 不好的备注示例（应避免）

1. "感觉xxx维度好" - 过于主观，没有具体证据
2. "xxx功能看起来专业" - 没有具体说明哪里专业
3. "页面文字内容多" - 没有说明质量如何
4. "差不多，随便选" - 缺乏专业判断
5. 只复制规则文档或query - 没有自己的分析

### 备注结构要求

每个维度的备注应包含：
1. **问题陈述**：明确指出在哪个维度发现了什么问题
2. **证据定位**：具体说明问题出现在哪里（哪个功能、哪个步骤、哪个视觉元素）
3. **影响评估**：说明这个问题对整体体验的影响程度
4. **改进建议**（可选）：如果可能，提供简单的改进方向

## 特殊情况处理

### 专业背景不足

如果只是某个细节不确定，应尽量依据大众普遍价值观进行判断。如果缺少必要专业背景导致核心质量无法判断需跳过，则写明跳过原因，并联系项目负责人，不要仅凭某一维度优劣进行选择。

### 需求不明确

如果用户需求描述模糊或存在歧义：
1. 尝试从上下文推断用户意图
2. 如果无法推断，在备注中说明需求不明确的具体点
3. 基于最常见的理解进行评估
4. 在备注中注明可能的理解偏差

### 产物无法加载

如果HTML产物无法正常加载或渲染：
1. 检查网络连接和浏览器兼容性
2. 尝试刷新页面或更换浏览器
3. 如果仍然无法加载，在备注中详细说明加载失败的现象
4. 终止后续评估流程

### 功能部分可用

如果产物的部分功能正常，部分功能异常：
1. 分别记录正常和异常的功能
2. 对正常功能进行完整评估
3. 对异常功能记录具体现象和错误信息
4. 在备注中说明功能完整度

## 质量红线

标注时应特别警惕以下问题：

1. **只看排版或字数，不核对文件、数据和细节要求**
   - 不能因为页面看起来整洁就认为质量高
   - 必须核对每个功能是否真正实现

2. **只看呈现内容观感，不看提示词要求**
   - 不能因为视觉效果好就忽略需求匹配度
   - 必须对照用户需求逐项检查

3. **只看最终结论，不核对中间计算和证据链**
   - 不能只看表面效果就下结论
   - 必须检查实现过程中的技术细节

4. **看到模型输出很完整就默认正确，忽略编造、错算或误读**
   - 不能因为内容丰富就认为质量高
   - 必须验证内容的准确性和合理性

5. **将真实模型名称、路径或个人偏好带入判断**
   - 不能因为使用了某个知名框架就认为质量高
   - 必须基于实际效果进行判断

6. **因为某一维度总体更好，就把所有维度都选同一方**
   - 不能因为视觉效果好就认为功能也好
   - 必须对每个维度独立评估

7. **备注过于笼统，无法让复核者知道具体依据**
   - 不能写"感觉不错"这种模糊评价
   - 必须提供具体的问题描述和证据

8. **忽略性能问题**
   - 不能因为功能实现就忽略性能问题
   - 必须检查帧率、加载时间等性能指标

9. **忽略兼容性问题**
   - 不能只在一种环境下测试
   - 必须考虑不同浏览器和设备的表现

10. **忽略用户体验细节**
    - 不能只关注技术实现
    - 必须考虑交互的直观性和易用性

## 提交前检查

- 已独立完成任务，没有查看、比较或采用其他标注员的结论。
- 若需求不成立，已只完成有依据的需求质量判断；若需求成立，已检查所有评估维度及全部可访问的输入、输出文件。
- 每个维度的备注都有具体的问题描述、证据定位和影响评估。
- 已逐项检查用户需求中的所有明确要求，未将"部分提及"误判为完成；所有缺失内容均映射到相应维度的问题描述。
- 已确定任务主要质量维度，并按提示词匹配度、功能与交互、产物技术质量、美学与体验完成覆盖自查；每个维度均有对应的可验证问题定位。
- 每个备注都包含具体的证据和定位，没有使用笼统的"质量好""体验佳"等模糊表述。
- 已完整检查3D产物的动态加载内容，未依据首次加载的静态内容推定产物完整规格。
- 每个评估维度都有独立的判断和备注，没有相互矛盾。
- 已按流程完成需求分析、产物体验、维度评估、问题定位和备注填写，没有遗漏任何环节。
- 已保存完整、可追溯的标注作业，并交由用户统一确认；未在未获用户授权时提交或推进任务。
