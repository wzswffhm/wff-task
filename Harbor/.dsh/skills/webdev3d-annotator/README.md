# Webdev+3D 前端产物人工标注技能

## 概述

这是一个用于评估AI生成的3D前端网页质量的标注技能。该技能参考了Harbor Work skill的结构，专门针对Text-to-3D前端网页生成模型的评估需求而设计。

## 技能特点

1. **专业化**：专注于3D前端网页的评估，涵盖视觉、交互、技术、美学等多个维度
2. **系统化**：提供完整的标注流程，从需求分析到最终评估
3. **标准化**：建立统一的评估标准和质量红线
4. **实用化**：提供详细的示例和参考指南

## 使用方法

### 1. 阅读技能文件

首先阅读 `SKILL.md` 文件，了解完整的标注流程和要求。该文件包含：
- 角色边界和职责
- 标注流程详解
- 评估维度说明
- 备注填写规范
- 质量红线
- 提交前检查清单

### 2. 参考文档

根据需要阅读参考文档：
- **标注流程指南**：详细的步骤说明和时间分配
- **评估维度详解**：5个评估维度的具体评估方法
- **质量标准手册**：质量红线和常见错误
- **快速参考指南**：快速检查清单和问题定位

### 3. 查看示例

查看 `examples/示例标注结果.md` 文件，了解完整的标注结果格式和内容要求。

### 4. 开始标注

按照以下步骤进行标注：

1. **需求分析**：阅读query.md，理解用户需求
2. **产物加载**：在浏览器中打开HTML文件
3. **深度体验**：全面体验产物的各项功能
4. **维度评估**：按5个维度逐项评估
5. **问题定位**：精确定位发现的问题
6. **备注填写**：为每个维度填写具体备注
7. **核对保存**：检查并保存标注结果

## 评估维度

### 1. 提示词匹配度
检查AI生成的3D前端产物是否准确理解并实现了用户的原始需求。
- 元素/特效缺失
- 风格偏离
- 完整性检查

### 2. 功能与交互
检查3D前端产物的功能实现和交互体验是否符合预期。
- 镜头逻辑
- 动画/状态机
- 交互触发

### 3. 产物技术质量
检查3D前端产物的技术实现质量，包括模型、材质、渲染和性能。
- 模型/物理硬伤
- 材质/渲染Bug
- 性能与健壮性

### 4. 美学与体验
检查3D前端产物的视觉美感和用户体验。
- 光影/渲染层次
- 色彩/后处理
- 布局

### 5. 其他维度
根据具体任务特点，补充其他需要评估的维度。
- 音效质量
- 响应式设计
- 无障碍性
- 创新性

## 质量红线

标注时应特别警惕以下问题：

1. 只看排版或字数，不核对文件、数据和细节要求
2. 只看呈现内容观感，不看提示词要求
3. 只看最终结论，不核对中间计算和证据链
4. 看到模型输出很完整就默认正确，忽略编造、错算或误读
5. 将真实模型名称、路径或个人偏好带入判断
6. 因为某一维度总体更好，就把所有维度都选同一方
7. 备注过于笼统，无法让复核者知道具体依据
8. 忽略性能问题
9. 忽略兼容性问题
10. 忽略用户体验细节

## 备注填写规范

### 好的备注示例

**提示词匹配度**：
> "缺失Query要求的蓬松云层，产物中完全没有云层元素，导致场景氛围与用户期望不符。"

**功能与交互**：
> "镜头缩放未做距离限制，导致可以缩放到星球内部，破坏了场景完整性。"

**产物技术质量**：
> "飞行器与云层发生严重穿模，视觉上明显不专业。"

**美学与体验**：
> "未开启AO导致物体缝隙处缺乏深度感，整体显得扁平。"

### 不好的备注示例（应避免）

1. "感觉xxx维度好" - 过于主观，没有具体证据
2. "xxx功能看起来专业" - 没有具体说明哪里专业
3. "页面文字内容多" - 没有说明质量如何
4. "差不多，随便选" - 缺乏专业判断
5. 只复制规则文档或query - 没有自己的分析

## 特殊情况处理

### 专业背景不足
如果只是某个细节不确定，应尽量依据大众普遍价值观进行判断。如果缺少必要专业背景导致核心质量无法判断需跳过，则写明跳过原因，并联系项目负责人。

### 需求不明确
如果用户需求描述模糊或存在歧义，尝试从上下文推断用户意图，如果无法推断，在备注中说明需求不明确的具体点，基于最常见的理解进行评估。

### 产物无法加载
如果HTML产物无法正常加载或渲染，检查网络连接和浏览器兼容性，尝试刷新页面或更换浏览器，如果仍然无法加载，在备注中详细说明加载失败的现象，终止后续评估流程。

### 功能部分可用
如果产物的部分功能正常，部分功能异常，分别记录正常和异常的功能，对正常功能进行完整评估，对异常功能记录具体现象和错误信息，在备注中说明功能完整度。

## 提交前检查

在提交标注结果前，请检查：

- [ ] 已独立完成任务，没有查看、比较或采用其他标注员的结论
- [ ] 若需求不成立，已只完成有依据的需求质量判断
- [ ] 若需求成立，已检查所有评估维度及全部可访问的输入、输出文件
- [ ] 每个维度的备注都有具体的问题描述、证据定位和影响评估
- [ ] 已逐项检查用户需求中的所有明确要求
- [ ] 已确定任务主要质量维度，并按提示词匹配度、功能与交互、产物技术质量、美学与体验完成覆盖自查
- [ ] 每个备注都包含具体的证据和定位，没有使用笼统的"质量好""体验佳"等模糊表述
- [ ] 已完整检查3D产物的动态加载内容
- [ ] 每个评估维度都有独立的判断和备注，没有相互矛盾
- [ ] 已按流程完成需求分析、产物体验、维度评估、问题定位和备注填写
- [ ] 已保存完整、可追溯的标注作业，并交由用户统一确认

## 常见问题

### Q1: 如何处理需求不明确的情况？
A1: 尝试从上下文推断用户意图，如果无法推断，在备注中说明需求不明确的具体点，基于最常见的理解进行评估。

### Q2: 如何评估3D场景的性能？
A2: 观察页面流畅度，记录FPS变化，使用性能监控工具，注意卡顿现象。

### Q3: 如何检查交互功能？
A3: 测试所有交互方式（键盘、鼠标、触摸），检查响应速度和准确性，观察动画流畅度。

### Q4: 如何评估视觉效果？
A4: 检查光影效果、色彩搭配、整体布局，评估是否符合用户需求。

### Q5: 备注应该写多长？
A5: 每个维度的备注应写1-2句，包含问题描述、证据定位、影响评估。
