# 评测集外发规范 vs 内部题包 差异清单

> 来源：飞书《评测集外发版本文档》(20260812) 之《外发版-评测题包交付规范 v4》(20260808) 与《Coding 交叉长尾领域数据生产规范》
> 对比对象：`block-storage-c-feature-20260813-1515`（nbd-server treefiles 功能题包）
> 日期：2026-08-14

## 结论速览

**现有题包不达外发验收标准**，核心差距在评分体系（程序化 pytest vs Judge 模型 Rubric）与题包结构（无 gating / golden_output / input_files / 标准元数据）。内部题包属"自产自评"管线（RL 训练数据生产），外发规范是"供应商采购验收"口径，两套体系不可直接互认；若需转外发格式，按下表逐项改造。

---

## 一、结构差异（五件套）

| 外发规范要求 | 内部题包现状 | 差异 | 级别 |
|---|---|---|---|
| `instruction.md` | ✅ 存在（415B） | 无场景/角色/交付物表格/硬约束分段，不满足"≥300 字、显式输出格式" | 🔴 |
| `task.toml`（schema 1.4） | ✅ 存在（schema 1.3） | 缺 artifacts、metadata.deliverables、rubric_index 等大量字段（见第三节） | 🔴 |
| `environment/Dockerfile` | ✅ 存在 | 基础镜像/依赖方式不同，无 agent 用户，WORKDIR=/workspace 非 /app | 🟡 |
| `environment/requirements.txt` | ❌ 无 | 依赖直接写在 Dockerfile，无独立 requirements.txt（规范：无依赖也交空文件） | 🟡 |
| `environment/input_files/` | ❌ 无 | 源码整体 COPY 进 workspace，无只读 input_files/ 输入区 | 🔴 |
| `solution/solve.sh` | ✅ 存在 | 内部是 `patch -p1 < oracle.patch` + make；规范是复制 golden_output 到 /app/output | 🟡 |
| `solution/golden_output/` | ❌ 无 | 用 oracle.patch 代替参考答案文件，无专家标准交付物 | 🔴 |
| `tests/test.sh` | ✅ 存在 | 内部自研模板（pytest 程序化），非规范"逐字复制不得改动"的固定模板 | 🔴 |
| `tests/finalize.py` | ❌ 无 | 无平台固定 finalize.py（有 finalize-manifest.py，用途不同） | 🔴 |
| `tests/graded/judge.toml` | ❌ 无 | 无 Judge 模型计分 Rubric | 🔴 |
| `tests/gating/gating.toml` | ❌ 无 | 无一票否决红线 | 🔴 |
| `tests/golden_output/`（评分侧副本） | ❌ 无 | 无 | 🔴 |
| `tests/assets/` | ❌ 无 | 无 | 🟡 |

## 二、评分机制差异（最核心）

| 维度 | 外发规范 v4 | 内部题包 |
|---|---|---|
| 评分方式 | Judge 模型（gpt-5.5）+ binary criterion，weighted_mean 池化 | pytest 程序化断言（3 场景确定性判定），reward = 程序化分 |
| 判官输入 | `/app/output/...` 候选产物 + `/tests/golden_output/...` 参考答案对比 | 无产物文件对比，直接跑测试 |
| 质量分 | quality_score 仅作证据，主分=程序化分 | rewardkit(qwen3-max) 质量证据，不进主分 |
| Rubric 条数 | L2≥8 / L3≥12 / L4≥18 / L5≥25 | 3 条（behavior_contract + implementation_quality + fix_locality） |
| 权重档位 | 仅 3.0 / 7.0 / 10.0 | 3.0 / 1.0（likert），不合规 |
| 维度体系 | 指令遵循/交付物内容质量/安全合规（三必需）+ 领域锚点≥30% | 无维度登记，无领域锚点概念 |
| gating | negate=true 红线条目，命中归零 | 无 gating 段 |

## 三、task.toml 元数据差异

| 外发必填字段 | 内部现状 |
|---|---|
| schema_version="1.4" | 1.3 |
| artifacts（/app/output/ 清单） | ❌ |
| [task].name = org/domain/... | 命名规则不同（codingrl/...） |
| [task].keywords = [领域, "office", 等级] | ["storage","block-storage",...] |
| [metadata].task_id | assignment_id（格式不同） |
| category_l1 / category_l2 / scene_l3 | ❌（仅 domain/subdomain） |
| capabilities / office_task_type / tools | ❌ |
| difficulty = L2~L5 | difficulty = "hard"（harbor 难度体系，非长程分级） |
| vl_dependency | ❌ |
| source_note（真实场景来源） | ❌（题目为开源项目功能复现，非真实付费场景） |
| expert_minutes（专家耗时） | ❌ |
| [[metadata.deliverables]] | ❌ |
| [[metadata.rubric_index]] | ❌ |

## 四、验收标准差异

| 外发规范 | 内部题包 |
|---|---|
| 双向预检：Oracle ≥0.7 / 空产物 ≤0.10 / verifier_error=0 | 有 oracle/nop 校准（reward=0 确认），口径不同 |
| SOTA 通过率上限（三家均分 L2≤65% / L3-L4≤55% / L5≤50%） | 用 16 trial 成功率验证（hard 目标 15-25%，reward1<4/16），未按模型三家均分 |
| 交叉复核一致性 ≥85% | ❌ 无 |
| 真实付费场景 + source_note 标注 | ❌ 开源仓库功能复现 |
| 三级分类平均分布 | ❌ 无分类概念 |
| Rubric 条数/关键项/负向≥20%/锚点≥30% | 不满足 |
| 批次准入门禁（准入100%、Golden 自检≥70%） | 无批次概念 |

## 五、打包与命名差异

| 外发规范 | 内部 zip（block-storage-c-feature-20260813-1515-...zip） |
|---|---|
| 目录层级「批次→题目→五件套」 | ❌ 直接打包任务运行目录 |
| 命名「供应商+领域+一级分类+时间」 | ❌ 内部 assignment_id |
| **无残留**：jobs/、logs/、reward.json、.git 等不得打包 | 🔴 **zip 内含 jobs/（job.log、result.json、baseline、selected-trials 等大量残留）** |
| 文件名 UTF-8、≤200 字节、禁符号链接 | 未核验 |

## 六、达标判定

| 检查项 | 达标？ |
|---|---|
| 五件套齐全（含 requirements.txt/input_files/golden_output） | ❌ |
| test.sh / finalize.py 为平台固定模板 | ❌ |
| judge.toml + gating.toml 齐备且 id 与 rubric_index 一致 | ❌（均无） |
| Rubric 条数下限 / Critical≥2 / 锚点≥30% / 负向≥20% / 三必需维度 | ❌ |
| weight 仅 3.0/7.0/10.0、仅 binary | ❌ |
| 双向预检 Oracle≥0.7 且 gating=1.0、空产物≤0.10、verifier_error=0 | 🟡 内部有等价校验但口径不同 |
| task_id 三处一致、org 段匹配 | 🟡 内部一致性 OK，但无 org 段 |
| 无真实密钥 / 无残留 / 命名规范 | ❌（zip 含 jobs/ 残留） |
| instruction ≥300 字、真实场景、三级分布 | ❌ |

**结论：不达标。** 若需交付外发，需按一~五节改造；若仅为内部 RL 训练数据生产，当前体系自洽，无需对齐。
