### ★ Windows 容器在本机的两个硬坑（重要，可复用）

1. **Docker Desktop 的 Windows 引擎被 install 级配置禁用**（见上）。解掉后才会出现 `windows` 引擎。
2. **`docker run` 报 `hcs::CreateComputeSystem ... The request is not supported`**：
   根因不是缺功能，而是 `RebootPending=True` —— `Containers`/`Microsoft-Hyper-V` 用 `-NoRestart` 启用后
   **必须重启一次**才会初始化容器栈。此时 `HypervisorPresent=True` 是 **VBS（内核隔离，VBS status=2）**
   在跑 hypervisor，与 Hyper-V 容器栈无关；`bcdedit hypervisorlaunchtype` 仍是 `Off`。
   解法：`bcdedit /set hypervisorlaunchtype auto` + 重启。

### ★ 镜像下载加速（mcr 直连仅 150 KB/s）

- MCR 直连 ~150 KB/s；`dockerd` 自身拉取只有 ~230 KB/s（2 层 2GB 要 2.5h）。
- **可用镜像源**：`https://mcr.m.daocloud.io`（token 走 `https://m.daocloud.io/auth/token?service=mcr.m.daocloud.io&scope=repository:windows/servercore:pull`）。
  16 并发分块可达 **8 MB/s**，2GB 约 3 分钟。
- **关键坑**：镜像 302 跳到后端存储后，**带 `Authorization` 头会被 S3 拒绝（403）** → 必须用 `curl -L`
  （curl 跨主机重定向会丢弃 Authorization），`urllib` 会转发导致 403。
- **`docker load` 只吃 docker-save 格式**：经典 windowsfilter 镜像库对 OCI layout 报
  `invalid archive: does not contain a manifest.json`。需自己拼 `manifest.json` + `<config-hex>.json` +
  `<layer-hex>/layer.tar`（可硬链接，gzip 层可直接用）+ `repositories`，再 tar 后 `docker load`。
- 脚本：`deliverables/2026-10-04_outside-harbor-win/_build217/fetch_servercore.py`（并行分块下载+校验）、
  `make_docker_save.py`（OCI→docker-save）。
