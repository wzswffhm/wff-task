## 凭据弹窗（CredentialHelperSelector）问题

**根因**：存在**两个 credential helper 同时生效**——
1. PortableGit 系统级 gitconfig：`helper-selector`（弹窗来源）
2. `~/.gitconfig`：指向 PortableGit 的 `git-credential-manager.exe`

Git 会依次调用所有 helper，`helper-selector` 是交互式选择器，故反复弹窗；且 `cmdkey /list` 中无任何 git 条目，说明凭据从未持久化。

**解决**：改用 SSH（复用已有 `~/.ssh/id_ed25519`，已绑定 wzswffhm，`ssh -T git@github.com` 通过），彻底绕开凭据管理器。push 全程无弹窗，验证有效。

**遗留**：上述两个 helper 配置**未删除**（改动全局配置影响面大，经用户授权后仍选择保留，因 SSH 已规避）。若后续使用 HTTPS 远程（如 git.woa.com、gitee.com），弹窗可能复现，届时清理 `credential.helper=helper-selector` 即可。

### 任务 3：4 模型自动化验证（`scripts/run_model_validation.py`）

**用户提供的端点**：

|---|---|---|
| aliyun MaaS | `https://llm-cz4pcezs463b102x.cn-beijing.maas.aliyuncs.com/apps/anthropic` | `qwen3.8-max`、`GLM-5.3`、`Kimi K3`（共用一个 Key） |

**实测结论**：
- 协议为 **Anthropic Messages**：`POST {base_url}/v1/messages`，header `x-api-key` + `anthropic-version: 2023-06-01`。
- **aliyun base_url 必须带 `/apps/anthropic` 后缀**——去掉后 `/v1/messages` 返回 404；加上则路由正确。
- **两个 Key 均被服务端拒绝**：
  - aliyun → `{"code":"InvalidApiKey","message":"API-key is blocked."}`
  - blvr → `{"error":{"message":"Invalid token"}}`
  - Key 格式看起来正常（aliyun 是 `sk-ws-` 前缀的浏览器会话式 token），端点路径也正确，故**问题在 Key 本身**（未激活/IP 白名单/过期/额度）。
  - 用户决定：**先按现状交付脚本**，Key 就绪后可直接跑通。

**脚本设计（5 个要点）**：

1. **凭据预检**：跑题前先对每个模型发一次 `Reply with exactly: OK`，提前暴露 Key/网络问题，避免跑一半才失败。
2. **VALID / INVALID 自动分类**（8 类模式）：`credential_rejected` / `auth_failed` / `rate_limited` / `quota_exhausted` / `network_timeout` / `network_error` / `model_unavailable` / `upstream_5xx` → INVALID；
   `model_overloaded` / `context_overflow` → VALID（按真实结果记录）。
   凭据类与 model-not-found 类**不重试**（重试无意义），其余指数退避重试。
3. **准入状态机**（把"待定"与"不通过"分开）：
   - 有效运行 < 3 → 待定
   - 存在 INVALID 未补跑 → 待定
   - 3 次有效但分数未回填 → 待定
   - 否则按条件 1 / 条件 2 判定 True/False
   - `--score-only` 退出码：`0` 无明确失败（含待定）／`1` 存在明确不通过
4. **职责边界（关键设计）**：脚本是**模型调用层**，不是评测沙箱。
   只负责调用/存轨迹/区分 VALID-INVALID/算区分度；
   `per_testcase.json` 初值 `NOT_RUN`、`report.json.score` 初值 `null`，
   **正式分必须由平台 harness（`test.ps1` + `grade.py`）回填**。
   这条分工是为守住"不得用 Linux Mock 替代真实 Windows Runtime 验证"的红线。
5. **凭据不入库**：支持 `HARBOR_WINDOWS_ENDPOINTS_JSON` / `--config`；
   `model_endpoints.local.json` 与 `*.local.json` 已加入 `.gitignore`。

- 冒烟跑通：4 模型全部正确识别为 INVALID（凭据被拒），生成 `error.json` + `badcase_attribution.md`，未误重试。
