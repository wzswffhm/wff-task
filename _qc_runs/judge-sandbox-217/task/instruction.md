# WReparse：NTFS 重解析点的安全遍历与确定性审计

## 背景

磁盘治理流水线要对来源不明的目录树做**只读盘点**：在不越界的前提下把整棵树枚举清楚，
并把所有 NTFS 重解析点（junction、符号链接、挂载点）单独登记出来，交给下游做保留或清理决策。

上线之后出现两类事故，根因都在遍历与登记环节：

1. 遍历器会悄悄跟随重解析点，越出扫描根目录读到无关数据；
2. 同一棵树在不同机器上产出不同的报告，导致下游比对全部失效。

`environment/workspace/WReparse` 是当前实现。行为依据有两个来源，分工明确：

- `environment/workspace/docs/REPARSE-CONTRACT.md` 给出该模块的**行为样例与边界定义**；
  同目录下的 `REPARSE-CONTRACT.draft.md` 是一份更早的草稿，来源与校准状态未知，
  使用前需自行核对；语义层面以正式契约为准；
- `environment/workspace/assets/observed-provider-facts.json` 是在真机
  （Windows 11 + NTFS + Windows PowerShell 5.1）上实测采集的 **provider 层权威事实**
  （属性与 `LinkType` 的真实取值、`.Target` 的实际类型、三种区域设置下的排序实测等）。
  **两者在实现细节上冲突时，以实测事实为准。**

当前实现与以上两个来源之间存在多处偏差，需要全部修掉。本文件**不重复**两个来源里的细则；
凡未写明的行为，一律以「正式契约的样例 + 实测事实」经你自行归纳后的结果为准。

## 目标

在不改变模块公共 API 名称、参数名与报告数据模型的前提下，让 `WReparse` 模块的输出
与两个行为依据完全一致。要修改的文件位于 `environment/workspace/WReparse/`。

## 必须满足的行为

1. **公共 API**：模块导出且仅导出契约 §2 列出的六个函数，函数名与参数名逐字一致。
   `Get-WReparseReport` 接受 `-Root`（必填）、`-MaxDepth`（默认 32）、`-Follow`（开关，默认关）。
2. **行为对齐**：扫描、条目分类、路径判定、链接解析、错误上报与序列化的**具体规则**
   由你从正式契约的样例与 `assets` 实测事实中归纳；凡与历史草稿冲突之处，以正式契约为准。
3. **确定性**：同一棵树、同一参数连续两次序列化必须**逐字节相同**，且该结论须在
   不同 Windows 区域设置（如 `en-US`、`de-DE`、`ja-JP`）下同样成立；
   报告中不得出现时间戳、进程号、随机值等易变字段。
4. **只读与边界**：默认不得越出扫描根；仅在显式 `-Follow` 时才按归纳出的规则解析目标，
   并正确区分祖先环、悬空目标与兄弟分支共指。
5. **证据**：本文件不列实施细则。实现须能用你自己的测试逐条证明其正确。

## 边界和约束

- 平台：Windows + Windows PowerShell 5.1 + NTFS。不得依赖管理员权限。
- 网络：不需要网络，也不应发起网络请求。
- 只读：扫描过程不得创建、修改或删除被扫描的条目。
- 允许修改 `environment/workspace/WReparse/**`；允许新建
  `environment/workspace/selftest.ps1`（见下方验收 18）。
- **不得修改** `tests/**`、`environment/**` 下的驱动脚本，以及
  `environment/workspace/docs/**`、`environment/workspace/assets/**`。
- 不引入外部依赖：保持纯 PowerShell + .NET BCL。
- 模块必须在 Windows PowerShell 5.1 下可正常导入并运行（不得要求 PowerShell 7）。

## 运行入口

评测在独立的评测环境中进行：评测方先准备一棵固定的 NTFS 目录树（含普通文件、目录、
junction、符号链接、硬链接，以及循环、悬空目标和名字前缀相似的兄弟目录等边界情形），
再对模块公共 API 运行一组契约一致性检查，结果写入 `results/result.json`。

`environment/workspace/tests/test_wreparse_basic.ps1` 是**可见冒烟测试**：它只确认
模块能导入、报告对象能产出、能序列化，**不检查字段结构与任何语义**。
通过它**不代表**实现了契约——当前这份有偏差的实现同样能通过它。

所属评测夹具与检查脚本属于**评测资产，不提供给候选**。请自行核对下列边界情形是否
都能正确处理（**期望结果需你依据两个行为依据自行推导**）：普通文件与目录、junction 与
符号链接、硬链接、相对目标链接、指向扫描根之外的链接、循环链接与悬空目标、仅前缀相同
的兄弟目录、**目标为文件的链接**、**指向同一目标的兄弟链接**、**空目录**、拒绝访问的
子目录、深于默认深度限制的子树、名字含非 ASCII 字符的条目，以及同一棵树重复序列化的
一致性。

## 用户可见验收

下列情形**必须全部自证通过**。每条只给出「要覆盖的情形」，**不给出期望值**——
期望值由你依据正式契约与实测事实自行推导，并由验收 18 的自测脚本落地：

1. 扫描一棵含重解析点的树：每个重解析点都被登记，且未给 `-Follow` 时都没有被进入。
2. 与扫描根只共享名字前缀的兄弟目录上的链接、以及指向扫描根内部的链接，
   两者的 `InScope` 判定应有区别。
3. 同一条相对符号链接的解析结果，与进程当前工作目录无关。
4. 连续两次调用 `Get-WReparseReport` 并序列化，两次 JSON 字符串完全相同。
5. 硬链接、junction、符号链接三者的条目分类各自正确，且 junction 与符号链接
   必须可区分。
6. 扫描根不存在、扫描根是文件、扫描根字符串无法规范化，三种情形上报的错误各不相同。
7. `-MaxDepth` 传负数与传 0 的行为**完全一致**。
8. `-Follow` 下经链接进入的条目，其 `RelativePath` 以**链接路径**为前缀命名，
   而不是以真实目标路径命名。
9. `-Follow` 下目标为**文件**的链接只登记链接条目自身，不产生任何子项。
10. 同一个目标被**兄弟分支**上的两个链接分别指向时**不构成环**：
    两个分支都应被正常进入，且 `Errors` 中不得出现针对它们的 `cycle`。
11. 扫描一棵**空目录**树时，序列化结果中 `Records` 与 `Errors` 均为 `[]`。
12. 导入模块后，可见函数恰好是契约 §2 的六个；内部辅助函数不可见。
13. 报告对象的字段集合恰好是契约 §3 声明的集合，不得多出任何字段
    （包括生成时间戳之类的元数据）。
14. 在名字含非 ASCII 字符（如 `Ä`、`ö`）的目录上，`Records` 的排序结果
    在不同 Windows 区域设置（`en-US` / `de-DE` / `ja-JP`）下**保持一致**，
    且与 `assets` 实测事实所要求的次序相符。
15. 未给 `-Follow` 时，报告的 `Errors` 中不出现 `cycle` 与 `broken_target`，
    即使扫描树里存在环和悬空目标。
16. 普通文件与目录的 `InScope` 恒为 `false`；`InScope` 只对重解析点条目有意义。
17. 任何重解析点条目的 `Target` 都是字符串类型，不因目标个数而变化。
18. **可复现自证**：新建 `environment/workspace/selftest.ps1`，用一行命令
    `powershell -NoProfile -ExecutionPolicy Bypass -File environment\workspace\selftest.ps1`
    即可在**候选侧**独立完成全部上述情形的验证：脚本须自建一棵覆盖
    junction、相对符号链接、硬链接、非 ASCII 名、拒绝访问子目录、循环、悬空目标、
    兄弟共指、目标为文件的链接、空目录、深于默认深度的子树的 NTFS 夹具，
    对公共 API 逐项断言，最后打印逐条 `[PASS]/[FAIL]` 清单与汇总行；
    全部通过时退出码为 0。脚本必须只读、无网络、不依赖管理员权限与外部模块。
